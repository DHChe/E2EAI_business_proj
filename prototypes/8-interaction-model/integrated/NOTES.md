# #8 상호작용 모델 — 통합 프로토타입

PROTOTYPE — 버리는 코드 (#8, 통합안)

[프로토타입 열기](index.html). 파일을 더블클릭해 연다. 기본은 `?gate=on&diff=all`, 비교 조건은 `?gate=off&diff=changed`다. 화면의 스위치로도 바꿀 수 있다. 상태와 감사 로그는 메모리에만 남고 새로 열면 초기화된다. 외부 리소스·네트워크·실제 송부·지급은 없다.

**사람의 결정 (2026-09-22): `gate=on`, `diff=all`.** 재량 판단을 기록하기 전에는 승인·동의가 열리지 않고, 두 문서 대조는 같음·바뀜·알 수 없음 행을 모두 보인다. `gate=off`·`diff=changed`는 비교용으로만 남긴다.

기준은 규정 3종 판 1과 합성 시각 **2026-11-18 18:00 KST**다. 사람의 선택은 기한순 대조표를 바탕으로 한 **통합안**으로 반영했다. 별도 안 B·C, 자동 다음 문서 이동, 반려 흐름은 만들지 않았다. 시간 절감은 채택 근거로 쓰지 않는다.

왼쪽의 주 배열은 진행 중인 기한의 최솟값 순이며 동률은 문서 번호 순이다. 다가오는 건, 승인 카드 도달 전, 처리함은 상태를 구분하는 같은 화면의 구획이다. 상단 설정과 화면 하단 고정 줄은 `gate`, `diff`, 기준 시각을 항상 보여 준다. 승인 후에도 선택한 문서를 유지한다.

주의 신호는 법적 하자·판정 불가 두 칸으로 유지하고 정책 대조는 별도 구획에 둔다. S-105의 법적 하자는 재무합의자가 본다는 가정이며, 카드에 **가정 — 규정상 처리자 없음**을 표시했다.

## 2. 추가한 사례와 그 계산

영업일은 `PRC-3-3`에 따라 기준일을 빼고 전날 또는 다음 날부터 센다. 토·일과 입력된 휴일(2026-10-03, 10-05, 10-09, 12-25)을 제외한다. 계산 범위는 2026년 10~12월이다. 일비의 업무일은 회사 영업일과 별개인 출장 일정의 구분이다. 법정 공휴일 서비스를 연결한 것이 아니며 달력은 합성 입력이다.

### 새 사례 S-113 — 사전승인 미완료 출발의 정산

- 노태식: 생산관리팀, 직급 부장, 직책 없음. 해외 사업장 방문, 하노이, 11/02~11/06, 업무 5일·지급 대상 숙박 4박.
- 사전승인 P-113은 10/16 기안, **11/03 완료**. 출발은 **11/02**다. 기안 기한은 10/19(출발 전 10영업일, `PRC-5-1`), 통상 완료 기한은 10/26(전 5영업일, `PRC-6-1`). 기안은 지켰으나 사전승인 완료가 출발 뒤다.
- 다 등급 부장 일비 80,000 × 5 = **400,000원**(`TRV-5-2`), 숙박비 600,000원 ≤ 160,000 × 4 = **640,000원**(`TRV-6-2`), 교통비 890,000원, 등록비 0원. 총액과 한도 적용 금액은 모두 **1,890,000원**, 초과분은 0원이다.
- `APV-5-2`의 해외 사업장 방문 행은 두 금액 모두 본부장(2단계)이다. `PRC-4-1`과 `APV-7-1` 제2호가 **사전승인 미완료 출발**을 상향 사유로 준다. 한도 적용 금액 단계 2 + 1 = 3, 총액 단계 2와 비교하면 대표이사(3)다(`APV-7-4`). 사전승인 전결권자 하한 2도 충족한다(`APV-7.2-1`).
- 청구액이 5,000,000원 이하이므로 재무합의자는 남윤호 한 명이다(`APV-9-2`). 기안자의 직책이 없으므로 **남윤호 → 배동환(생산관리팀장) → 생산본부장 → 대표이사**다(`APV-8-1`).
- 복귀 11/06 + 10영업일 = 정산 기안 기한 **11/20**(`PRC-10-1`), 실제 기안 11/10으로 준수했다. 남윤호에게 11/17 도달 + 3영업일 = **11/20** 처리 기한(`PRC-14-1`). 뒤쪽 역할에서는 다가오는 건으로 읽힌다.
- 실비 증빙 600,000 + 890,000 = 1,490,000원, 증빙 없이 지급하는 일비 400,000원을 더하면 청구 1,890,000원이다(`TRV-4-2`).

### 새 사례 P-114 — 기안 기한 뒤의 국내 사전승인

- 강우진: 해외영업팀, 직급 과장, 직책 없음. 부산 11/19~11/20, 업무 2일·지급 대상 숙박 1박. **11/18 기안·도달**.
- 출발 11/19의 2영업일 전은 **11/17**(`PRC-5-1`). 기안 기한을 지나 기안했으므로 경과 이력을 표시하고 `PRC-6-2`의 **출발일 11/19**를 문서의 기한으로 사용한다. 통상 완료 기한 11/18(`PRC-6-1`)은 이력 행으로 남긴다.
- 현재 결재자의 처리 기한은 11/18 다음 날부터 3영업일: 11/19, 11/20, 11/23 → **11/23**. 출발일이 더 이르므로 문서의 기한은 11/19이고, 남은 1명만 있어도 시계 부족이 보인다.
- 국내 과장 일비 40,000 × 2 = **80,000원**, 숙박비 55,000원 ≤ 90,000 × 1 = 90,000원, 교통비 180,000원. 합계·한도 적용 금액 모두 **315,000원**(`TRV-5-2`, `TRV-6-2`). 국내 1,000,000원 이하·상향 없음이므로 **해외영업팀장** 전결이다(`APV-5-2`, `APV-7-4`, `APV-8-1`).
- `PRC-6-2`의 출발일은 `kind: deadline` 블록에 없다. 카드에서 이를 숨기지 않으며, 날짜를 18:00까지로 표시한 것은 시연 가정이다. 실제 출발 시각과의 관계는 원문 보완 사항이다.

### 기존 사례의 보완과 시계 부족 계산

- **P-103:** 금액·일정·결재선은 원본 그대로다. 배동환에게 11/17 도달 → 3영업일을 쓰면 11/20 → 같은 날 생산본부장에게 도달하여 3영업일을 쓰면 **11/25**. 11/30 출발의 5영업일 전인 사전승인 완료 기한 **11/23**을 넘는다. 현재 결재자 배동환과 다가오는 결재자 생산본부장 모두 이 계산을 본다. 각자가 허용된 기간을 전부 사용하는 경우의 산술이며, 반드시 늦어진다는 예측은 아니다.
- **S-106 / TRV-7-1:** 원본 2,800,000원과 결재선을 유지하고, 사전승인 뒤 과장 강우진과 같은 숙소에 머문 자료를 추가했다. 대리 가 등급 상한 200,000 × 3 = 600,000원, 동행 과장 상한 230,000 × 3 = 690,000원이다. 실제 숙박비 600,000원은 본인 상한에도 들어간다. 판단 전 계산은 본인 상한을 쓰며, 선행개발팀장이 같은 숙소 필요를 기록한 뒤에만 상위 상한을 적용한다. 어느 쪽도 총액·한도 적용 금액·결재선을 바꾸지 않는다. 남윤호의 재무합의 큐에서는 이 재량을 다시 판단하지 않는다.
- **P-111 / TRV-13-4:** 원본 총액 3,000,000원과 팀장 전결을 유지하면서 일정을 12/07~12/15의 9일로 보완했다. 업무일은 12/07~09와 12/15 복귀의 4일, 비업무일은 12/10~14의 5일이다. 지급 숙박은 업무일 체크인 3박이고 개인 일정의 5박은 청구하지 않는다. 일비 90,000 × 4 = 360,000원, 숙박비 230,000 × 3 = 690,000원, 왕복교통비 1,550,000원, 등록비 400,000원으로 합계 3,000,000원이다. 4/9라는 비율로 직접 동기를 자동 결정하지 않는다. 해외영업팀장이 자료를 보고 업무 동기로 인정하는 경로만 작동하며, 왕복교통비 안분으로 금액이 바뀌는 경로는 #17 대기로 막았다.
- **모름 사례:** S-106의 숙소명은 정산 자료에만 있고, S-108의 숙소명은 양쪽 모두 없다. 두 경우 모두 `? 알 수 없음`이다. 원본에 없던 사실을 같음으로 채우지 않았다.
- **검산용 자료:** 정산 7건에 총 17개의 실비 증빙 금액 스냅샷을 명시했다. 원본의 대표 증빙 도식을 전체 증빙인 것처럼 세지 않는다. 사전승인 5건에는 예상 항목 합계를 쓴다. E-109·E-110은 청구가 아직 확정되지 않았으므로 합계 검사에서 통과한 정산인 것처럼 세지 않고, **청구 미확정 2건**을 표시한다.

## 3. 짝 보류 판정 결과

**codex의 승인 카드 도달 전 배치를 유지한다. E-110은 남윤호에게 열린 짝 확인이지만 상신된 문서의 승인 카드로 만들지 않았다.**

근거는 다음 경계를 함께 읽은 결과다.

1. `docs/company/travel-procedure.md:192`의 `PRC-11-2`는 확정된 값 위에서만 정산을 기안하게 한다. 이 문장 하나만으로 값 모순의 짝 확인 시점까지 단정하지는 않는다.
2. `CONTEXT.md:303`은 추출 불확실이 정책 대조 전에 닫히게 한다. `CONTEXT.md:310`은 후보 복수·짝 보류를 **중간 상태**로 두고, 값 모순이면 재무합의자, 그 밖에는 기안자가 확인하며 최종 대사 결과로 닫는다고 정한다. 처리자가 재무합의자라는 것과 재무합의 승인 카드라는 것은 같지 않다.
3. `docs/design/receipt-pipeline.md:835-839`의 `ReconciliationOutcome`에는 **대사 완료 / 대사 불일치 / 짝 없음**만 있다. `:875`의 `ConfirmedEvidence.reconciliation`, `:882-892`의 `PolicyFacts.reconciliation` 모두 이 최종 결과 타입을 받는다. 열린 짝 보류를 정책 대조 입력으로 전달하는 자리는 없다.
4. 같은 문서 `:2137-2152`는 짝 보류 라우팅, 추출 문제 → 경쟁·대조 불가 → 값 모순의 처리 순서, 닫힌 뒤의 대사 결과를 명시한다. 통화가 다르면 두 원금액을 남기고 차액을 계산하지 않는다.
5. `docs/adr/0008-extraction-uncertainty-is-first-class.md:31-33`은 정책 대조·법정 판정이 확정 타입만 받게 한다. `docs/adr/0010-human-routing-bounded-by-structure-measured-by-ratio.md:36-37`은 대기 건을 승인 카드나 자동 정산으로 우회시키지 못하게 한다.
6. `docs/design/receipt-pipeline.md:320-329`의 승인 큐와 `:2247-2262`의 변환 경계에서 카드로 전파하는 주의 신호는 법적 하자와 판정 불가다. 짝 보류를 세 번째 승인 카드 신호로 더하지 않는다.

E-110의 **23,000 JPY / 카드 원거래 150 USD**는 그대로 남긴다. 같은 거래로 확인하면 대사 불일치로 기록하되 차액은 만들지 않고, 재검산·대사·정산 기안 대기라는 경계를 유지한다. 정책 대조나 승인 액션을 여는 버튼이 아니다.

**남은 범위:** 원문은 “상신한 뒤 새로 발견된 짝 보류가 승인 카드와 별개 업무로 존재할 수 있는가”라는 사후 재개 시점을 직접 정의하지 않는다. 열린 짝 보류를 승인 카드에 싣는 claude 배치는 채택하지 않았고, 이 사후 재개 문제는 #17/#10의 열린 질문으로 남긴다. 현재 경계 판단을 모든 문서의 제출 시점에 대한 보편 규칙으로 넓히지 않는다.

| `gate=on` (기본) | 내 몫 재량 이유를 기록하기 전 승인/동의 버튼 비활성. 판단 기록과 문서 승인을 나누어 남김 | 내 몫 질문과 원문을 실제로 읽는가, 기록 버튼이 형식적 통과 의식이 되는가, 책임자를 정확히 구분하는가 |
| `gate=off` | 승인/동의 버튼은 처음부터 활성. 누를 때 입력한 재량 이유를 함께 기록하는 codex 동작. 이유가 비면 진행하지 않음 | 별도 관문 없이도 재량 판단이 빠지지 않는가, 버튼 활성 상태가 이미 판단을 마쳤다는 인상을 주는가 |
| `diff=all` (기본) | 같음·바뀜·모름 행을 모두 나란히 표시 | 전체 맥락이 바뀐 항목·모름을 찾는 데 도움 되는가, 긴 표 때문에 필요한 근거가 가려지는가 |
| `diff=changed` | `=` 행만 접고 펼침 수를 남김. `≠`와 `?`는 표시 | 같음 행이 접혀도 비교 맥락을 이해하는가, 자료 없음과 변경 없음을 구분하는가 |

토글을 바꿔도 이미 기록한 판단과 선택 문서는 유지한다. 첫 상태끼리 비교하려면 새로 연다. 두 조건 모두 승인 후 자동 이동과 일괄 승인이 없다. 두 조건 모두 반려와 지급액을 바꾸는 부정적 재량 선택은 비활성 `#17 대기`다.

권고의 판정 기준은 판단 누락·오판, 책임자 식별, 차이·모름 발견, 대기 발견, 조항→계산→결재선의 추적이다. 시간 절감이나 합성 사례에서의 클릭 수 감소를 채택 근거로 삼지 않는다.

## 6. #11에 넘길 지표
