# #11 Eval·검증 계획 — codex 레인 독립 제안

이 문서는 선택 전 제안이다. 값의 성질은 `하드 규칙`, `법령의 귀결`, `[설계 가정]`, `[초기 검증 가정]`으로 구분한다(`docs/PRD.md:145-147`). 아래 시험 설명은 구현 지시의 초안이며 제품 코드·시험 코드는 아니다. 공통 결정 D1~D15는 `docs/research/eval-plan-lane-brief.md:24-46`을 따른다.

## §0 요약

1. 함정 집합은 위반 0을, 분포 집합은 `[합성 분포 위 관측]` 비율과 초기 가정의 반증을 본다(D2·D3, `docs/research/eval-plan-lane-brief.md:31-32`).
2. 독립 정답은 구현 phase 첫 step에서 규정만 읽고 작성하며, 제품은 그 파일을 읽지 않는다(D6·D7, `docs/ARCHITECTURE.md:151`).
3. 코드 변경은 전건 재생, 모델·프롬프트·전처리 변경은 사용자가 승인한 실측으로 확인한다(D8·D9, ADR-0016).
4. 실물·JaWildText는 판독만 재고 출처별로 공개한다(D4, `docs/research/receipt-datasets.md:74-83`).
5. 다른 레인과 가장 갈릴 자리는 분포 집합의 크기와 법정 플래그가 적을 때의 N=3 `[설계 가정]`이다(§5·§11, `docs/PRD.md:120`).

## §1 평가의 층과 집합

한 출장의 영수증에 끝4가 없으면 판독 결과가 맞더라도 짝은 사람 확인을 기다린다. 그 뒤 한도·기한·결재선을 코드가 계산하고, 승인자는 규정 근거가 붙은 카드를 본다. 이 세 일을 한 정확도 수치로 합치지 않는다(`docs/design/receipt-pipeline.md:2502-2505`, `docs/PRD.md:152-165`).

## §3 반증 조건 대응표

수집 명령: `grep -n '반증' docs/adr/*.md`. ADR-0011~0031에서 번호 붙은 조건 82개, ADR-0016의 번호 없는 단문 조건 1개, 합계 **83개**를 아래에서 각각 한 행으로 다룬다. ADR-0010에는 번호 붙은 반증 절이 없고 H1~H11·R1~R4는 §2 S12·§4에서 측정한다(`docs/adr/0010-human-routing-bounded-by-structure-measured-by-ratio.md:59-67`). PRD 논증 전체의 반증 2개는 마지막 두 행이다(`docs/PRD.md:119-121`).

지표 표기 `A/B`는 해당 고유 사건의 A건/B건이다. 기본 모집단은 고정 집합의 해당 조건을 실제로 가동한 사건이며, 같은 `(집합 판, 시나리오 ID, 문서/지출/작업 ID, 조건 ID)`의 재시도는 한 건으로 접는다. 반복 자체가 조건이면 원사건 ID당 반복 횟수를 별도로 센다. 사람 접촉은 감사 이벤트 ID로 세고, 같은 이벤트의 재생은 접는다. 비율은 분포에서만 `[합성 분포 위 관측]`이라 적는다. 함정은 관측 유무만 본다(D3, `docs/research/eval-plan-lane-brief.md:32`; `docs/design/receipt-pipeline.md:3026-3036`). `실사용 전 미측정`은 실제 승인자의 행태와 조직의 선호·운영 비용을 합성으로 입증할 수 없다는 뜻이다(D5).

## §4 문서 단위 지표와 사람 확인 지점 셈법

예를 들어 정산서 한 장을 두 승인자가 원래 결재선에서 읽으면 일반 승인·동의 문서는 **한 장**, 결재 행위는 **두 번**이다. 끝4가 없어 기안자에게 별도 짝 확인을 요청하면 추가 접촉은 **한 번**이다. 세 수를 더해 하나의 "사람 확인"으로 부르지 않는다(`#8`의 #11 코멘트, `docs/research/state-vocabulary-comparison.md:139-142`, `docs/design/receipt-pipeline.md:3030-3036`).

## §5 분포 집합

가상 회사 한 기간을 **2026-10-01부터 2027-09-30까지 1년, 출장 48건**으로 고정하자 `[설계 가정]`. 규정 3종 시행일은 2026-10-01이고, 전시회는 각 연 1회이므로 1년이 두 전시회를 모두 넣기 쉽다(`docs/adr/0017-public-demo-single-vm-replay-default-capped-live.md:93-94`, `docs/company.md:31-42`). 48건은 회사의 실제 출장량이 아니다(`docs/company.md:94-98`). 생성기는 시드·세계 시계·규정 판·원인 태그를 고정하고, 독립 정답은 이후 첫 step에서 만든다(D6, `docs/ARCHITECTURE.md:565-571`). 아래 모든 건수·비율은 `[설계 가정]`이며 `[합성 분포 위 관측]` 외의 운영률로 읽지 않는다.

## §8 S16 기준선

기준선은 제품 밖 평가기에 두고, **경비유형별·세그먼트별 사전 신청/정산 금액 대조와 거래 단위 한도 대조를 모두 수행**한다. 앞 두 비교는 Concur/Emburse 조사, 거래 한도는 Ramp 조사에 근거한다(`docs/research/request-vs-expense-comparison.md:27`, `:67-69`, `docs/research/ax-competitive-landscape.md:207`, `docs/PRD.md:166`). 벤더 제품을 그대로 구현했다는 주장은 하지 않는다.

| 같은 입력에 심을 차이 | 기준선이 비교하는 것 | 제품에서 추가로 볼 것·출처 |
| --- | --- | --- |
| 유형/세그먼트 금액 변화, 거래 한도 초과 | 반드시 검출해야 기준선이 허수아비가 아니다 | 제품도 검출; `docs/PRD.md:156`, `:166` |
| 총액·유형별 금액 같고 좌석 등급/숙박 박수/일정/행선지/동행/사적 일정 변화 | 문서 근거상 기준선의 속성 비교는 확인되지 않음 | 필드별 차이를 검출; `docs/research/request-vs-expense-comparison.md:68` |
| 차이 없는 재상신, 사전 인정 범위 안 정산 | 허위 금액 신호 0인지 확인 | 허위 차이·재상향 0; `docs/PRD.md:156` |

위 각 갈래의 **2건씩**을 함정 24건 안에 넣는다 `[설계 가정]`. 종류별 참차이 검출 수·놓친 수·허위 차이 수를 공개하고 S16 자체에는 임계값을 두지 않는다(`docs/PRD.md:166`). 점검표: 금액 비교를 총액 하나로 약화하지 않았는가, 세그먼트·거래 한도 기능을 빼지 않았는가, 같은 정답 라벨을 두 평가기에 줬는가, 기준선과 제품이 서로의 출력/정답을 읽지 않는가(`docs/ARCHITECTURE.md:151`).

## §10 사람 승인 실측 절차

| --- | --- | --- |
| 1. 고정 표본 봉인 | 자체 렌더 함정 24건 전부, 분포에서 유형·결제수단·서식에 걸친 12건, JaWildText 고정 30장, 사용자 실물 약 30장: 합계 약 96이미지/사건 `[설계 가정]`. 판독기와 답변기는 각각 해당 호출만 센다. 표본 ID·렌더 판·이미지 sha256을 먼저 고정 | D3·D4·D9, `docs/research/receipt-datasets.md:79-83`, `docs/ARCHITECTURE.md:167-178` |
| 2. 예상 비용 제시 | 후보 모델별 `Σ(입력 토큰×입력 단가 + 캐시 읽기 토큰×캐시 단가 + 출력 토큰×출력 단가 + 이미지 토큰×해당 단가)`에 재시도 예약분을 더한다. 배치 가능한 호출은 D9의 배치 API **50% 할인**을 별도 열로 보인다. ADR-0017의 장당 `$0.03~$0.044`는 **2026-09-22의 실측 전 추정**일 뿐이고 현 청구 단가로 단정하지 않는다. 호출 수·모델·상한·환율 가정을 적어 승인받는다 | D9, `docs/adr/0017-public-demo-single-vm-replay-default-capped-live.md:50-59` |
| 3. 승인 뒤 첫 실측 | 구현 말미 1회, 다섯 호출의 필요한 표본만 live로 실행하고 `model_call`을 기록한다. 하네스 자체는 API를 부르지 않는다 | D9, ADR-0016:24-34 |
| 4. 모델 선택 | 판독기·답변기별로 같은 고정 함정 표본에서 하드 위반 0·조용한 오류 0인 후보만 남겨 **측정된 비용이 가장 싼** 것을 선택한다. 모두 실패하면 미선택으로 보고 실패 유형을 고친다. LLM은 채점하지 않는다 | D2·D10, `docs/research/eval-plan-lane-brief.md:31`, `:39` |
| 5. 변경 뒤 | 코드만 바뀌면 매 커밋 전 시나리오 replay. 프롬프트·모델·전처리 변경은 사용자가 다시 명령할 때만 예상 비용과 함께 **바뀐 호출 지점**의 동일 표본을 실측; 다른 호출은 기존 기록 재생 | D8·D9, ADR-0016:24-35 |
| 6. 작은 사람 검수 | 실측마다 약 30분: 보류 답변 약 20개를 읽으며 질문에 답했는지, 수사가 숫자를 바꾸는지, 조항 전문과 적용 범위를 이해할 수 있는지, 복합 카드의 두 갈래를 찾을 수 있는지만 표기한다. 실제 승인·고무도장 행동은 `실사용 전 미측정` | D5, ADR-0020:88-94, ADR-0030:70-75 |

`false abstention`은 규칙이 풀어 준 `ambiguous_*`는 추가 호출 없이 세고, `unreadable`은 **사용자가 승인한 실측 표본에서만** 강제 응답 스키마의 반사실 재실행을 비용표에 추가한다. 강제 응답은 운영 경로에 넣지 않고 정답 라벨과 비교하며, 정당한 기권은 분모에서 뺀다(`docs/design/receipt-pipeline.md:3078-3099`, D9).

보고서와 데모의 정적 **평가 결과** 페이지에는 집합 판·측정일·모델/프롬프트/전처리 판·표본 수·정답 출처·비용·하드 위반·조용한 오류·기권·R1~R4·S16 종류별 차이·가정 반증·실패 사례·`미측정`을 싣는다. 자체 렌더/JaWildText/실물을 **각각 별도 열**로 내고 마지막 승인 실측이라는 시점을 표시한다. 실물 원본과 개인정보는 공개하지 않으며 화면 형태는 #12가 정한다(D4·D15, `docs/PRD.md:159`, `:162`, `docs/research/eval-plan-lane-brief.md:44`). 실측 승인이 없으면 해당 칸은 `미측정`이고 replay 수치를 live 품질로 부르지 않는다(ADR-0016:65).

## §11 증거 지표 재해석

측정 전에 보고서 규칙으로 다음 문장을 봉인한다: **“분포 집합 48개 출장에서 법정 플래그(`법적 하자`·`판정 불가`)가 붙은 고유 지출이 3건 미만이면, 1차 증거 지표의 해석을 S7(의무 면제를 법적 하자로 잘못 찍지 않음)과 S8(여비의 근로소득 전환 판단 재료를 빠뜨리지 않음)로 옮긴다.”** 48건과 N=3은 모두 `[설계 가정]`이며 실제 회사 빈도나 법령 수치가 아니다. 플래그는 같은 지출의 두 사유를 한 건으로 접고, 두 사유별 건수도 공개한다. 3건은 이 표본에서 극히 적은 신호를 “비었다”로 분류하기 위한 사전 선택이지 통계적 입증선이 아니다(D13, `docs/PRD.md:119-120`, `docs/design/receipt-pipeline.md:2498-2505`).

재해석 전후에도 S7·S8의 하드 위반은 각각 그대로 판정한다. 이 규칙은 합성 분포 위의 **반증 방향만** 말하고 입증을 선언하지 않는다(D3·D12, `docs/research/eval-plan-lane-brief.md:32`, `:41-42`).

| 조항 선택 | 함정 질문마다 첫 step 작성자가 규정 원문과 질문의 적용 사실을 보고 **허용 조항 ID 목록**을 붙인다. 모델이 고른 `(문서코드, 판, ID)`가 목록에 있는지 집합 대조한다. 목록 충돌은 D7 절차 | D6·D7·D11, `docs/research/eval-plan-lane-brief.md:35-40` |

| 의미와 숫자 | 범위 표지·주어를 잘라 다른 경우에 적용하는 실패는 전문 부착으로 막고, 같은 숫자의 반대 방향 문장은 서버 템플릿의 의미 태그와 계산 기록으로 검사한다. 사람이 볼 표본에는 질문·전문·앞뒤 맥락을 함께 둔다 | #11의 #15 코멘트 결함 A/B, ADR-0020:32-40, `docs/ARCHITECTURE.md:193-197` |

원문 확인: PRD가 요구하는 승인 카드·보류 답변의 **원문 인용 대상은 사내 정책 조항**이고(`docs/PRD.md:154`, `CONTEXT.md:368-373`), 답변기의 조항 도구도 적용 판의 정책 조항이다(ADR-0020:32-45). 증빙 설계의 예시 화면에는 법인세법 시행규칙 §79처럼 **법령 식별자와 판정 이유**가 붙지만, 법령 조문 전문을 제품이 축자 인용하는 자리는 확인되지 않는다(`docs/design/receipt-pipeline.md:2482-2494`). 따라서 이 전제 아래 #15의 **법령 원문 재대조 주기**는 현 제품 Eval 밖이다(D14의 기본값, `docs/research/eval-plan-lane-brief.md:46`). 나중에 법령 원문 축자 인용을 넣으면 조항별 시행일·원문 스냅샷과 수신 시점을 보존하고, 이미지 조문도 포함해 재대조 주기를 별도 이슈로 정해야 한다(#11의 #15 코멘트). 사내 규정의 적용 판/원문 대조는 지금도 S4로 유지한다.

## §13 구현 검증 계약

아래 7문장은 `97d1dd9:docs/research/agent-architecture-proposal-codex.md:454-460`의 **원문 그대로**다(공통 지시서 `docs/research/eval-plan-lane-brief.md:58-67`). phase 이름은 실제 `phases/` 설계 전에 쓰는 `[설계 가정]`인 단계 별칭이다. 첫 step은 정답 저작만 하고 시험 코드는 뒤 step에서 쓴다(D6).

| # | 검증 계약 원문 | 구현 phase의 시험 계획 `[설계 가정]` |
| --- | --- | --- |
| 1 | 책임자 미배정·타 세계 ID·다른 역할로 호출해 모델/커넥터가 시작되지 않는지 확인한다. | 경계/권한 step: 역할×세계×책임자 조합 속성 시험, 시작 호출 0 대조. ADR-0013·0019 |
| 2 | 모델 응답 수신 전후·결과 커밋 직전·임대 만료 시 종료해 중복 필드 버전·감사 없는 전이·늦은 반영이 없는지 확인한다. | 작업/감사 step: 각 중단점 결함 주입 뒤 재개, revision·감사 행·fencing 비교. ADR-0011·0012 |
| 3 | 판독 원본에 업무 명령 지시문을 넣어 A가 B의 조회나 쓰기 권한을 얻지 못하는지 확인한다. | 모델 계약 step: 이미지·메일 원문의 주입 픽스처와 세계 접근 거절 확인. ADR-0018 반증 1, ADR-0021:86-93 |
| 4 | 같은 숫자를 반대 방향으로 서술한 답변, 다른 판 조항, 비연속 합성 인용이 표시되지 않는지 확인한다. | 답변/화면 step: 방향 템플릿·판·전문 결함 주입, 화면 노출 0. ADR-0020:88-94, S4 |

| 6 | 사전승인→총무 연결→인사 근태→정산 재무 동의→전결→지급을 같은 사건으로 추적한다. 반려·재상신/미정 후속은 #17을 채운 뒤 실행하고, 그 전에는 성공 처리되지 않는지 확인한다. | 통합 step: 연결 ID 전구간 추적. #17은 닫혔으므로 남은 `UNDEFINED_BY_17`·`UNDEFINED_BY_26`만 성공 거절. `docs/PRD.md:161` |
| 7 | 승인자가 읽은 카드의 판정 항목 집합과 계산 기록 집합을 비교하고 독립 평가기로 숫자·기한·결재선을 다시 계산한다. 제품 함수를 두 번 부르는 검증은 독립으로 세지 않는다(docs/adr/0013-postgres-object-storage-isolated-by-world-id.md:37). | 통합/카드 step: 카드 스냅샷 항목 집합 대조와 규정 블록 독립 재계산. S2·S3·S10·S15 |

#26의 추가 불변식은 같은 대사/라우팅 step에서 **속성 기반 시험**으로 둔다. `(카드 줄 ID, 증빙 ID)` 확정 짝의 1:1 유일성, 같은 입력의 결과와 영수증 없음 불변, 사람 선택과 모순된 자동 확정 금지, 한 경쟁 묶음의 직렬화와 `STALE_REVISION`, 교착 없는 진행, 입력 소진 뒤 종료를 각각 결함 주입한다(`docs/design/receipt-pipeline.md:2250-2283`, ADR-0031 결정 5, #11의 #26 코멘트). 판독기·답변기 계약을 합친 변형에서도 악성 원문이 답변을 오염시키는지 비교해 ADR-0018 반증 1을 측정한다. #11이 요구한 실패 주입에는 깨진/늦은 카드 파일, 메일 원문 변경, 조직 배정 부재를 넣는다(ADR-0021:86-96, `docs/ARCHITECTURE.md:550-563`). 이 시험들은 설계 계약이며 현재 구현·합격을 주장하지 않는다.
