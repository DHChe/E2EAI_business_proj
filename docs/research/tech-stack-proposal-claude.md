## 1. 출발점 — 기다림은 계산이 아니라 문서의 상태다

#9 갱신 1은 "에이전트가 기안·결재를 대신 올리는 순간"을 전제로 삼았다(`gh issue view 9`, 갱신 절). 그 뒤 저장소가 이 전제를 거뒀다.

- **에이전트는 결재 행위의 행위자가 되지 않는다.** PRD 그릴링 2026-09-21 결정이다(`CONTEXT.md:331`). MVP 제외 13도 자동 승인과 자동 동의를 두지 않는다(`docs/PRD.md:141`).
- **증빙 파이프라인에서 모델을 부르는 곳은 두 곳이다.** 검산·대사·판정은 전부 코드다(`docs/design/receipt-pipeline.md:74`).
  파이프라인 밖에서 모델을 부르는 곳은 보류 답변(`docs/PRD.md:45`)과 여행사 이메일 판독(`CONTEXT.md:345`) 둘이다.
- **기한은 저장값이 아니라 계산값이다**(`docs/company/travel-procedure.md:48` `PRC-3-1`). 경과는 표시만 한다(`docs/PRD.md:46`).
  "N일 뒤에 깨워라" 같은 타이머가 필요 없다. 필요한 것은 기준일과 시계다.
- **승인 대기 타임아웃과 기한 초과 뒤의 상태는 #17의 미결이다**(`docs/PRD.md:143`, `docs/company/travel-procedure.md:285` `PRC-14-3`).
  그러니 런타임이 만료를 스스로 처리하는 기능은 지금 쓸 데가 없다.

그러면 작업의 모양은 아래와 같다.

| 작업 | 행위자 | 모델 호출 | 길이 | 루프 안에서 사람을 기다리나 | 근거 |
| --- | --- | --- | --- | --- | --- |
| 증빙 ① 사전 검사(업로드 즉시) | 에이전트 | 1회 | 요청 1개 | 아니다. 결과를 제출자에게 곧바로 보여 준다 | `receipt-pipeline.md:242-243` |
| 증빙 ② 필드 판독 | 에이전트 | 1회(+배치 재처리) | 요청 1개 | 아니다. 불확실한 값은 수기 확정 **작업**으로 넘긴다 | `receipt-pipeline.md:74`, `:337` |
| 여행사 이메일 판독 | 에이전트 | 1회 | 요청 1개 | 아니다 | `CONTEXT.md:345`, `docs/company/tools.md:15` |
| 보류 답변 | 에이전트 | 몇 턴(읽기 전용 도구) | 요청 몇 개 | 아니다. 답을 만든 뒤 검증하고 보여 준다 | `docs/PRD.md:45` |
| 검산·대사·판정·결재선·한도·기한 | 시스템(코드) | 0 | 즉시 | 해당 없음 | `receipt-pipeline.md:74`, ADR-0005 |
| 수기 확정 | 사람(기안자) | 0 | 사람 시간 | 문서 상태 | `receipt-pipeline.md:273` |
| 결재(승인·동의·반려·보류) | 사람(결재선) | 0 | 며칠 | 문서 상태 | `CONTEXT.md:384`, `PRC-14-1` `travel-procedure.md:269` |
| 이의 플래그(재심 개시) | 사람(admin) | 0 | 즉시 | 문서 상태 | `docs/adr/0002-admin-read-only-audit-axis.md:21-29` |
| 지급 처리 | 사람(재무팀) | 0 | 즉시 | 문서 상태 | `docs/PRD.md:132` |

**결론 [유도]:** 에이전트 작업은 전부 **짧고 경계가 있는 작업**이다. 사람의 판단은 에이전트 루프 **밖에서** 문서 상태를 바꾼다.
그래서 R-b(며칠 걸리는 대기)는 DB의 행 하나로 충족된다. 프로세스를 붙잡고 있을 필요가 없다.
R-d(중단과 재개)는 작업 하나를 저장된 입력으로 다시 돌리는 것으로 충족된다.
대화 상태가 여러 요청에 걸치는 경우는 보류 답변 하나다. 그 `messages` 배열은 작업 행에 저장한다(#4 `:331`).

이 논지가 틀리는 조건은 §3.5 반증 1이다.

## 3. 에이전트 런타임

### 3.1 추천 — B1: Messages API 직접 호출

- **SDK**: `@anthropic-ai/sdk` 0.127.0(MIT).
  구조화 출력은 `client.messages.parse()`에 `output_config.format`으로 `zodOutputFormat()`(`@anthropic-ai/sdk/helpers/zod`)을 넘긴다. 구조화 출력은 GA다.
  그러면 `receipt-pipeline.md:372-441`의 zod 슬롯을 요청 스키마로 바로 쓸 수 있다.
  한계: 외부 `$ref`는 지원하지 않고, `allOf`와 `$ref`를 함께 쓸 수 없다(§12 structured-outputs, 확인 2026-09-22).
- **작업 = DB의 `job` 행 하나.** 상태는 `queued | running | done | failed | paused`이고, 임대(`lease_until`)와 시도 횟수를 둔다.
  같은 프로세스 안의 워커가 임대를 잡고 실행한다. 프로세스가 죽으면 임대가 끝나고 다시 잡힌다.
  결과는 `field_value` 새 행으로 쓴다. `(job_id, field)`에 유일 제약을 걸어 재시도가 값을 두 번 쓰지 않게 한다(멱등).
- **보류 답변은 작은 수동 루프다.** 도구는 계산 기록과 조항 원문을 읽는 **읽기 전용** 도구뿐이다. 도구 목록은 #10이 정한다.
  답을 다 만든 뒤 검증하고, 통과한 답만 보여 준다.
  - S4(인용이 조항 원문의 연속 부분문자열인가, 숫자가 계산 기록과 같은가)는 기계 대조로 한다(`docs/PRD.md:154`).
  - S5(재량 조항을 판단한 문장이 없는가)는 기계 대조만으로는 다 잡지 못한다 `[유도]`. 판정 방식은 #11이 정한다.

  검증 전에 토큰을 화면에 흘리면 S4를 어긴 문장이 잠깐이라도 보인다. 그래서 **토큰 스트리밍은 하지 않고** 단계 전이만 보낸다(R-a를 이 수준으로 정의한 이유).
- **Tool Runner(B2)를 쓰지 않는 이유**
  1. Tool Runner 문서가 직접 "human-in-the-loop approval, custom logging, or conditional execution"에는 수동 루프를 쓰라고 한다(#4 `:305`). 우리는 턴마다 모델 호출을 기록해야 한다(§5.5).
  2. 러너 상태를 프로세스 밖으로 직렬화하는 방법이 문서에 없다(#4 `:983`).
- **상태 기계는 순수 TS 리듀서로 쓴다.** 모양은 `(문서 상태, 명령, 맥락) → 이벤트[] | 거부`다. 결재선 단계는 **데이터**다(§3.4).
- **ADR-0010의 정지를 작업 큐로 구현한다.** 사람에게 보내는 양이 상한을 넘으면 큐를 `paused`로 두고 미완료·대기 수를 공개한다(`docs/adr/0010-...:36-37`).
  대기 건을 승인 카드로 흘려보내는 경로는 코드에 두지 않는다.
- **판정 입력의 경계.** 판정 작업은 필요한 필드가 모두 `Confirmed<T>`(`_status` 없음)일 때만 큐에 넣는다(ADR-0008 `:32`, `receipt-pipeline.md:776-798`).
  타입이 한 번 막고, 큐에 넣는 조건이 다시 막는다.

### 3.4 상태 기계 — R-f를 데이터로 표현한다

- **결재선은 기안 시점에 `approval_step` 행으로 고정한다.** 열은 `document_id, seq, role(결재권자|재무합의자), assignee_person_id, clause_ref`다(`APV-11-1`, `CONTEXT.md:44`).
  정산 문서의 재무합의 단계는 결재 단계보다 앞의 `seq`를 받는다(`APV-9-1`).
  단계 목록은 전결표 블록에서 계산한다. S2는 이 계산을 규정 블록으로 독립 재계산해 비교한다(`docs/PRD.md:152`).
- **액션 집합은 역할에 붙는다.** `ACTIONS[결재권자] = {승인, 반려, 보류}`, `ACTIONS[재무합의자] = {동의, 반려, 보류}`다(`CONTEXT.md:384`, `APV-9-5`).
  ADR-0003은 provisional이고 #17이 시험한다(`docs/adr/0003-approver-actions-three.md:3`). 집합을 데이터로 두면 그 결과를 반영하기 쉽다.
- **리듀서의 판정 순서**
  1. 명령의 행위자가 **현재 단계**(가장 앞의 미완료 단계)의 담당자인가.
  2. 액션이 그 역할의 집합에 드는가.
  3. `blocking: true`면 앞 단계가 동의하기 전에는 뒤 단계가 행동할 수 없다.
  4. `reject_always_allowed: true`면 반려는 자기 차례에 늘 유효하다.

  마지막 결재 단계가 승인하면 문서는 재무팀 지급 처리 대기로 간다(`docs/PRD.md:132`).
- **정의되지 않은 전이는 이름 붙은 거부로 막는다.** 반려·보류 이후의 상태, 이의 재심의 복귀는 #17의 몫이다(`docs/PRD.md:177`).
  #17이 정하기 전까지 리듀서는 그 전이를 추측하지 않는다. `UNDEFINED_BY_17` 같은 이름 붙은 거부를 돌려준다. S11 하드 규칙("#17이 정하지 않은 후속 상태를 성공으로 처리하지 않는다", `docs/PRD.md:161`)을 코드로 옮긴 것이다.
- **admin의 이의 플래그는 결재 액션이 아닌 별도 명령이다.** 문서를 `재무합의대기`로 되돌리고(`docs/adr/0002-...:29`), 감사 이벤트 종류도 따로 둔다. 네 번째 액션으로 세지 않는다(`:65-66`).
  admin에게는 값 수정·원복 명령이 **아예 없다**(`:23-27`).
- **DB가 한 번 더 막는다.** 결재 행위 이벤트를 넣을 때 트리거가 확인한다(§5.3).
  - 행위자가 사람이고 현재 단계의 담당자와 같은가.
  - 기안자와 다른가(`APV-8-2` `approval-matrix.md:176`).
  - 책임자가 NULL이 아니고 사람인가.

  이 중 하나라도 어기면 `RAISE(ABORT, …)`로 문장을 끝낸다(§12 SQLite trigger).
  애플리케이션의 버그 하나가 S11 하드 규칙을 깨지 못하게 한다.

### 3.5 `APV-9-3` 노출의 형태와 변경 주체 — 제안

PRD는 이것을 #9·#10에 맡겼다(`docs/PRD.md:173`, `CONTEXT.md:403`).

- **형태: 조항 값을 그대로 보여 준다(읽기 전용).** 결재선 화면과 카드에 `APV-9-3`의 세 값을 `(APV, 판, APV-9-3)` 인용과 함께 표시한다. 따로 두는 "설정 화면"은 없다.
- **변경: 판 개정으로만 한다.** ADR-0005는 원본이 문서 셋뿐이고 정책 값을 별도 파일에 두지 않는다고 했다(`docs/adr/0005-...:30-32`). 제외 10도 코드 상수를 금한다(`docs/PRD.md:138`).
  그러면 값을 바꾸는 유일한 길은 전결표의 새 판이다. **변경 주체는 규정 개정권자다**(규정을 개정할 권한이 곧 이 설정을 바꿀 권한이 된다는 점, `CONTEXT.md:67`).
  admin은 바꾸지 못한다(`docs/adr/0002-...:27`).
- **실행: 엔진은 판 1의 값 조합 `{sequential: true, blocking: true, reject_always_allowed: true}`만 실행한다.** 다른 조합의 판을 올리면 **부팅이 이름 붙은 오류로 실패한다.**
  근거는 제외 3이다. "재무합의를 합의의 일반형으로 넓히지 않는다"(`docs/PRD.md:131`). 병렬이거나 차단하지 않는 재무합의를 실행하는 것은 그 일반화다 `[유도]`.
- 이 제안의 약점은 §9 질문 3에 적었다.

### 3.6 반증 조건

1. **#10이 에이전트에게 실행 전에 사람 확인이 필요한 부작용 도구를 준다**(예: 여행사로 메일 발송, 전표 생성). 그러면 C1이 돌아온다.
   그 경우에도 `job.status = awaiting_confirmation`과 명령 하나로 충분할 수 있다.
   **한 작업 안에 사람 확인 지점이 둘 이상이고 그 사이에 보상 동작이 필요해지면** 내구 실행 계층을 다시 평가한다.
2. **보류 답변이 몇 턴의 루프로는 S4·S5 위반을 막지 못한다.** 더 긴 탐색이 필요해지고, 한 번의 답변이 수십 초를 넘는다(실측).
   그래도 B1은 유지한다. 대신 R-a를 "단계 전이"에서 "도구 호출 단위 진행"으로 올린다.
3. **구조화 출력이 zod 슬롯 스키마를 거부한다**(§3.1의 `$ref` 제한 등).
   그러면 도구 입력 스키마를 쓰는 방식으로 내려간다. 여전히 B1이다.
4. **같은 프로세스 안의 워커가 처리량을 못 따라간다.** 예를 들어 `job` 대기 시간이 수기 확정 화면의 응답 기대를 넘는다(임계값은 #11).
   그러면 워커를 별도 프로세스로 뗀다. 테이블은 그대로 둔다.

## 4. 웹 스택

### 4.1 추천 — TypeScript 단일 저장소: React(Vite) SPA + Hono(Node) API

- **한 프로세스**에 셋을 둔다. HTTP API(Hono 4.13.8, MIT), 같은 프로세스 안의 `job` 워커(§3.1), 커밋 뒤 이벤트 버스다. 정적 SPA도 같은 서버가 내준다.
- **명령은 `POST` 하나의 명령 처리기로 들어간다.** 행위자 식별자는 서버 세션에서 꺼낸다. **요청 본문에서 받지 않는다**(R-e의 웹 층 보증).
- **진행 상황은 SSE로 보낸다.** 연결하면 스냅샷을 먼저 보내고 이어서 이벤트를 흘린다(§4.3). 뷰어 하나에 연결 하나이고, 그 뷰어의 큐 전체가 그 한 연결로 온다(R-c).
- **카드는 JSON 뷰 모델로 만든다.** 판정 기록에서 `CardViewModel`을 만들고 화면은 그것을 그린다.
  그러면 S15("판정 기록의 항목 집합 = 카드 항목 집합", `docs/PRD.md:165`)가 DOM 긁기가 아니라 **데이터 비교**가 된다.
  카드의 형태는 #8이 정한다(`docs/PRD.md:172`). 이 제안은 뷰 모델이 데이터로 있다는 것만 정한다.

그래서 W1이 조금 앞선다. 둘의 차이는 되돌릴 수 있는 크기다.

| 재접속 | 명세가 정한다. 브라우저가 `Last-Event-ID` 헤더를 붙여 다시 붙고, `retry` 필드로 간격을 정하며, 204로 재접속을 멈춘다(§12 WHATWG, 확인 2026-09-22) | 직접 만든다 | 해당 없음 | 해당 없음 |

감사 이벤트의 순번을 SSE id로 쓰면 **화면의 재개(R-d)와 감사 로그가 같은 순서를 공유한다.** 화면이 본 것이 곧 감사 로그의 접두사다.

### 4.4 반증 조건

1. **Python으로만 돌릴 수 있는 부품이 들어온다.** 1순위 후보는 방향 분류기다(§11 모순 5).
   그 경우 스택을 바꾸지 않고, `job`의 한 종류로 Python 사이드카를 붙인다. ADR 후보 E의 문구가 "TS + 사이드카 한 종류"로 바뀐다.
2. **배포 플랫폼의 프록시가 SSE를 버퍼링하거나 끊는다.** 그러면 폴링으로 내려간다. 배포 뒤 첫 확인 항목이다.
3. **#12의 시각 시스템이 특정 프레임워크에 묶인 부품 라이브러리를 요구한다.** 그러면 W1의 React 선택을 다시 본다. `docs/ui-guide.md:22-23`은 토큰을 스택이 정해진 뒤에 적는다고 했다.

## 5. 데이터 저장

### 5.1 추천 — SQLite, 세계 하나당 파일 하나

- **세계(world)**는 한 벌의 회사 데이터와 그 위의 모든 문서·감사 이벤트다. 읽기 전용 시드 `seed.sqlite`에서 **복사**해 만든다.
  - 공개 데모 방문자 한 명(§6) = 세계 하나
  - 평가 시나리오 하나(#11) = 세계 하나
  - 하네스 AC 하나 = 세계 하나(`docs/agents/harness.md:96` "AC는 실행 가능한 커맨드")
- 라이브러리는 `better-sqlite3` 13.0.3(MIT, Node ≥22)로 한다. **WAL** 모드를 켠다.
  읽기와 쓰기는 동시에 진행되지만 **쓰기는 한 번에 하나**이고, WAL은 **네트워크 파일시스템에서 동작하지 않는다**(§12 SQLite WAL, 확인 2026-09-22).
  세계가 방문자 단위로 쪼개져 있으니 한 파일에 쓰는 주체는 대개 한 사람이다 `[유도]`.
- 시드는 합성 시나리오를 빌드 스크립트로 만든 **파생물**이다. 커밋하지 않는다. ADR-0005 ⑤와 같은 태도다(`docs/adr/0005-...:88-91`).

**독립 재계산(S2·S3·S10)과의 관계.** 평가기는 앱의 계산 결과를 믿지 않는다. 규정 블록과 **저장된 입력**(확정값, 기준일, 적용 판)으로 다시 계산한다.
그래서 입력은 전부 저장하고, 파생값(기한)은 저장하지 않는다. 기한을 저장하지 않으니 "저장 날짜에만 의존한 기한"이 생길 자리가 없다.

**판이 여럿 동시에 살아 있어야 한다.** `PRC-2-2`(`travel-procedure.md:33`)는 사전승인 기안일의 판을 정산까지 적용한다. 그러면 새 판이 나온 뒤에도 옛 판으로 판정되는 출장이 남는다.
지금 저장소에는 문서마다 파일이 하나뿐이다(§11 모순 6). 옛 판을 둘 자리를 정할 때까지 이 MVP는 **판 1만 적재**한다. 해시 고정은 그 판이 몰래 바뀌지 않게 막는다.

### 5.4 증빙 처리 라이브러리 — 배포에 걸리는 사실 하나

- EXIF 방향 보정은 `sharp`(0.35.4, Apache-2.0)의 `autoOrient()`로 한다. "Auto-orient based on the EXIF `Orientation` tag, then remove the tag"(§12 sharp, 확인 2026-09-22).
- PDF 직접 래스터화(ADR-0009 `:26`) 후보:
  - `mupdf`(npm) 1.28.1은 **AGPL-3.0-or-later**다. 공개 링크로 서비스하면 AGPL의 네트워크 조항이 걸린다 `[유도]`.
  - `pdfjs-dist` 6.3.289는 Apache-2.0이다. Node에서 래스터화하려면 캔버스 구현이 필요하다 [미확인].
  - 라이브러리 선택은 구현 phase의 몫이다. 라이선스는 배포 형태(§6)와 함께 정한다.

### 5.5 모델 호출 기록과 재생

모든 모델 호출은 `request_hash`(모델, 시스템 프롬프트, 메시지, 이미지 sha256, 출력 스키마의 정규화 해시)로 기록한다. 실행 모드는 셋이다.

| 모드 | 동작 | 쓰는 곳 |
| --- | --- | --- |
| `live` | API를 부르고 기록한다 | 로컬 개발, 공개 데모의 라이브 버튼(§6) |
| `replay` | 해시로 기록을 찾아 돌려준다. **못 찾으면 큰 소리로 실패한다**(몰래 live로 넘어가지 않는다) | 공개 데모 기본, 하네스 AC, #11 회귀 |
| `record-missing` | 없는 것만 live로 부르고 기록한다 | 시드 만들기 |

얻는 것은 셋이다.

1. **API 키 없이 시스템 전체가 돈다.** 하네스에서 "API 키"는 `blocked` 사유다(`docs/agents/harness.md:73`). 모델 호출이 끼는 step도 재생으로 AC를 통과할 수 있다.
2. 프롬프트나 모델을 바꾸면 해시가 달라져 재생이 실패한다. 그래서 **바뀐 호출이 드러난다**. 회귀로 쓸지는 #11이 정한다.
3. 데모가 결정적이다.

### 5.6 반증 조건

1. 한 세계 안에서 `SQLITE_BUSY` 대기가 실측된다. 예를 들어 워커 쓰기와 사람 명령이 부딪쳐 명령 응답이 늦어진다. → Postgres(S2).
2. 인스턴스를 여럿으로 늘려야 한다. WAL은 네트워크 파일시스템을 지원하지 않는다. → Postgres와 `LISTEN/NOTIFY`.
3. #1이 **모든 심사자가 같은 세계를 공유**하는 데모를 원한다. 한 파일에 쓰는 사람이 늘어나니 1번을 먼저 잰다.
4. SQLite 트리거로 결재 행위 가드를 표현할 수 없다. 예를 들어 #17이 대결 같은 교차 규칙을 넣는데 제외 3이 그것을 막지 않는 경우다. → 가드를 애플리케이션 계층 하나로 줄이고, 그 사실을 ADR에 적는다.

## 6. 실행·배포

### 6.1 추천 — 공개 링크, 상시 컨테이너 1대

- **PaaS 컨테이너 한 대.** 예를 들어 Fly.io의 `shared-cpu-1x` 256MB는 월 $2.02이고, 볼륨은 GB·월 $0.15다(§12 Fly, 확인 2026-09-22).
  `sharp`와 PDF 래스터화에 필요한 메모리는 [미확인]이다. 256MB로는 모자랄 수 있다.
- **방문자별 샌드박스.** 첫 방문에 시드를 복사해 세계를 만든다. 서명 쿠키가 `(world_id, persona)`를 든다. 일정 기간 쓰지 않은 세계는 지운다.
  **시연용 세계를 지우는 것은 감사 로그 삭제가 아니다.** 세계 자체가 소멸하는 것이다. 한 세계 안에서는 append-only다.
- **시나리오 시계.** 기한은 주입한 시계로 계산한다(§5.3). 그러니 세계마다 시나리오 날짜를 줄 수 있다. 실제 날짜와 상관없이 "기한 D-1"이 같은 모습으로 보인다.
  "시계 앞으로"는 세계 메타데이터에 적는다. 감사 이벤트와 섞지 않는다(S11 오염 방지).
- **기본은 기록 재생이다(§5.5).** 화면에 "기록된 실행 — 모델 응답은 YYYY-MM-DD의 실행 기록"이라고 표시한다.
  **라이브 판독**은 미리 고른 표본에만, 하루 예산 상한 안에서 한다. 상한은 DB에서 `usage × 단가`를 합산해 우리가 센다. Anthropic 콘솔의 지출 한도 기능은 [미확인].
- **같은 이미지를 로컬에서도 띄운다.** `docker compose up` 하나로 뜨고, 자기 키를 넣으면 live가 된다.

### 6.2 심사자 3분 경로의 모양

데모 시나리오의 **내용**은 #1이 정한다(`docs/PRD.md:178`). 여기서는 인프라가 허락해야 하는 **모양**만 적는다.

1. 링크를 연다. 로그인 없이 세계가 생긴다. 키도 설치도 없다.
2. 페르소나를 고른다. 출장자, 결재권자, 재무합의자, admin 중 하나다.
3. 시드된 세계에는 여러 상태의 문서가 이미 있다. 기한순 큐(#8)가 바로 보인다(R-c).
4. 행동 하나를 한다. 승인·반려·보류, 수기 확정, 보류 답변 요청 중 하나이고, 결과가 SSE로 온다(R-a).
5. 그 문서의 감사 이력을 연다. 행위자·책임자와 필드 출처가 보인다(R-e, R-g).
6. (선택) 시계를 앞으로 돌리거나, 프리셋 표본으로 라이브 판독을 한 번 돌린다.

### 6.4 비밀, 비용, 합성 데이터

- **비밀**: `ANTHROPIC_API_KEY` 하나다. 플랫폼 비밀로만 두고 클라이언트에 내보내지 않는다. `replay` 모드에서는 키가 없어도 된다.
- **비용 추정 `[유도, 실측 전]`**: 기준은 Sonnet 5의 입력 $2/MTok, 캐시 적중 $0.20/MTok, 출력 $10/MTok이다(§12 pricing, 확인 2026-09-22).
  - 증빙 한 장은 호출 둘(①·②)이고, 이미지는 최대 4,784 시각 토큰이다(`receipt-pipeline.md:119`).
  - 프롬프트 약 2,000토큰, 출력 ① 200 / ② 1,500토큰을 **가정**하면 캐시 없이 약 $0.044다.
  - ②가 ①의 이미지를 캐시로 받으면(`:337-343`의 순서) 약 $0.03이다.
  - Opus 5($5/$25)면 약 2.5배다. 모델 선택은 #11의 몫이다.
- **합성 데이터**: 범위와 이미지 출처는 #1의 몫이다(`docs/PRD.md:178`). 스택 쪽에서는 두 가지만 약속한다.
  1. 시드는 스크립트로 만든다.
  2. 증빙마다 `image_origin`을 기록해 S9·S12를 이미지 출처별로 가를 수 있게 한다(`docs/PRD.md:117`).

  공개 링크에서 **임의 업로드**를 허용할지는 개인정보와 얽힌다(`docs/PRD.md:132`, `:178`). 그래서 §9 질문 2로 올렸다.

### 6.5 반증 조건

1. #1이 공개 링크를 두지 않기로 정한다. 예를 들어 개인정보·권한의 깊이 때문이다. → D3을 주 경로로 하고 D4를 보조로 둔다.
2. 라이브 판독 비용이나 남용이 상한을 반복해 넘는다. → 라이브를 끄고 D1 재생만 남긴다. 그래도 못 버티면 D4로 간다.
3. 최소 머신의 메모리로 PDF 래스터화가 안 된다. → 머신을 키운다. 비용 행이 바뀐다.
4. AGPL 라이브러리를 쓰기로 했는데 소스 공개 조건을 받아들일 수 없다. → Apache 계열로 바꾼다(§5.4).
