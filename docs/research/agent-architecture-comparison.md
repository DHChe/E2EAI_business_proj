# #10 에이전트 아키텍처 — 3레인 통합 비교와 결정 기록

- **날짜**: 2026-09-22
- **맥락 티켓**: #10 (에이전트 아키텍처 설계)
- **상태**: 비교와 결정 완료. ARCHITECTURE 문서와 ADR 0018~은 **아직 쓰지 않았다**(§7).

이 문서는 세 레인의 독립 제안을 한 자리에 놓는다. 무엇이 합의였고 무엇이 갈렸으며, 누가 어떻게 정했는지를 남긴다. 여기의 번호(A·D·U·C)는 뒤에 쓸 ARCHITECTURE와 ADR이 그대로 인용한다.

## 0. 방법

1. **세 레인 독립 제안.** codex·grok·claude 세 모델이 **같은 지시서**(레인 이름만 다름)로 서로 읽지 않고 풀었다. 셋 다 develop `3bbe46a`에서 갈라졌다. codex·grok은 Orca 워커로(run `run_8c9365ca95d7`), claude는 코디네이터의 서브에이전트로 돌았다.

   | 레인 | 커밋 | 분량 | 원문 브랜치 (로컬, 아직 push 안 함) |
   | --- | --- | --- | --- |
   | codex | `97d1dd9` | 462줄 | `DHChe/frontier-10-arch-codex` |
   | grok | `46e5540` | 516줄 | `DHChe/frontier-10-arch-grok` |
   | claude | `a30c5f7` | 1090줄 | `DHChe/frontier-10-arch-claude` |

   원문은 `docs/research/agent-architecture-proposal-<레인>.md` 한 파일씩이고, develop에 병합하지 않고 위 브랜치로만 보존한다(#9 U8과 같음). 이 문서는 원문을 "codex §3.1"처럼 절 번호로 가리킨다.
2. **결정을 가르는 사실은 코디네이터가 원문으로 재확인했다.** 대상은 SlipScan 두 요약, PRD:45, `APV-9-4`, `PRC-10-1`, ADR-0011:35, ADR-0005:12-14, `CONTEXT.md:365`, 카드사 조회 기능이다(§2 끝, §4). 저자와 다른 모델의 교차 검증은 아직 하지 않았다(§7).
3. **결정.** 세 레인이 독립으로 같은 답을 낸 15건은 합의로 받았다(§2). 갈린 자리 가운데 되돌리기 어려운 6건은 사용자가 골랐다(§5). 되돌리기 쉽거나 합의가 받치는 9건은 코디네이터가 정해 사용자에게 알렸다(§6, 이의 없음).

출처 표기: **합의** = 세 레인이 서로 읽지 않고 같은 답. **사용자** = 사용자가 고름. **코디네이터** = 코디네이터가 정하고 사용자에게 알림.

## 3. 갈린 자리

### D1. LLM 에이전트의 수 — 2 vs 3

- **grok 3**: 분류와 추출을 다른 계약으로 센다. 이유는 **실패 격리** — 한 응답이 유형과 금액을 같이 쓰면 검산을 통과하는 유형 쪽으로 금액을 맞춘다(grok §3.3 1행).
- **codex·claude 2**: 분류·추출은 권한(도구 0)·입력 신뢰 수준(같은 이미지)·책임자가 같아 에이전트 경계가 아니다(claude §2.3, codex §1.1).
- **실질**: 세 레인 모두 분류·추출을 **별도 호출·별도 스키마**로 둔다(#18 그대로). 차이는 그 스키마 경계를 "에이전트 경계"로 세느냐다.
- 판독기와 답변기를 가르는 이유는 codex·claude가 같은 것을 댔다 — 영수증·메일 속 지시문이 조회 도구를 쥐고 승인자에게 문장을 내는 맥락에 들어가지 않게(**실패 격리/권한**).

### D2. 에이전트가 기안 초안을 쓰는가

- **codex**: A가 기안자가 준 서술·첨부를 폼 후보로 구조화하는 초안 작업을 한다(에이전트 초안 + 사람 상신). "위임 범위 내 에이전트 상신"은 사용자 질문으로 남김(codex §5.3, §9).
- **grok·claude**: 없다. 모델 호출 지점은 ADR-0011이 센 4곳(분류·추출·메일 판독·보류 답변)에서 늘리지 않는다(claude §2.1, §6.4 표 "에이전트가 쓰는 초안").
- 저장소 상태: ADR-0011:100 정정이 "에이전트는 결재 행위자가 되지 않는다"는 결재 쪽만 거뒀고 **기안 쪽은 열려 있다**고 적었다.

- **codex의 약점(스스로 적음)**: 담당자가 결과를 열람·중단할 권한 없이 이름만 빌려주는 사람이 될 위험, 새 개념(운영 배정·팀장 재배정·배정 버전)이 규정에 없다 — 표 전체가 `[설계 가정]`.
- **grok의 약점**: "기안자 고정"을 기각했지만 규칙의 결과가 기계 조작 대부분에서 기안자다. #9에서 지적된 "확정 전 오독의 책임이 출장자에게 찍힌다"가 그대로 남는다.
- **claude의 약점(스스로 적음)**: 영수증 추출은 여전히 기안자(H3~H5가 자동 확정한 칸은 기안자가 안 봤을 수 있음). 없애지 못하고 `responsible_rule`로 "확정했다" vs "검토 의무가 있다"를 드러내기만 한다. 근거는 `PRC-11-2`(정산은 확정값 위에서만 기안 — 기안자가 서명).
- 모두 ADR 후보(codex 0019, grok 0019, claude 0019)이고 감사 스키마에 박히므로 **되돌리기 어렵다.**

### D4. 보류 답변의 형태 — 문장 검사 vs 슬롯

- **grok**: 모델이 문장을 쓰고, 검사기가 숫자=계산 기록·인용=부분문자열·재량 판단/권고 없음을 대조한다(grok §4).
- **codex**: B는 계산 ref·조항 ref와 서술 조각만, 서버가 숫자·인용을 채운다. 원문은 "계산이 120,000원 초과라도 LLM이 '한도 이내'라고 쓰면 숫자 일치 검사만 통과할 수 있다"고 적는다. 그래서 금액·기한·결재선·판정 **방향**을 주장하는 문장은 서버 템플릿으로만(codex §2.2).
- **claude**: `text`/`calc`/`quote` 슬롯, text에 숫자 리터럴(한국어 수사 목록 포함) 금지, `outcome` enum(`answered`·`needs_drafter`·`discretion_returned`·`cannot_answer`), V1~V5. V1 수사·V4 문형·V5는 목록형이라 불완전하다고 인정(claude §3.3, §4.3).
- codex의 반례는 grok 방식에 그대로 적용되고, claude 방식에서도 방향 문장은 `text` 조각 안에 남을 수 있다(V4는 권고 문형만 봄).

### D5. 모의 커넥터 — 3개 읽기 전용 vs 4개(ERP 포함)

- **claude**: ERP를 만들지 않는다. 판정이 읽는 ERP 값이 없고(지급 처리는 상태 전이, 장부 원화는 확정하지 않음 `docs/PRD.md:136`, `TRV-14-3`), 쓰는 커넥터를 두지 않으면 ADR-0011 반증 3도 닫힌다. 약점: 무대 4계통 중 하나가 화면에 한 번도 안 나온다(`docs/company/tools.md:50` "넷은 … 최소 개수").
- **grok**: ERP는 지급 처리 커밋 뒤 outbox가 모의 전표 한 장(`ledger_krw` 비움), 한성워크는 근태 행을 outbox로 씀. 커밋 뒤라 반증 3은 안 열림.
- **codex**: ERP는 전표·지급 기록과 환율표를, 한성워크는 조직·일정·앱 결재 결과 투영과 버전 있는 회사 달력을 준다(환율표·달력은 **합성 참조 자료**, codex §4.1). 지연은 주입 시계·`available_at`, `pending`/`invalid`/`absent` 구분.
- 이 선택이 **계정 분류**(PRD:174 이월)를 끌고 온다 — ERP가 없으면 claude처럼 "하지 않음", 있으면 grok 7종 / codex 8구획.

### D6. 카드 내역이 들어오는 형태

- **grok·codex**: as-is 그대로 월 단위 파일을 사람이 반입. 명세 도착 전 상신이 흔하고, 도착 뒤 새 짝 보류는 A10으로 승인을 멈춘다.
- **claude**: **이용 내역 매일 자동 + 청구 명세 월 1회 사람.** 이유: 정산 기안 기한이 복귀일부터 10영업일(`PRC-10-1`, 코디네이터 확인)이라 월 명세만 받으면 교차 확인(H3)이 사라지고 대사가 상신 뒤로 밀린다.
- 사실 확인(코디네이터, 2026-09-22): 카드사 기업 웹은 기간을 지정한 승인·이용 내역 조회와 엑셀 다운로드를 제공한다(아래 출처). "매일 자동으로 가져온다"는 기술 가능성이 아니라 **가상 회사 운영의 선택**이고, as-is(`docs/company/tools.md:16` "월 단위 수동 다운로드")에서 한 걸음 벗어난다.

### D7. 규정 개정권자

- grok: 대표이사 단독 게시. codex: 대표이사 **승인** + 경영지원본부장 **게시**(권한 분리). claude: 대표이사, 앱 안에 게시 기능 없음(저장소 새 판 + 부팅 적재 = 판 적재 이벤트, 책임자 대표이사).
- 셋 다 본부장 단독을 배제한 이유가 같다 — 고액 전결권자가 자기 검사(`APV-9-3`)를 정하게 된다(`docs/company/org.md:26-27`의 감사 분리 논리).
- 규정 3종 어디에도 개정권 조항이 없다(claude §7.2, grep 0건) → 결정 뒤 규정 문언 반영이 필요.

### D8. EXIF가 없는 이미지

- grok: `orientation_unverified` 남기고 무회전으로 진행. Claude 호출로 방향을 묻는 것은 **기각**(단계 표와 어긋나고 실패가 섞임).
- claude: EXIF만 쓰고 `방향 미보정` 기록, 회전된 사진은 `_status`로 드러나 재촬영·수기로 간다(정확성 유지, R1만 증가). 대체 후보로 **① 분류 스키마에 회전각 칸**(#11이 정확도 측정).
- codex: 자산 미검증이면 `ORIENTATION_ASSET_UNVERIFIED` 운영 차단 — "EXIF만으로 완료라고 표시하지 않는다". 추출 자체를 막는지는 문언상 모호.

## 5. 사용자 결정 (6)

되돌리기 어렵고(감사 스키마·ADR에 박힘) 가치 판단이 필요한 것만 물었다. 코디네이터 추천과 다르게 고른 것이 둘이다(U1·U6).

| # | 자리 | 선택 | 누구의 안 | 코디네이터 추천 |
| --- | --- | --- | --- | --- |
| U1 | 비결재 조작의 책임자 규칙 (D3) | **업무 운영 담당자 배정** — 팀장이 재무·인사·총무 운영 담당을 세계마다 실명으로 사전 배정하고 배정은 버전으로 관리. 사람이 한 입력은 그 사람. 보류 답변 작성의 책임자는 질문한 승인자 | codex §6 | 검토 의무자 규칙(claude) — **다름** |
| U2 | 보류 답변의 형태 (D4) | **슬롯 + 방향 주장 문장은 서버 템플릿** — 숫자·인용은 코드가 계산 기록·원문에서 채우고, 금액·기한·결재선·판정 방향을 말하는 문장은 템플릿으로만. 모델은 이음말만 | codex §2.2 + claude §3.3 | 같음 |
| U3 | 모의 커넥터와 ERP (D5) | **3개·모두 읽기 전용, ERP 없음** — 카드사 웹, 여행사 메일함, 한성워크 조직 정보. 외부로 쓰는 커넥터 없음 → ADR-0011 반증 3도 닫힘. **계정 분류는 이 MVP에서 하지 않는다**(PRD:174 이월 항목을 닫음) | claude §4.4, §7.3 | 같음 |
| U4 | 카드 내역 도착 형태 (D6) | **이용 내역 매일 자동 + 청구 명세 월 1회 사람** — as-is 문서(`docs/company/tools.md:16`)는 그대로 두고, 매일 가져오기는 to-be 개선으로 서술 | claude §4.4.1 | 같음 |
| U5 | 규정 개정권자 (D7) | **대표이사, 앱 안에 게시 기능 없음** — 새 판은 저장소의 규정 문서 개정 + 부팅 적재, 세계마다 "판 적재" 이벤트의 책임자는 대표이사 | grok §8.2 + claude §7.2 | 같음 |
| U6 | 에이전트의 기안 초안 (D2) | **초안은 에이전트, 상신은 사람** — 판독기가 기안자가 준 서술·첨부를 폼 후보로 구조화하고, 기안자가 고쳐 상신. 초안은 artifact이지 판정 입력이 아니며, 책임자는 작성을 요청한 기안자 | codex §5.3, §6.2 | 쓰지 않음(grok·claude) — **다름** |

**결정이 끌고 오는 것.**

- **U6 → 모델 호출 지점이 4곳에서 5곳이 된다.** ADR-0011:16-17이 센 호출 지점(분류·추출·메일 판독·보류 답변)에 기안 초안이 더해지므로, ADR을 쓸 때 ADR-0011 개정 또는 보완이 필요하다. claude가 적은 반증 조건 "다섯 번째 호출 지점이 요구된다"(claude §2.5-2)가 이 결정으로 성립한다. 에이전트 수는 그대로 2다 — 기안 초안은 판독기의 작업이다(codex §2.1). 부작용 도구 "아니오"(A1)는 유지된다. 상신은 사람의 명령이고, 에이전트는 초안을 돌려줄 뿐이다.
- **U1 × U3 × U4.** codex의 배정표(codex §6.2)에서 ERP·환율 참조 동기화 행은 U3으로 빠진다. 카드 이용 내역의 매일 가져오기(U4)는 시스템 작업이고, 그 책임자는 배정된 카드 수집 담당이다. claude가 제안한 `responsible_rule` 칸은 채택하지 않는다. 그 역할(책임의 근거를 감사 조회에서 가르기)은 codex의 `assignment_id`·버전이 맡는다(codex §6.3).
- **U1의 남은 세부.** codex 표의 "결재선·기한 계산 → 인사 절차 운영 담당" 중 기한은 저장하지 않는 계산값이라 감사 이벤트가 없다는 claude의 지적(claude §6.4)이 있다. 기한 계산을 책임자 표에 둘지는 ARCHITECTURE 작성 때 정한다.
- **U5 → 규정 문언.** 규정 3종에 개정권 조항이 없다(claude §7.2). 문언 반영은 #20 방식(규정 + 기계 판독 블록 + `CONTEXT.md` 동시 수정)의 후속이다.

## 6. 코디네이터 결정 (9) — 사용자에게 알림, 이의 없음

- **C1** 에이전트 수는 2(판독기·답변기)로 센다. 분류·추출은 별도 호출·별도 스키마를 유지해, grok이 댄 실패 격리 이유를 스키마 경계로 보존한다(D1).
- **C2** 보류 답변 도구는 계산 기록(입력 revision 포함)과 조항 원문을 읽는 3개로 둔다 — ADR-0011:27 문언 안이다. grok의 `read_field`·`read_card_snapshot`은 문언 밖이라 넣지 않는다.
- **C3** 상신 뒤 새 짝 보류(A10)와 재무합의자에게 배정된 짝 확인(값 모순)은 현재 단계의 승인·동의만 막는다. "열린 의무"(claude §5.2)라는 이름을 도메인 용어로 올릴지는 #22가 정한다.
- **C4** EXIF가 없으면 EXIF만 쓰고 `방향 미보정`을 기록한 채 진행한다. 방향 자산이 준비됐다고 표시하지 않는다. 분류 스키마의 회전각 칸(claude §7.4)은 #11 측정 후보이고, grok의 기각 사유(grok §8.4)를 함께 넘긴다.
- **C5** 결재권자가 여럿일 때의 `decided_by`는 #20으로 넘긴다. grok의 교착 지적(grok §10.2)을 붙인다.
- **C6** 카드 파일의 깨진 줄은 격리한다. 파일 전체를 거부하지 않는다.
- **C7** 공개 데모의 보류 질문은 미리 고른 목록만 쓴다(ADR-0017:39).
- **C8** 명령은 기대 revision을 조건으로 걸고, 어긋나면 `STALE_REVISION`으로 거부한다. SlipScan의 조용한 건너뛰기(claude §3.3)는 받지 않는다.
- **C9** 기안 폼 입력의 출처는 `사람 수기 확정` + `entry_mode`로 둔다. ADR-0012 반증 2를 열지 않기 위해서다. 용어 정의(`CONTEXT.md:315`)의 보정은 #22가 한다. U6의 에이전트 초안을 기안자가 채택한 값도 여기에 든다(codex §6.4 "사람이 채택해 입력으로 만들 때만 별도 확인 명령과 필드 provenance").
