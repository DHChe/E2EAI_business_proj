# 상태 어휘와 되돌아가는 전이 — codex 독립 제안 (#17)

작성·확인: 2026-09-22. 상태: **검토용 제안, 확정 규범이나 구현이 아님**. 적용 기준은 이 worktree의 ADR 0001–0022이며 다른 #17 레인의 문서는 읽지 않았다.

**추천은 결재와 증빙 처리의 축을 분리하고, 세 구간의 반려를 모두 기안자의 문서 전체 재기안으로 닫으며, 항목별 부분 승인은 채택하지 않는 것이다.** 초과분 불인정·안분은 항목별 인정금액의 결정으로 지원하되, 일부 항목만 결재 효력을 먼저 얻거나 지급되는 경로는 두지 않는다. 반려는 출장 취소·자비 부담·급여 공제를 자동 확정하지 않는다.

이하 **추천·초안·표·그림·예시와 새 식별자는 모두 [설계 가정]**이다. 현재 사실은 붙인 파일:줄 또는 이슈 URL의 확인 내용이고, 가정은 그 사실로부터 반드시 따라오는 결론이 아니다. 실제 법률 효력·임금 공제의 적법성은 판단하지 않는다. 규정 문언 초안은 가상 회사의 정책 선택이며, 법률 검토를 대신하지 않는다.

## 1. 근거와 해석의 경계

- 작업 명세는 [#17 본문·댓글](https://github.com/DHChe/E2EAI_business_proj/issues/17)이다(확인 2026-09-22, `gh issue view 17 --comments` 및 본문 JSON). 구간별 반려에서 상태 어휘 전체로 범위가 넓어졌고, 부분 반려와 항목별 부분 승인을 구별하라는 요구를 포함한다.
- 보류 답변 뒤 **같은 승인자**의 대기 복귀는 이미 결정됐다. 미정인 것은 무응답·반려 이후·재심 복귀·타임아웃이다(`docs/adr/0003-approver-actions-three.md:25-26`, `docs/adr/0011-messages-api-direct-waits-are-document-state.md:35-37`).
- 결재선은 기안 때 고정되고, 입력 수정으로 결재선이 달라지면 재기안이다. 정산 하한은 사전승인 기안 시 계산한 전결권자의 단계이며, 완료 전 출발도 포함한다(`docs/company/approval-matrix.md:150`, `:254-256`).
- 재무합의는 정산에만 있고 기안자와 첫 결재자 사이에 선다. 판 1은 순차·차단·항상 반려 허용이다(`docs/company/approval-matrix.md:205-235`, `docs/adr/0014-apv-9-3-exposed-declaratively.md:27-33`). 협조자를 이 역할로 대신하지 않는다. 저장소가 확보한 협조 문법과 재무합의의 비대칭을 따른다는 뜻이며, 현행 법령을 독립 재검증했다는 뜻은 아니다(`docs/research/korean-approval-grammar.md:74`, `:276`, `CONTEXT.md:24`, `:68`).
- `gate=on`과 상신 뒤 짝 보류는 현재 단계의 승인·동의만 막는다. 반려·보류를 막는 근거가 아니다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:46`, `docs/ARCHITECTURE.md:313-315`).
- 상태·감사·후속 작업은 한 트랜잭션이며, 명령은 기대 revision을 갖고 어긋나면 `STALE_REVISION`이다. 결재 행위자는 현재 담당자인 사람, 책임자는 항상 사람이다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:23-37`, `docs/research/agent-architecture-comparison.md:198`, `CONTEXT.md:331`).
- 반려 사례 조사에서 사유 없는 실행 종료, 사유와 거절자 전파, 상환 요구라는 서로 다른 패턴이 발견됐다. **본 안은 사유·행위자·다음 담당자만 차용**하며 상환을 자동 결론으로 가져오지 않는다(`docs/research/competitor-screens.md:99-113`).
- 약 93%는 이 회사의 승인률이 아니다. 저장소도 Claude Code 관측과 이 파이프라인을 구별한다. 이 문서는 그 숫자를 효과 추정치로 사용하지 않는다(`docs/adr/0010-human-routing-bounded-by-structure-measured-by-ratio.md:56-57`).
- 이웃의 미정 사항은 [#21](https://github.com/DHChe/E2EAI_business_proj/issues/21), [#20](https://github.com/DHChe/E2EAI_business_proj/issues/20), [#22](https://github.com/DHChe/E2EAI_business_proj/issues/22), [#25](https://github.com/DHChe/E2EAI_business_proj/issues/25), [#8 결과](https://github.com/DHChe/E2EAI_business_proj/issues/8#issuecomment-5769586450)를 읽어 확인했다(모두 2026-09-22). 이 문서가 그 티켓의 답을 대체하지 않는다.

## 2. 물음 0 — 축은 나누고, 전이 권한은 하나로 모은다

**추천: 문서 결재 축과 증빙 처리 축을 분리한다.** 증빙 축 안에서도 추출 필드의 확정 여부와 대사 관계의 결과를 독립 속성으로 둔다. 문서 한 건에 증빙 여러 장이 있고, 결재대기 중에도 한 장의 짝 보류가 새로 생길 수 있다. 한 enum으로 합치면 문서가 `결재대기`인지 `짝 보류`인지 둘 중 하나를 잃는다. 이는 상신 뒤 짝 보류가 문서 상태를 바꾸지 않는 기존 결정과 맞지 않는다(`docs/ARCHITECTURE.md:315`). 실행 `job`·화면 표시 층은 기존대로 따로 둔다(`docs/ARCHITECTURE.md:309`).

**되돌림은 한 군데에서 결정한다.** 증빙 작업은 결재를 되돌리는 명령을 만들지 않는다. 명령 처리기가 변경 사실을 수락하면서 다음 셋을 원자적으로 정한다: (a) 새 값·대사 revision, (b) 다시 계산할 범위와 승인 유효성, (c) 문서의 재개 단계. 작업 완료 콜백에 `resumeApproval`을 또 두지 않는다. 재검산이 비동기면 처리기는 차단 사유와 job을 함께 기록하고 결과 수락 때 그 사유만 닫는다. 상신·수정·재심·짝 확인이 **같은 재개 판정표**를 사용한다(§5).

[설계 가정] 아래는 설명용 계약이며 구현 스키마가 아니다.

```text
문서: document_id + attempt_id + revision + 결재상태 + stage_id
      + 고정 결재선 + 정책 판 + 입력 스냅샷 + 재심 복귀점(있으면)
증빙: evidence_id + revision + 추출 확정 여부 + 대사 작업 상태/결과
결재기록: attempt_id + stage_id + 검토 스냅샷 + actor + decision
변경 수락: 확정값 저장 → 필요한 검산/대사/정책 계산 → 스냅샷 비교
           → 같은 단계 유지 | 동일 결재선 처음부터 재검토 | 재기안 필요
공통 명령: expected_revision + command_id + 세션 actor + 책임 배정
```

`반려`는 현재 결재 시도의 종료이고 `기안`은 후속 시도의 상태다. 화면은 원문서 번호의 연결을 유지하되 과거 반려 이력을 새 기안으로 덮지 않는다. `완료`도 결재 완료와 출장 전체 완료를 구분하여 표시한다. 기존 용어집에서 정산 완료 뒤 지급 처리가 따로 있고 출장 완료는 그 뒤다(`CONTEXT.md:114`, `:128`).

**기각:** 하나의 선형 상태 기계(증빙 수만큼 조합 증가), 독립된 두 워크플로의 상호 재개 호출(늦은 추출 결과가 새 결재를 되돌릴 수 있음), `job.failed`를 문서 반려로 번역하는 안(실행 실패와 사람 판단을 혼동).

**반증 조건:** 동일 명령을 재전송하거나 구 revision 작업을 늦게 도착시켰을 때 재개 단계가 둘 생기거나, 증빙 revision과 다른 입력에 대해 결재가 수락되는 사례가 하나라도 나오면 이 단일 처리기 계약은 실패다. #11은 정합성 검사로 이를 검증해야 한다.

## 3. 물음 1 — 구간별 반려는 문서 전체 재기안

| 구간 | 추천 결과와 다음 담당자 | 재상신 시작점·결재선 | 기존 승인 효력 | 기각한 대안·이유 | 추천이 틀리는 조건 |
| --- | --- | --- | --- | --- | --- |
| 사전승인 반려 | `반려`; 기안자에게 사유와 수정 대상 전달. 기안자가 새 시도를 열어 `기안` | 사람의 재상신 때 당시 조직 정보와 수정 입력으로 다시 계산; 첫 결재권자부터 | 반려된 시도의 중간 승인은 이력만 남고 새 시도에 승계하지 않음 | 자동 출장 취소: 문서 반려가 예약·사건 취소와 동일하다는 규정 없음. 같은 단계만 재개: 문서 전체를 다시 기안한다는 의미가 흐려짐 | 단순 서류 보완 반려가 반복돼 모든 결재 재수행이 주된 추가 접촉이 되면 보류 사용 규칙·반려 단위를 재검토 |

| 재무합의 반려 | `반려`; 기안자가 증빙·내역을 수정. 총무 자료가 원인이면 자료 요청 상대는 총무지만 문서 소유자는 기안자 | 첫 재무합의부터; 반려한 두 번째 재무합의자나 직전 결재권자로 바로 보내지 않음 | 앞 재무합의자의 동의도 새 시도에 승계하지 않음 | 총무로 문서 자동 이관: 기안자와 증빙 제공자를 혼동. 반려권 제한: APV-9-3과 충돌 | 재무 담당 두 사람이 같은 불변 증빙을 계속 재확인해 R3·R4를 넘긴다면 변경 범위 한정 승계안을 다시 비교 |

세 구간의 근거는 건 전체 반려와 재기안(`CONTEXT.md:79-82`), 고정 결재선과 재기안(`docs/company/approval-matrix.md:254-256`), 재무합의의 위치(`:205`)다. **매번 재계산**하되 규정 판을 새 판으로 갈아끼우지는 않는다. 한 출장의 적용 판은 `PRC-2-2`를 따른다(`docs/company/travel-procedure.md:33-43`). 재기안 때문에 사전승인 기준일을 새로 잡아 유리한 판을 고르는 동작은 허용하지 않는 것을 추천한다(규정 보완 필요, §11).

[설계 가정] 반려 사유는 필수이고, **무엇을 고치면 재기안 가능한지** 또는 **동일 내용으로는 승인하지 않는 이유**를 포함한다. 재무합의는 gate가 열려 있어도 반려할 수 있지만, 권한·현재 단계·revision·사유 검증은 생략하지 않는다. `항상`은 누구나 어느 상태에서나 반려한다는 뜻이 아니다. 협조자·admin·에이전트에 반려 명령 권한을 주지 않는다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:35-37`, `:46`).

사전승인 반려 뒤 기안자가 더 진행하지 않으면 `반려`를 종결 이력으로 남긴다. 새 `취소 승인` 단계나 철회 승인자는 만들지 않는다. 후속 시도를 만들 의무·응답 기한은 규정 초안이 필요하다. 출장 미실시 표시는 사건의 사실 기록일 뿐, 이미 발생한 비용을 없애지 않는다. 현재 예약은 사전승인 완료 뒤 착수하고, 완료 뒤 정산 전 변경은 재기안 없이 정산으로 넘긴다(`docs/company/travel-procedure.md:89-91`, `:156-158`). 따라서 **이미 완료된 사전승인을 정상 반려 버튼으로 소급 반려하지 않는다**. 그 경우는 재심이다.

예약이 이미 잡힌 반려 사례의 위약금 분담, 정산 반려의 청구 포기·개인 부담·급여 공제는 §11의 규정 초안으로만 넘긴다. `TRV-12-4`가 초과분 본인 부담을 정한 경우와 문서 반려를 동일시하지 않는다(`docs/company/travel-policy.md:251`).

## 4. 물음 2 — 두 시계, 상태 유지, 권한 없는 에스컬레이션

**추천: 무응답 보류와 기한 경과는 원 상태를 유지하고, 기한 경과를 한 번 기록해 담당자·기안자·배정된 절차 운영 담당의 지연 목록에 올린다. 자동 승인·반려·취소는 없다.** 에스컬레이션은 책임자의 주의를 요청하는 기록이며 결재선을 올리거나 대결 권한을 주지 않는다. 자동 알림 채널·반복 주기는 여기서 정하지 않는다.

- 결재자 시계: 자기 차례 도달일부터 `PRC-14-1`의 3영업일 안에 승인·동의·반려·보류 중 하나를 하면 해당 처리 의무를 이행한다. 보류 답변으로 돌아오면 그날이 새 도달일이다(`docs/company/travel-procedure.md:269-283`).
- 문서 시계: 보류했다고 사전승인 완료 등 다른 기한을 닫거나 늦추지 않는다. 미이행 기한은 계속 비교하며 경과 사실을 보인다. 현재 걸린 의무의 정확한 정의·출발일 기한 종료 시각은 #20의 결정을 입력으로 받는다(`docs/company/travel-procedure.md:68-80`, `:129`, [#20](https://github.com/DHChe/E2EAI_business_proj/issues/20), 확인 2026-09-22).
- 답변 없이 보류가 지속되면 **보류 그대로**다. 기존 결재자 시계를 재사용해 무응답 기한을 발명하지 않는다. 문서의 다른 열린 기한이 지나면 지연 목록에 올린다. 그 기한도 없으면 현재로서는 시간 경과만 보이고, 무응답 자체의 별도 응답 기한은 #20의 새 조항 없이는 발동하지 않는다.
- 답변이 늦게 와도 같은 승인자 대기로 복귀한다. 경과 이력은 남고 새 도달일만 추가된다. 여러 번 보류해도 과거 지연을 지우지 않는다.
- 타이머는 계산한 기한을 기준으로 명령을 제안한다. 수락 직전에 현재 revision과 주입 시계·달력·규정 판으로 다시 계산한다. 이미 답변·결재로 의무가 닫혔으면 지연 전이를 만들지 않는다. 조회는 쓰기를 촉발하지 않는다. 스케줄러가 제출하는 별도 시스템 명령이고, `(의무 식별자, 도달 회차, 경과 종류)`당 멱등 기록 한 개다.
- 새 시스템 조작의 책임자는 팀장이 배정한 **인사 절차 운영 담당**으로 두는 것을 추천한다. 미배정이면 실행하지 않고 `RESPONSIBLE_UNASSIGNED`; 지연 표시 자체는 계산해서 보인다. 이는 운영 배정이 결재자를 교체하지 않는 원칙을 유지한다(`docs/adr/0019-non-approval-owner-is-assigned-operations-person.md` 결정 6·7·11; `docs/ARCHITECTURE.md:261`, `:305`).

기존 규정은 경과 표시와 불이익 미정만 정한다(`docs/company/travel-procedure.md:285-291`). **자동 경과 기록·운영 목록은 현재 규정의 사실이 아니라 추가 제안**이며 §13에 현행 문서와의 차이를 적었다. #20이 담당·시간 조건을 확정하기 전에는 새 타임아웃 명령을 실행하지 않는다.

**기각:** 무응답을 동의로 간주(판단 없는 효력 발생), 자동 취소(지출·지급 의무가 지워질 수 있음), 결재권자 상향(고정 결재선 침해), 3영업일을 임의 응답 기한으로 재활용(처리 기한과 답변 기한 혼동).

**반증 조건:** 지연 목록만으로 장기 미처리 건의 다음 담당자를 특정할 수 없거나, 반복 보류로 지연 표시를 회피할 수 있으면 이 안은 틀렸다. 반대로 운영 담당 확인 요청이 R3·R4를 넘기면 에스컬레이션의 반복·집계 방식을 줄여야 한다. 자동 취소로 해결했다고 간주하지 않는다.

## 5. 물음 3·4·5가 공유하는 재개 판정표

**추천: 값이 그대로면 같은 단계, 판단 입력이 달라지면 동일 결재선의 처음, 결재선이 달라지는 수정은 재기안이다.** 영향받은 일부 승인만 골라 재사용하는 최적화는 MVP에서 하지 않는다. 여기서 판단 입력은 금액뿐 아니라 증빙·짝·법정 판정·정책 결과·재량 판단·목적·사유까지 승인 카드가 판단 근거로 제시한 스냅샷을 말한다. 단순 표시 정렬·운영 메타데이터·질문의 답변 텍스트 자체는 해당하지 않는다. S15가 각 승인자에게 판정 기록 전체를 요구하기 때문이다(`docs/PRD.md:165`).

| 변경 상황 | 검산·대사·정책 계산 | 재개 지점 | 과거 승인 |
| --- | --- | --- | --- |
| 값 수정 없이 보류 답변만 추가 | 판정 입력 생성 금지; 기존 계산 참조 | 같은 승인자·같은 대기. 답변 실패는 성공 답변으로 간주하지 않음 | 유지 |
| 수기 확정으로 추출값 수정 | 동일 검산·대사 다시 실행, 이어 법정 판정·정책 계산. 원본 불변이면 모델 재추출 안 함 | 기안 전이면 기안; 상신 뒤면 아래 두 행 적용 | 새 입력 검증까지 승인·동의 차단 |

| 재량 판단 결과가 결재선 입력/단계를 바꿈 | 계산 결과와 차이를 기록 | **#21 결정 대기**. 판단 저장은 가능하나 그 결과에 의존하는 진행은 거절 | 기존 선 자동 수정·상향·하향·최악값 선정을 하지 않음 |
| 짝 보류 해소 뒤 검토 스냅샷이 기존과 같음 | 최신 대사 결과와 근거가 같은지 검증 | 멈췄던 현재 단계; 보류 중이었다면 보류 유지 | 유지 |

재량 판단의 사실 입력이 그대로면 이미 기록한 재량 결론을 다시 묻지 않는다. 그 결론 때문에 검토 스냅샷이 바뀌어도 새 revision에 계산 결과와 결론 참조를 함께 고정하여, 앞 단계로 돌아갈 때 같은 관문을 반복해서 여는 순환을 막는다. 판단 근거 사실이 달라진 경우에만 해당 판단을 미해결로 다시 열고, 판단자가 불명확하면 #20 경계에서 멈춘다.

**판별 순서가 중요하다.** 새 짝 보류 발견 자체로 과거 승인을 취소하지 않는다. 발견 시에는 현재 단계에서 차단 사유만 추가한다(A10·C3). 짝이 닫히고 검토 스냅샷이 확정돼야 위 표로 돌아갈 위치를 정한다. 그 사이 반려·보류는 현재 담당자가 할 수 있다. 완료와 동시에 새 짝 보류가 발생하면 기대 revision으로 선행 사건 하나만 수락하고, 완료가 먼저 확정됐다면 사후 변경은 재심으로만 받는다. 에이전트나 카드 수집 job이 완료를 자동 재개하지 않는다.

### 5.1 물음 3 — 재심은 과거 효력을 삭제하지 않는다

**추천: 정산은 기존대로 재무합의대기로 보내되, 복귀점과 원 승인·지급 이력을 보존한다.** 이미 지급 처리된 기록을 되돌리지 않고 차액을 조정 대상으로 남긴다. 지급 전이라면 재심이 닫힐 때까지 지급 처리 명령을 막는 것을 추천한다. 이는 “과거 승인이 없던 일이 된다”는 뜻이 아니라 **향후 실행을 일시 정지**하는 설계다. 법률상 소급 무효를 선언하지 않는다.

1. 내부감사가 사유·대상 필드/근거·대상 revision을 지정해 재심을 연다. 값 수정·판단은 하지 않는다. 진행 중이면 대기/보류 상태·단계·질문을 복귀점으로 저장하고, 완료 건이면 완료와 지급 처리 여부를 별도로 저장한다(`docs/adr/0002-admin-read-only-audit-axis.md:25-30`, `:63-66`).
2. 정산은 그 시도의 **첫 유효 재무합의자**부터 재심한다. 재무합의자가 둘이면 순차로 쟁점을 검토한다. `APV-9-4` 때문에 재무합의자가 0명인 경우는 임의 대체하지 않고 `UNDEFINED_BY_17`로 계속 거절한다. 이 예외의 담당을 #20이 정해야 한다(`docs/company/approval-matrix.md:233`, `docs/ARCHITECTURE.md:346`).
3. **정정 없음**: 쟁점이 재무 검토 범위뿐이면 재무합의자들이 기존 `동의`로 쟁점을 닫은 뒤 진행 중 문서는 복귀점으로, 완료 문서는 완료로 돌아간다. 업무상 필요·정산 차이 등 결재권자 범위의 쟁점이 포함되면 재무합의 뒤 원 결재선도 순서대로 재심하며 마지막 재심 승인 뒤에 복귀한다. 재무합의 동의만으로 다른 역할의 쟁점을 닫지 않는다(APV-10-1~3, `docs/company/approval-matrix.md:239-250`). 재무 범위에만 속한 무변경 완료 건에 전결권자 재승인을 붙이지 않으며, 모든 재심에 admin 해제 확인을 추가하지 않는다. 복귀점이 보류면 보류와 질문을 살리고, 재심 동의를 답변으로 간주하지 않는다.
4. **정정 있음**: 기안자/기존 권한의 수기 확정자가 고치고 재검산·대사를 수행한다. 결재선이 같으면 첫 재무합의부터 동일 선을 재검토하고, 다르면 재기안한다. 재무합의자는 자신이 원래 판단하는 것만 본다(`docs/company/approval-matrix.md:239-250`). 과거 지급 완료는 유지하고, 새 승인금액과 기지급액 차이를 계산해 새 지급/반환 처리 대상으로 연결한다. 원 지급을 두 번째로 실행할 수 없다.
5. 재심에서 `반려`하면 재심 시도가 반려되고 기안자에게 돌아간다. 이미 지급한 돈이 자동 회수되거나 과거 승인이 소급 삭제되지는 않는다. `보류`는 재심 단계 안에서 답변을 기다린다. 같은 미종결 재심에 추가 플래그가 오면 쟁점을 병합하여 별도 병렬 결재선을 만들지 않는다.
6. **사전승인**: 진행 중에는 원 현재 결재권자, 완료 건은 원 전결권자의 `결재대기(재심)`로 보내는 것을 추천한다. 재무합의 상태를 새로 만들지 않는다. 정정 없으면 기존 복귀점/완료, 정정 있으면 동일 선 재검토/재기안 규칙을 따른다. 다만 **완료 후 정산 전 사전승인 수정은 새 재기안으로 처리하지 않고 `PRC-9`대로 정산 판단에 연결**한다. 이때 사전승인 재심은 원 결정의 타당성을 검토해 쟁점·결론만 남기고, 예약·일정 변경 승인 절차로 쓰지 않는다. 원 결정의 효력을 실제로 취소해야 한다면 현행 규정으로는 닫지 못하므로 규정 개정까지 미정으로 표시한다.

마지막 항은 **ADR-0002:29의 대상 상태를 문서유형별로 좁히는 ADR 개정 제안**이다. 현재 조항의 사전승인 제외 및 `PRC-9-2`와의 긴장은 §13에서 드러낸다. 개정 수락 전 사전승인 플래그는 계속 거절한다.

**기각:** 완료·기지급의 일괄 롤백(실제 지급 사실을 지움), 모든 무변경 재심의 전체 재승인(새 근거도 없는데 접촉만 증가), admin의 재심 종료 승인(감사자가 결재자 역할을 얻음), 사전승인에 재무합의 삽입(APV-9-1과 충돌).

**반증 조건:** 무변경 재심에서 업무상 필요 쟁점을 재무합의만으로 닫는 사례가 나오면 재심 범위의 담당 분리가 실패한 것이다. 범위가 불명확한 쟁점을 임의로 재무 범위라고 분류해서는 안 된다. 그 경우는 원 결재선까지 재심하는 보수적 경로를 추천한다. 지급 정지 때문에 규정상 지급 의무를 부당하게 연장하는 결과가 확인되면 정지 방식부터 바꿔야 한다. 사전승인 재심이 실제로 세 번째 판단 봉우리가 되면 해당 확장안을 철회하고 규정 개정 문제로 되돌린다.

### 5.2 물음 4 — 세 전이를 서로 다른 의미로 처리한다

**값만 수정 후 재개: 채택.** 원본이 같은데 금액·날짜를 사람이 확정했다면 재추출 없이 검산·대사를 다시 돈다. 재촬영으로 원본이 바뀔 때만 새 증빙의 추출 경로를 연다. 기존 수기 확정 요구를 그대로 따른다(`CONTEXT.md:315-318`, `docs/design/receipt-pipeline.md:279-282`). 변경 저장과 “재개하시겠습니까” 확인을 분리하지 않는다. 사람은 바꾼 값과 사유를 제출하고 코드가 §5의 재개점을 정한다.

**항목별 부분 승인: 미채택.** 여기서 거절하는 것은 한 문서 안에서 A항목 승인 효력이 발생하고 B항목은 보류되며 A만 지급 가능한 독립 결재 단위다. #19의 “일부는 통과, 일부는 보류”를 문서 승인으로 제공하지 않는다. 수신부서별 부분 반려와 개념상 다르다는 점은 인정한다. 기각 이유는 액션 셋의 수가 아니라 **현재 결재선·정산 하한·지급 기한이 문서 단위인데 독립 항목 완료를 넣으면 효력 발생일과 반환 상계를 여러 벌 정의해야 하기 때문**이다(`docs/adr/0003-approver-actions-three.md:58-60`, `docs/company/approval-matrix.md:150`, `docs/company/travel-procedure.md:295-307`).

재량 “인정하지 않음”과는 **결과 금액이 갈라진다는 점에서 같고, 미결 항목을 남긴다는 점에서 다르다**. `TRV-12-4`는 초과분을 본인 부담으로 닫고, `TRV-13-4`는 왕복교통비 안분으로 결론을 낸다. 둘 다 항목이 미정으로 남지 않는다(`docs/company/travel-policy.md:251`, `:283-304`). 따라서 모든 항목의 판단이 끝난 문서에서 청구액·인정액·본인 부담액을 나란히 보이고, **문서 전체 승인**을 받는다. 이는 “전액 지급 승인”이 아니다. 재량 판단 기록을 별도 승인 버튼으로 세지 않고 해당 담당자의 승인 전 입력으로 둔다. #21의 선 변경, #20의 판단자 미정은 그 지점에서 막는다.

[설계 가정] 예: 두 항목 100·50 중 둘째 초과분 20을 불인정했다면 청구 150, 인정 130, 본인 부담 20으로 **전체 결론이 난 문서**를 승인할 수 있다. 둘째의 업무 관련성이 아직 미정이라면 문서 전체를 보류한다. 이 예는 실제 정책 계산 사례가 아니다. `PRC-13-5`에서 근거가 없으면 반려하라는 규정을 항목 0원 처리로 우회하지 않는다(`docs/company/travel-procedure.md:241-264`).

**타임아웃 뒤 에스컬레이션: 상태 유지형으로 채택.** §4의 운영 목록·감사 사건만 더하고 결재 권한을 옮기지 않는다.

**기각:** 값을 고칠 때마다 OCR 재시도(확정값을 새 추출값으로 덮을 위험), 항목 승인별 문서 분할(한 출장 정산의 상계·결재선을 다시 정의해야 함), 모든 불인정을 반려로 번역(명시적으로 인정금액을 줄이는 규정의 표현력을 잃음).

**반증 조건:** 값 수정만 했는데 새로운 추출 호출이나 확인 세션이 열리면 재개 설계가 실패다. 일부 미결 항목 때문에 정상 항목의 지급을 묶는 비용을 회사가 수용하지 않겠다고 결정하면 부분 승인 미채택은 틀렸으며, 항목별 지급 기한·상계·결재선 규정부터 설계해야 한다. 기한 경과에도 누구의 처리 대상인지 표시되지 않으면 에스컬레이션 채택은 명목뿐이다.

### 5.3 물음 5 — 새 짝 보류의 해소는 현재 단계에서 판정한다

**추천: 발견 때 현재 단계 유지, 해소 때 §5의 단일 판정표 적용.** 기존 짝과 판단 근거가 동일하게 복원되면 현재 단계가 재개된다. 다른 카드 줄·값·법정 판정·정책 결과가 생겼다면 과거 승인 효력을 그 새 입력에 승계하지 않고 동일 선 처음부터 재검토한다. 재무합의자의 값 모순 확인과 기안자의 경쟁 후보 확인이라는 담당 분리는 유지한다(`CONTEXT.md:310`, `docs/ARCHITECTURE.md:277`, `:315`).

대사 작업 상태의 `짝 보류`·`후보 복수`는 영속화하되 `ReconciliationOutcome`의 최종 결과에 새 완료 값을 억지로 끼우지 않는다. 작업 중간 상태와 완료 결과를 감싸는 구분이 필요하다. 현재 내부 상태는 영속화하기로 했지만 결과 타입에는 둘이 없다(`docs/adr/0013-postgres-object-storage-isolated-by-world-id.md:38`, `:87`, `docs/design/receipt-pipeline.md:835-839`).

**기각:** 언제나 재무합의 처음으로 돌아감(무변경 확인도 승인 반복), 언제나 현재 단계 유지(다른 거래를 검토한 옛 승인 승계), 짝 보류 자체를 문서 보류로 바꿈(A10·C3 위반).

**반증 조건:** 해소 후 카드 줄이 달라졌는데 과거 승인이 유효하다고 표시되거나, 동일 근거 복원인데 새 재기안이 요구되는 사례가 생기면 비교 경계가 틀렸다. 위 두 종류를 #11에서 각각 고정 사례로 둔다.

## 6. 상태 표 — 상태, 결과, 표시를 혼동하지 않는 어휘

## 9. 물음 6 — 사람 확인 지점의 증감

**추천: 정상 경로에 새 확인 지점 0개, 기존 지점 삭제 0개.** 반려 뒤 재상신·정정 뒤 재검토는 기존 결재 지점의 **재방문**이며, 재심에는 예외적으로 기존 사람이 다시 판단한다. 이를 “0개 추가”라는 말로 숨기지 않고 아래처럼 접촉 횟수를 별도 센다. 기준선은 `docs/ARCHITECTURE.md:366-380`의 13개 자리 유형이며, 역할이 다른 두 짝 확인 행을 각각 센 것이다. 운영 배정은 건별 확인 요청이 아니다(`:382`).

| 상황 | 기준선 대비 추가 지점 유형 | 건별 추가 사람 동작/확인 수 [설계 가정] | 추가가 없을 때 생기는 실패 |
| --- | --- | --- | --- |
| 정상 사전승인·정산 | 0, 삭제 0 | 0 | 기존 지점 유지 |
| 반려 후 재기안 | 0(기존 상신·결재 재방문) | 상신 1 + 새 선 승인/동의 n회; 수정 입력은 실제 횟수 별도 | 기존 반려 시도 승인을 새 내용 승인으로 잘못 승계 |
| 값만 수정, 아직 승인받은 단계 없음 | 0 | 기존 수정 입력 1; 별도 재개 확인 0 | 수정 입력은 필요하지만 확인 팝업은 실패를 추가로 막지 못함 |
| 판단 입력 수정, 동일 결재선 | 0 | 이미 승인한 m단계의 재승인 m회 추가; 현재·후속 결재는 원래 남은 동작 | 새 근거를 보지 않은 과거 승인으로 완료 |
| 새 짝 보류, 동일 근거로 해소 | 0 | 기존 짝 확인 1; 재개 확인·과거 재승인 0 | 짝 확인을 빼면 다른 지출 연결 가능 |
| 무변경 정산 재심 | 0(기존 재무합의·결재 지점 재방문) | 재무 쟁점만이면 동의 k회; 업무 판단 쟁점도 있으면 k+n회. APV-9-4 예외 별도 | 감사 쟁점을 사람 판단 없이 닫거나 재무가 업무상 필요까지 대신 판정 |
| 사전승인 재심 | **기존 결재대기의 재심 진입 경로 1개 추가** | 현재/원 전결권자 1회, admin 해제 확인 0 | 문서유형 때문에 감사 플래그를 영구 거절하거나 권한 없는 재무가 검토 |
| 타임아웃 | 0 | 강제 확인 버튼 0; 운영 담당의 실제 연락·질문은 발생 횟수 공개 | 지연 표시만으로 담당 의무를 숨기지 않음; 읽음 확인은 불필요 |
| 항목 불인정·안분 | 0 | 기존 재량 판단 기록; 항목별 승인 0 | 항목별 지급/본인 부담 결론은 보여야 하지만 추가 결재가 불필요 |
| 반환 순액 종결 | **집행 종결의 반환 분기 1개 추가**, 결재 지점 0 | 기존 지급 처리 대신 반환 사실 기록 1회: 집행 동작 수 순증 0 | 반환되지 않았는데 출장이 종결·기한 이행으로 표시 |

따라서 **정상 경로 순증 0, 예외 진입 경로 2개(사전승인 재심·반환 종결), 새로운 승인자 역할 0**이다. 재심·수정의 실제 반복 접촉은 0이라고 주장하지 않는다. 결재자 수 n과 이미 통과한 단계 수 m을 문서마다 기록하고, 같은 자료를 다시 읽은 수·정정 발견 수를 #11에 넘긴다. R1~R4의 분모를 바꾸지 않고 문서 단위 재승인·정책발 접촉을 보조 집계한다(`docs/design/receipt-pipeline.md:2512-2519`, #8 결과 댓글, 확인 2026-09-22).

**기각:** 재검증 완료 팝업, 에스컬레이션 수신 확인, admin의 재심 종료 승인, 금액이 달라졌다는 기안자의 추가 “동의”를 매번 받는 안. 이미 있는 입력·결재 외에 구체적으로 막는 실패가 없다. 기안자는 인정액과 본인 부담을 볼 수 있고 이의 제기 경로를 쓰지만 침묵을 새 동의로 간주하지 않는다.

**반증 조건:** 재검토가 의미 있는 오류를 잡지 못하면서 재요청으로 R3·R4를 지속 초과하면 전 단계 무승계는 지나치게 보수적이다. #11에서 승인별 검토 입력의 의존관계를 검증할 수 있을 때만 선택적 승계를 다음 안으로 비교한다. 확인을 없앤 결과 원 revision과 다른 금액을 지급 처리할 수 있으면 지점 수를 줄인 안은 실패다.

## 10. 순액 반환과 지급 처리 — 검색으로 드러난 추가 범위

이 항목도 #17의 미결이다(`docs/PRD.md:86`, `:143`, `:160`, `:177`, `CONTEXT.md:212`). **추천: 순액 부호별 집행 종결을 구별한다.** 결재 상태는 모두 `완료`이고, 순액 양수는 지급 처리, 0은 차액 없음 처리, 음수는 반환 처리 대기 후 재무의 반환 사실 기록으로 닫는다. “지급 처리됨”이라고 음수 반환까지 부르지 않는다. 실제 송금은 실행하지 않는다(`docs/PRD.md:132`).

[설계 가정] 반환은 별도 입금 사실·금액·참조를 재무가 기록하는 방식을 추천하고 급여 자동 공제는 채택하지 않는다. 반환 기한은 정산 완료일부터 기존 지급 기한과 같은 **5영업일 이내**를 새 규정 초안으로 제안한다. 현재 `PRC-16-1`은 회사 지급 의무를 규정하므로 음수에 그대로 적용했다고 주장하지 않는다(`docs/company/travel-procedure.md:295-305`). 새 조항 전에는 음수 건을 “반환 시기 미정”으로 표시하고 지급 의무가 이행됐다고 기록하지 않는다. 양수의 완료일 기준 기한은 재심 때문에 조용히 초기화하지 않는다. 재심이 지연시킨 일수·원기한·재심 후 조정액의 기한을 각각 드러내며, 조정액의 새로운 기한 기준은 §11 초안으로 넘긴다.

기지급 뒤 재심이면 기지급액을 상쇄 삭제하지 않고 **새 인정액과 기지급액의 차이**만 처리한다. 최초 지급이 없던 건과 이미 지급한 건을 구별하고, 처리 식별자별 중복 기록을 막는다. 양수·0·음수 모두 종결 사건이 있어야 S10을 검사할 수 있다(`docs/PRD.md:160`).

**기각:** 반려 즉시 반환 채무 확정, 완료 금액을 새 금액으로 덮고 전체 재지급, 급여 공제를 기본값으로 삼기. 반려는 지급 불인정 사유·범위를 계산하지 않으며 반환 방법은 현재 규정의 빈칸이다(`docs/company/travel-policy.md:235`).

**반증 조건:** 분할 반환·부분 지급을 추적해야만 업무를 닫을 수 있거나 5영업일이 실제 반환 절차에 맞지 않으면 이 MVP의 단일 종결·기한 제안은 틀렸다. 해당 규정·집행 기록을 먼저 확장한다.
