# ADR-0035 — 모델 실측은 사용자가 승인할 때만 하고, 매 커밋은 기록 재생으로 검증한다

- **상태**: Accepted
- **날짜**: 2026-09-25
- **맥락 티켓**: #11 (결정), #9 (기록 재생·실측 단가), #10 (판독기·답변기 두 계약), #1 (공개 데모)

## 맥락

[ADR-0016](0016-record-and-replay-model-calls.md)은 모델 호출을 기록하고 재생한다.

- `replay`는 기록을 못 찾으면 `REPLAY_MISS`로 실패하고 몰래 live로 넘어가지 않는다(`docs/adr/0016-record-and-replay-model-calls.md:31`).
- 재생이 통과해도 지금 모델의 품질이 입증되지는 않는다. 모델 선택과 품질 검증은 #11로 넘어왔다(`:65`).
- 시드를 만들 때(`record-missing`)는 키가 한 번 필요하다(`:66`).
- 재생의 재료를 정하면서 "목(mock) 응답을 손으로 쓰는 안"을 "실제 응답과 멀어진다"며 기각했다(`:56`).

하네스는 API 키를 사람만 풀 수 있는 `blocked` 사유로 둔다(`docs/agents/harness.md:73`). 실측 단가는 아직 추정이다 — 영수증 한 장에 약 $0.03~$0.044 `[실측 전]`(`docs/adr/0017-public-demo-single-vm-replay-default-capped-live.md:55`). [ADR-0017](0017-public-demo-single-vm-replay-default-capped-live.md)도 모델 선택을 #11로 넘겼다(`:59`).

그런데 첫 실측 전에는 재생 기록이 없다. 하네스가 API를 부르지 않으면, 그동안의 시험은 손으로 쓴 응답으로만 돌 수 있다. 이것이 ADR-0016의 기각과 부딪힌다(F3).

이 ADR에서 **비교 문서**는 `docs/research/eval-plan-comparison.md`다. A1–A16은 그 문서 `:48-63`, F1–F15는 `:134-148`, C1–C18은 `:173-190`에 있다. D1–D15는 레인 지시서 `docs/research/eval-plan-lane-brief.md:24-46`의 결정이다.
레인 인용(codex·grok·claude §N)은 비교 문서 §0(`:11-19`)이 가리키는 #11 제안서의 절이다.

## 결정

1. **하네스는 Claude API를 부르지 않는다**(D9). step의 AC와 시험은 재생 기록과 손으로 쓴 가짜 응답으로만 돈다.
2. **코드만 바뀌면 매 커밋 재생으로 전 시나리오를 돈다**(D8). ADR-0016의 `replay` 모드이고 API 비용은 0이다. 재생 중에도 검산·대사·결재선·감사는 실제 코드가 돈다(ADR-0016 결정 4).
   - 첫 승인 실측 전에는 재생 기록이 없다(결정 4). 그동안 매 커밋 시험은 손으로 쓴 가짜 응답으로만 돌고, 재생 결과 칸에는 `시드 전·미측정`이라고 적는다. 이때 나는 `REPLAY_MISS`를 성공한 재생으로 세지 않는다. 첫 실측으로 기록이 생긴 뒤부터 매 커밋 전 시나리오를 재생한다.
3. **실측은 사용자가 명령할 때만 한다**(D9). 프롬프트·모델·전처리가 바뀌었을 때다.
   - 돌기 전에 예상 비용을 보이고 승인을 받는다.
   - 비용은 배치 API(50% 할인), 고정 표본, 바뀐 호출 지점만 돌리기로 줄인다.
   - 계산법·표본·바뀐 것만 돌리는 규칙은 `docs/EVAL.md` §10이다.
4. **첫 실측은 구현이 끝날 무렵 1회다**(D9). 모델 고르기를 겸하고, 이때 재생 기록을 처음 만든다.
5. **`record-missing`은 사용자가 승인한 실측에서만 쓴다**(F13). ADR-0016의 "시드 만들기"는 그 실측 안에서만 일어난다.
6. **`REPLAY_MISS`를 실측으로 몰래 채우지 않는다**(A10). 빠진 기록은 실패로 드러나고, 다음 승인 실측이 채운다.
7. **손으로 쓴 가짜 응답은 제어 흐름과 하드 규칙 시험에만 쓴다**(C7). 모델 품질을 주장하는 근거로 쓰지 않는다.
   - 예: 판독기가 `1,234`를 구분자 모호로 돌려준 척하는 응답은, 미해결 값이 정책 대조를 통과하지 않는지(S9)를 시험한다. 그 응답으로 "판독기가 구분자를 잘 가린다"고 쓰지 않는다.
   - 첫 실측 뒤에는 가짜 응답의 모양을 재생 기록과 비교한다. 실제 응답에만 있는 모양(예: 후보 셋 이상)을 가짜 응답 목록에 더한다. 목록은 `docs/EVAL.md` §9다.
8. **모델은 측정으로 고른다**(D10, C4). 두 단계다.
   - **선별** — 후보마다 함정 집합의 판독 이미지와 JaWildText 고정 표본 40장(C3)만 돌린다. 하드 규칙 위반 0이고 심은 함정의 조용한 오류 0인 후보만 남긴다.
   - **본 측정** — 남은 후보 가운데 가장 싼 모델로 분포 집합을 돈다.
   - 판독기와 답변기는 따로 고른다. 답변기는 함정 T-QUOTE·T-INJ·T-STATE로 고른다.
   - 통과한 후보가 없으면 고르지 않고, 고르지 않았다고 공개한다(A16).

## 근거

**왜 하네스가 API를 부르지 않는가.** 매 커밋 API를 부르면 키·비용·비결정성이 모든 step에 실린다(ADR-0016 근거). 코드만 바뀐 커밋은 모델에 보내는 요청이 같으므로 재생으로 충분하다. 재생 중에도 결정론 코드는 지금 돈다.

**왜 사용자 승인인가.** 실측은 돈이 들고, 단가는 아직 추정이다(`[실측 전]`). 비용을 보고 돌릴지 정하는 것은 사람이다.

**왜 가짜 응답을 허용하는가.** ADR-0016이 기각한 것은 손으로 쓴 응답을 **재생의 재료**로 쓰는 안이었다. 그 기각 표(`docs/adr/0016-record-and-replay-model-calls.md:52-56`)는 재생의 대상을 무엇으로 할지 고르는 자리였다(`:16`). 이 ADR은 재생 기록을 대신하게 하지 않는다. 재생 기록이 없는 동안 제어 흐름을 시험하는 데만 쓴다.
"실제 응답과 멀어진다"는 약점은 두 방법으로 줄인다. 모델 품질을 주장하지 않고(결정 7), 첫 실측 뒤에 모양을 비교해 목록을 보강한다.

**왜 `record-missing`을 좁히는가.** 기록에 없는 것만 live로 부르는 모드가 평소 개발이나 하네스 경로에 열려 있으면, "하네스는 API를 부르지 않는다"(결정 1)가 그 모드로 샌다 `[유도]`.

**왜 두 단계로 고르는가.** 모든 후보를 모든 집합에 돌리면 비용이 후보 수만큼 곱해진다. 선별은 작은 집합으로 하드 규칙과 조용한 오류를 먼저 거른다. 대가도 있다 — 분포 집합에서만 드러나는 약점은 비싼 후보에서 보지 못한다(claude §16-4).

| 기각한 대안 | 기각 이유 |
| --- | --- |
| 하네스 AC가 필요할 때 live를 부른다 | 키는 사람만 풀 수 있는 `blocked` 사유다(`docs/agents/harness.md:73`). 비용이 사람 모르게 쌓인다 |
| 매 커밋 실측 | 위와 같다. 코드만 바뀐 커밋은 요청이 같다 |
| `REPLAY_MISS`를 live로 채운다 | ADR-0016 결정 3. "기록된 실행" 표시가 거짓이 된다 |
| 가짜 응답으로 낸 비율을 모델 품질로 싣는다 | 비율이 가짜 응답을 쓴 사람의 숫자가 된다(F15) |
| 모든 후보를 모든 집합에 돌린다(claude §16-4 ②) | 비용이 후보 수만큼 곱해진다 |
| JaWildText 표본 100장(claude §7-3) | 후보마다 선별을 돌리는 첫 실측이 커진다(C3) |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 가짜 응답으로 통과한 제어 흐름이 첫 실측에서 실제 응답의 모양 때문에 자주 깨진다. 그러면 가짜 응답은 시험의 재료로도 모자라고, ADR-0016의 기각 이유가 여기서도 선다(결정 7).
  2. 프롬프트·전처리를 자주 바꿔야 해서, 승인 실측을 기다리는 일이 개발을 막는다. 그러면 승인의 단위(예: 상한을 정한 사전 승인)를 다시 정한다(결정 3).
  3. 선별을 통과한 가장 싼 후보가 분포 집합에서 하드 규칙을 어기는 일이 되풀이된다. 그러면 선별 집합이 분포의 약점을 대표하지 못한다(결정 8).
- 자세한 것은 `docs/EVAL.md`에 있다 — 가짜 응답·재생 기록은 §9, 실측 절차·모델 고르기·보고서는 §10.
- 실측 명령의 형태(스크립트, 비용 확인 절차)는 구현 phase가 정한다. 실측 비용은 공개 데모의 실시간 판독 상한(월 5,000원, ADR-0017 결정 6)과 따로 센다. 실측은 사용자가 승인한 한 번의 지출이고, 데모 상한은 방문자가 쓰는 운영 비용이라 서로의 한도를 쓰지 않는다.
- 기존 결정과의 관계.
  - [ADR-0016](0016-record-and-replay-model-calls.md): 기각 표의 "목(mock) 응답을 손으로 쓰는 안"과 결과의 `record-missing`에 보완 표시를 했다. "재생 통과는 지금 모델의 품질 입증이 아니다"(`:65`)는 그대로다.
  - [ADR-0017](0017-public-demo-single-vm-replay-default-capped-live.md): 넘어온 모델 선택(`:59`)의 규칙을 결정 8이 정한다. 어느 모델인지는 첫 실측이 고른다.
  - [ADR-0018](0018-two-model-contracts-no-side-effect-tools.md): 두 계약(판독기·답변기)을 따로 고른다.
  - [ADR-0034](0034-two-synthetic-sets-distribution-refutes-only.md): 첫 승인 실측에서 분포 집합 전부를 돌린다.
