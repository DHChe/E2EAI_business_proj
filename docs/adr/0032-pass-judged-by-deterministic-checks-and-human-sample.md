# ADR-0032 — 합격은 결정론 대조와 사람 표본으로만 판정하고, 평가기는 제품 코어 밖에서 따로 계산한다

- **상태**: Accepted
- **날짜**: 2026-09-25
- **맥락 티켓**: #11 (결정), #15 (합의는 검증이 아니다), #9 (독립 재계산의 입력 저장), #10 (시나리오 구동기 경계), #12 (평가 결과 페이지)

## 맥락

#11은 PRD 성공 기준 S1~S16과 ADR의 반증 조건을 무엇으로 재는지 정한다(`docs/PRD.md:147`). 무엇으로 재느냐보다 먼저, 합격을 **누가** 정하느냐가 문제다.

- **모델의 자기 판단은 게이트가 되지 못한다.** [ADR-0008](0008-extraction-uncertainty-is-first-class.md)은 모델의 자기보고 신뢰도가 과신하고 모델마다 편차가 커서 단독 게이트로 쓸 수 없다고 판단했다(`docs/adr/0008-extraction-uncertainty-is-first-class.md:39-42`). LLM이 제품 출력을 채점하면 같은 약점이 평가 쪽으로 옮겨 온다.
- **두 생산자의 합의는 검증이 아니다.** #15에서 한 인용이 스코프 표지를 떨어뜨렸다. 다른 갈래는 그 페이지를 인용하지 않았으므로 잡지 못했을 것이다. #11 코멘트("#15에서 관찰된 실패 하나")는 이것을 "병렬 독립 생산의 합의는 검증이 아니다"라고 적었다.
- **같은 함수를 두 번 부르면 독립이 아니다.** [ADR-0013](0013-postgres-object-storage-isolated-by-world-id.md) 결정 8은 독립 재계산을 위해 입력을 모두 저장하고, "제품 함수를 두 번 부르는 것은 독립이 아니다"라고 정했다(`docs/adr/0013-postgres-object-storage-isolated-by-world-id.md:37`). 아키텍처의 경계 표는 제품이 무대의 정답을 읽으면 독립 재계산과 #11의 판정이 오염된다고 적었다(`docs/ARCHITECTURE.md:151`).

세 레인(codex·grok·claude)은 서로 읽지 않고 이 두 규칙에 따로 닿았다(비교 문서 A1·A8).
Eval 계획 본문은 `docs/EVAL.md`다. 하네스는 ADR을 모든 step 프롬프트에 주입하지만 `docs/EVAL.md`는 주입하지 않는다(`docs/agents/harness.md:186`, D14). 그래서 모든 코드가 지킬 규칙만 이 ADR에 두고, 자세한 것은 `docs/EVAL.md`의 절을 가리킨다.

이 ADR에서 **비교 문서**는 `docs/research/eval-plan-comparison.md`다. A1–A16은 그 문서 `:48-63`, F1–F15는 `:134-148`, U1–U5는 `:158-162`, C1–C18은 `:173-190`에 있다. D1–D15는 레인 지시서 `docs/research/eval-plan-lane-brief.md:24-46`의 결정이다.
레인 인용(codex·grok·claude §N)은 비교 문서 §0(`:11-19`)이 가리키는 #11 제안서의 절이다.

## 결정

1. **평가는 세 층이다**(A1).
   - **결정론 층** — 코드가 계산하는 결재선·한도·기한·차이·대사·법정 3값·라우팅·감사·상태 전이.
   - **모델 층** — 호출 지점 다섯(`docs/ARCHITECTURE.md:167-178`)의 출력.
   - **사람 층** — 결과물을 읽으면 알 수 있는 것. 예: 보류 답변을 읽을 수 있는가.
   층과 집합의 대응은 `docs/EVAL.md` §1이다.
2. **합격·불합격은 결정론 대조와 사람 표본 검수로만 정한다**(D2). 결정론 대조는 정답 비교·재계산·부분문자열 대조·집합 대조다.
   모델 층도 이 도구로 채점한다. 모델이 낸 값을 라벨·정답 조항 목록과 기계로 비교한다(A1).
3. **LLM은 합격·불합격을 정하지 않는다**(D2). LLM을 쓸 수 있는 자리는 사람이 볼 표본을 **고르는** 일뿐이다. 고른 표본의 판정은 사람이 한다.
   정답 파일의 다툼을 다른 모델 리뷰어가 중재하는 일([ADR-0033](0033-gold-answers-written-first-and-locked.md))은 정답 값을 가리는 일이다. 제품 결과를 LLM이 채점하는 일이 아니다(D7).
4. **평가기는 제품 코어 밖에 두고 따로 계산한다**(A8).
   - 정답 파일(`eval/gold/`, C5)·라벨·S16 기준선은 제품 코어 밖에 둔다. 제품 코어는 평가 코드에서 아무것도 import하지 않는다.
   - 시나리오 구동기는 입력 사건(영수증 업로드·메일 도착·시계 진행 등)만 넣는다. 기대값(진짜 짝, 진짜 금액)을 제품에 넘기지 않는다(`docs/ARCHITECTURE.md:151`).
   - 평가기는 저장된 입력(ADR-0013 결정 8)을 읽어 자기 경로로 다시 계산한다. 제품 함수를 다시 불러 얻은 값은 독립 재계산으로 세지 않는다.
5. **사람 표본은 실측 1회에 약 30분이다**(D5, A15, C14). 보류 답변 약 20개, 승인 카드 3장 `[설계 가정]`, 데모 첫 화면 1회를 본다. 불합격은 건별로 공개하고 고친다.
   실제 승인자의 행동(확인 도장만 찍는가, 두 갈래를 보지 않는가 등)은 사람 표본으로 재지 않는다. `실사용 전 미측정`으로 공개한다(D5). 체크 항목은 `docs/EVAL.md` §10이다.
6. **평가 결과는 공개 데모의 정적 페이지로만 싣는다**(D15). 마지막 실측 결과를 이미지 출처별로 싣고, 실패와 `미측정`도 싣는다. 제품 안에 실시간 평가 대시보드를 만들지 않는다. 화면 형태는 #12다.

## 근거

**왜 LLM 판정을 빼는가.** LLM 채점은 모델의 판단을 다른 모델에게 다시 묻는 것이다. 답과 채점기가 같은 오독을 하면 틀린 답이 통과한다. #15가 그 모양이다.
결정론 대조는 같은 입력에 같은 판정을 낸다. 틀리면 어느 규칙에서 틀렸는지도 드러난다.

**왜 사람 표본을 남기는가.** 보류 답변이 읽히는지, 붙은 조항이 질문과 맞는지는 기계 대조로 다 잴 수 없다. 그러나 사람에게 넘기는 양은 작게 묶는다(실측 1회에 약 30분).
`사람이 확인함`이라는 기록은 건수가 적을 때만 증거로서 값을 갖는다(`CONTEXT.md:359`, #19).

**왜 평가기를 밖에 두는가.** 평가기가 제품 함수를 부르면 제품의 오독이 평가에도 그대로 들어간다. 예: 숙박비를 합계가 아니라 밤마다 비교하도록 잘못 짠 함수(`TRV-6-2`)를 평가기가 다시 부르면, 둘 다 같은 틀린 값을 내고 대조는 통과한다.
반대 방향도 있다. 제품이 기대값을 읽을 수 있으면, 정답을 보고 맞춘 결과가 합격으로 센다(`docs/ARCHITECTURE.md:151`).

**왜 정적 페이지인가.** #11 본문은 "에이전트가 거절 권고했는데 사람이 승인한 비율" 대시보드를 물었다. 그런데 승인 카드와 보류 답변에는 권고를 싣지 않는다(`docs/PRD.md:141`). 그래서 잴 대상이 없다(F11). 평가 결과를 보여 줄 자리는 D15가 정한 정적 페이지 하나다.

| 기각한 대안 | 기각 이유 |
| --- | --- |
| LLM 채점기가 보류 답변의 질로 합격을 정한다 | 채점기와 답변의 오독이 겹치면 통과한다(D2). 자기보고 신뢰도를 게이트로 쓰지 않는 ADR-0008과 같은 이유다 |
| 두 모델이 같은 값을 내면 합격 | 합의는 검증이 아니다(#11 코멘트, #15) |
| 평가기가 제품 함수를 다시 불러 비교 | 독립이 아니다(ADR-0013 결정 8) |
| 정답을 시나리오 입력에 함께 싣는다 | 제품이 정답을 읽을 수 있다(`docs/ARCHITECTURE.md:151`) |
| 제품 안 실시간 평가 대시보드 | 권고를 싣지 않아 잴 대상이 없다(F11). D15 |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 합격에 꼭 필요한 품질 항목이 결정론 대조로 잴 수 없고, 사람 표본 30분으로도 다 볼 수 없다. 예: 보류 답변의 적절성을 수백 건 단위로 봐야 한다. 그러면 사람 표본의 크기나 합격 항목을 다시 정한다(결정 2·5).
  2. 평가기가 제품과 같은 규정 블록 파서나 계산 모듈을 써야만 돈다. 그러면 파서의 오독이 양쪽에 같이 들어가, 독립이 그 모듈 아래에서 끊긴다(결정 4).
  3. LLM이 고른 사람 표본이 무작위 표본보다 결함을 덜 담는다. 선별이 결함을 숨긴다는 뜻이다. 그러면 선별에도 LLM을 쓰지 않는다(결정 3).
- 자세한 것은 `docs/EVAL.md`에 있다 — 층과 집합은 §1, 성공 기준 대응은 §2, 사람 표본은 §10, 구현 검증 계약(독립 평가기 포함)은 §13, `실사용 전 미측정` 목록은 §15.
- 넘기는 것: 평가 결과 페이지의 형태는 #12.
- 기존 결정과의 관계.
  - [ADR-0008](0008-extraction-uncertainty-is-first-class.md): 모델의 자기 판단을 게이트로 쓰지 않는 규칙을 평가 쪽으로 넓힌다.
  - [ADR-0013](0013-postgres-object-storage-isolated-by-world-id.md): 결정 8(입력 저장, 독립 재계산)을 평가기 쪽에서 강제한다.
  - [ADR-0033](0033-gold-answers-written-first-and-locked.md): 정답 파일은 이 ADR의 평가기가 읽는 기대값이다. 제품 코어는 읽지 않는다.
  - [ADR-0034](0034-two-synthetic-sets-distribution-refutes-only.md): 어느 집합에서 무엇을 합격으로 보는지를 정한다.
