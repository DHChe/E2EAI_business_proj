# ADR-0023 — 업무 상태는 문서 축과 증빙 축 둘이고, 거절에는 이유를 말하는 이름을 붙인다

- **상태**: Accepted
- **날짜**: 2026-09-22
- **맥락 티켓**: #17 (결정), #19 (되돌아가는 전이의 요구), #10 (`UNDEFINED_BY_17`의 자리), #22 (표시 이름의 후속)

## 맥락

#17은 "반려의 후속 상태 정의"로 시작했다. #6이 승인 액션을 3종으로 정하면서 같은 모양의 질문이 셋 더 붙었고, 이 티켓이 상태 어휘 전체의 주인이 됐다(이슈 #17 코멘트 "범위 확장").
그 코멘트의 표 다섯 행 — 반려 뒤, 답 없는 보류, 재심 복귀, 값만 수정한 뒤의 재개, 항목별 부분 승인 — 이 이 ADR 묶음(0023–0028)의 합격선이다.

#19는 추출 파이프라인에 한 줄 상태 기계 `processing → extracted → pending_review ⇄ corrected → reconciled | rejected`를 제안했다(`docs/research/receipt-parsing.md:250`).
ARCHITECTURE는 이미 업무 상태·실행 상태(`job`)·표시 상태를 나눴다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:43`).
#17이 정하지 않은 전이는 리듀서가 추측하지 않고 `UNDEFINED_BY_17`로 거절한다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:35-37`).

세 레인(codex·grok·claude)이 서로 읽지 않고 제안했다. 이 ADR은 그중 축과 이름의 결정을 받는다. 반려·재상신은 [ADR-0024](0024-rejection-resubmission-and-card-bound-approvals.md), 철회는 [ADR-0025](0025-withdrawal-only-for-preapproval.md), 답 없는 보류는 [ADR-0026](0026-hold-answer-deadline-time-changes-no-state.md), 재심은 [ADR-0027](0027-reopen-returns-to-first-finance-consent.md), 순액 반환은 [ADR-0028](0028-negative-net-goes-to-repayment-pending.md)이 정한다.

이 ADR 묶음에서 **비교 문서**는 `docs/research/state-vocabulary-comparison.md`다. A1–A16은 그 문서 `:48-63`, D1–D11은 `:71-155`, U1–U6은 `:207-212`, C1–C10은 `:226-235`에 있다.
레인 인용(codex·grok·claude §N)은 비교 문서 §0(`:11-19`)이 가리키는 #17 제안서의 절이다. grok의 번호 없는 절은 이름으로 적는다(비교 문서 `:19`).

## 결정

1. **업무 상태는 문서 축과 증빙 축 둘이다**(A1). 문서 축은 기안 문서 하나의 결재 상태, 곧 누구의 차례인가다. 증빙 축은 증빙·필드·대사 짝의 값 상태다.
   문서를 앞 단계로 되돌리는 규칙은 문서 축 한 곳에만 둔다(A1). #19의 한 줄 기계는 문서 상태로 채택하지 않는다(A1).
2. **증빙 축에는 되돌아가는 상태 이름이 없다**(A1, A2). 값을 고치면 새 필드 revision이 생기고, 모델을 다시 부르지 않고 검산·대사를 다시 돌린다(A2).
   증빙 축은 기존 이름만 쓴다. 추출이 도는 중인지는 업무 상태가 아니라 실행 상태 `job`이다(C3). codex의 `추출 전/추출 중`·`추출 완료`는 표시 층으로 내린다(C3).
3. **두 축은 가드와 system의 변경 수락으로만 이어진다.** 증빙 축의 미해결은 상신과 현재 단계의 승인·동의를 막는 가드다(A6, A13). 값 변경이 문서를 되돌리는지는 그 변경을 수락하는 system 전이가 정한다(C8, ADR-0024 결정 5–7).
4. **`진행중`은 저장 상태가 아니다**(A16). 상신 뒤 완료 전의 `재무합의대기`·`결재대기`·`보류`를 묶어 부르는 표시어다(codex §6, claude §15). 저장 상태는 대기 상태와 단계 번호다. 표시 이름의 정리는 #22다(비교 문서 `:250`).
5. **시간은 상태를 바꾸지 않는다**(A8). 기한과 그 경과는 저장하지 않는 계산값이다(`PRC-3-1`, `docs/company/travel-procedure.md:48`). 보류 답변 기한은 [ADR-0026](0026-hold-answer-deadline-time-changes-no-state.md)이다.
6. **반려 뒤 상태의 이름은 `반려`다**(C1). 기안자에게 돌아간 문서이고, 나가는 길은 재상신과(사전승인만) 철회다. 그 의미는 ADR-0024·ADR-0025가 정한다(C1).
7. **새 저장 상태는 `철회`(사전승인만)와 `반환 대기`(정산만) 둘이다**(U2, U6). 재심은 새 상태가 아니라 대기에 붙는 표지다(A10).
8. **거절에는 이유를 말하는 이름을 붙인다**(C6). `UNDEFINED_BY_17`은 #17이 정하지 않고 다른 티켓에 넘긴 자리에만 남는다. 목록은 아래 둘째 표다.
   표에 없는 권한·상태 거부 — 자기 결재, 다른 세계의 문서 같은 것 — 의 이름은 구현에서 정한다(`docs/ARCHITECTURE.md:255`).
9. **저장 상태는 아래 표가 전부다.** 설명용 표이고 스키마가 아니다. 전이의 가드와 행위자는 `docs/ARCHITECTURE.md` §7의 전이 표에 있다.

## 근거

**왜 두 축인가.** 단위가 다르다. 반려의 단위는 건 전체이고(`CONTEXT.md:79`), 출처는 필드마다다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:41`).
한 기계로 합치면 "필드 하나가 `추출 불확실`인 문서는 무슨 결재 상태인가"를 모든 조합에 대해 정해야 한다(claude §2 논거). 세 레인이 모두 이 결론에 닿았다(A1).
되돌아가는 규칙을 문서 축 한 곳에 두면, 값 수정과 반려가 서로 다른 되돌림 이름을 각자 갖는 일이 생기지 않는다(grok §0).

**왜 증빙 축에 새 이름을 두지 않는가.** 필요한 이름이 용어집과 파이프라인에 이미 있다(grok §0 기각 둘째). 추출 진행 중은 업무 상태가 아니라 실행 상태다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:43`).
codex의 표도 이것을 "진행 표시"라고 불렀다(C3, codex §6).

**왜 `반려`인가.** 기존 문서가 모두 `반려`를 상태로 쓴다(`CONTEXT.md:81`, `:121`, `:128`). 이름만 바꾸는 것이라 되돌리기 쉽다(C1).

**왜 이름 있는 거절인가.** 리듀서가 추측하지 않는다는 원칙(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:36`)은 그대로다. 다만 #17이 이유를 정한 거절까지 "미정"이라고 부르면, 감사 조회가 결정된 거절과 미정을 구별하지 못한다 `[유도]`.
S11은 #17이 정하지 않은 전이를 성공으로 처리하지 않게 한다(`docs/PRD.md:161`). 이름을 가르면 남은 미정이 어느 티켓의 몫인지 이벤트에서 바로 보인다.

| 기각한 대안 | 기각 이유 |
| --- | --- |
| 한 기계에 추출 단계와 결재 단계를 이어 붙인다. #19의 한 줄 기계(`docs/research/receipt-parsing.md:250`) | A1. 반려와 재추출이 같은 화살표를 쓰면, 짝 보류가 문서 상태를 바꾸지 않는다는 #10의 A10과 모순된다(grok §0 기각 첫째) |
| 증빙 축에 `추출 전/추출 중`·`추출 완료`를 상태로 둔다(codex §6) | C3. 실행 상태 `job`과 표시 층이 이미 있다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:43`) |
| 반려 뒤 상태의 이름을 `재기안 대기`로 한다(claude §3.1, §15) | C1. 기존 문서가 모두 `반려`를 쓴다 |
| 미정 전이와 거절을 모두 `UNDEFINED_BY_17` 하나로 둔다. #17 채택 전에는 기존 거절이 유효하다(codex §17) | C6. 결정된 거절과 미정이 같은 이름이 된다 |
| 기한 경과로 상태를 바꾸는 명령을 두고 `DEADLINE_IS_DISPLAY_ONLY`로 거절한다(grok §2) | 그런 명령을 두지 않는다(결정 5). 이름도 U3과 맞지 않는다 — 답변 기한의 경과는 표시만이 아니라 새 도달일을 만든다([ADR-0026](0026-hold-answer-deadline-time-changes-no-state.md)) |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 한 건이 멈춘 이유가 문서 상태도, 증빙·대사 상태도, 승인·동의를 막는 가드도 아닌 셋째 이름으로만 설명된다(grok §0).
  2. 값 수정과 반려가 서로 다른 되돌림 이름을 각자 갖게 되어, 같은 종류의 단계 복귀가 두 벌로 구현된다(grok §0).
  3. 증빙 축에서 사람의 되돌리기 행위가 필요해진다. 예를 들어 재무합의자가 기안자의 수기 확정을 "무효"로 되돌려야 하는 규정이 생긴다(claude §2 틀리는 조건).
  4. 같은 명령을 다시 보내거나 옛 revision의 작업이 늦게 도착했을 때 재개 지점이 둘 생긴다(codex §2 반증 조건).
- **사람 확인 지점.** 이 ADR은 축과 이름만 정한다. 더하거나 빼는 지점은 0이다. 지점의 증감은 ADR-0024–0028이 각각 적고, 수치는 #11이 잰다(D9).
- 표의 `[설계 가정]` 둘 — 결재선 변경의 도착 `반려`, 지급 뒤 상태의 이의 플래그 — 은 각각 ADR-0024 결정 5와 ADR-0027 결정 6에서 근거를 적는다.
- 표시 이름(재기안 차수·실효·답변 기한 경과·재심 중 등)은 #22가 정한다(비교 문서 `:250`). 이 ADR은 저장 상태와 전이의 이름만 정한다.
- 기존 결정과의 관계.
  - [ADR-0011](0011-messages-api-direct-waits-are-document-state.md) 결정 6의 장치(이름 붙은 거부)는 그대로다. 그 자리의 범위를 이 ADR의 거절 표로 좁힌다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:35-37`, 정정 표시).
  - [ADR-0003](0003-approver-actions-three.md)의 승인자 액션 3종은 그대로다. 철회는 기안자의 행위, 반환 확인은 재무팀의 행위, 이의 플래그는 감사자의 행위이고 넷째 결재 액션이 아니다(A10).
  - [ADR-0012](0012-transition-audit-provenance-in-one-transaction.md): 모든 전이는 행위자와 책임자를 남긴다. system 되돌림의 행위자·책임자는 ADR-0024 결정 7이다.
  - 전이 표와 상태도는 `docs/ARCHITECTURE.md` §7이다. 논증은 이 ADR 묶음이 갖는다.
