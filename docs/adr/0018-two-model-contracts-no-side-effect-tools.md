# ADR-0018 — LLM 에이전트는 판독기와 답변기 둘이고, 에이전트에게 부작용 도구가 없다

- **상태**: Accepted
- **날짜**: 2026-09-22
- **맥락 티켓**: #10 (결정), #9 (ADR-0011의 호출 지점·도구), #18 (분류·추출 호출), #11 (주입 픽스처·반증)

## 맥락

#10의 질문은 다섯이다 — 에이전트는 몇 개인가, 각각 무엇을 책임지는가, 어떤 도구를 쥐는가, 어디서 사람 승인을 받는가, 상태와 감사는 어떻게 남는가.
경계를 나눈 이유는 "보기 좋아서"가 아니라 실패 격리·권한·책임 중 하나로 설명되어야 한다(<https://github.com/DHChe/E2EAI_business_proj/issues/10>).

[ADR-0011](0011-messages-api-direct-waits-are-document-state.md)은 이 가운데 셋을 #10에 남겼다.
모델을 부르는 곳을 넷으로 셌고(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:16-17`), 보류 답변의 도구 목록을 #10에 맡겼고(`:27`),
"에이전트에게 부작용 도구가 있는가"에 #10이 답해야 한다고 적었다(`:95`).

세 레인(codex·grok·claude)이 서로 읽지 않고 풀었다. 다섯은 합의였다.
부작용 도구가 없다(A1). 부서 에이전트·오케스트레이터 에이전트가 없다(A2). 에이전트 하나는 (시스템 프롬프트, 출력 스키마, 도구 허용 목록) 묶음이다(A3).
여행사 메일 판독은 증빙 판독과 같은 계약군이다(A4). 숫자와 판정은 전부 코드다(A6).

갈린 것은 둘이다. 에이전트 수는 grok이 3, codex·claude가 2였다(비교 문서 D1). 기안 초안은 codex만 두었다(D2).
앞의 것은 코디네이터가 C1로 정했다. 뒤의 것은 사용자가 U6으로 정했고, 코디네이터 추천(초안 없음)과 다르다(비교 문서 `:180`).

이 ADR에서 **비교 문서**는 `docs/research/agent-architecture-comparison.md`다. A1–A15는 그 문서 `:48-62`, U1–U6은 `:175-180`, C1–C9는 `:191-199`, D1–D9는 `:75-147`에 있다.
레인 인용(codex·grok·claude §N)은 비교 문서 §0(`:11-19`)이 가리키는 #10 제안서의 절이다.

## 결정

1. **"에이전트 하나"는 (시스템 프롬프트, 출력 스키마, 도구 허용 목록)의 묶음이다**(A3). 프로세스·부서·모델 이름의 수가 아니다.
   워커가 부르는 Messages API 호출의 한 프로필이다([ADR-0011](0011-messages-api-direct-waits-are-document-state.md) 결정 1).
2. **LLM 에이전트는 둘이다 — 판독기(`reader`)와 답변기(`answerer`)**(C1).

   | 에이전트 | 입력 | 도구 | 출력 |
   | --- | --- | --- | --- |
   | 판독기 | 신뢰할 수 없는 문서 1건(증빙 이미지, 여행사 메일), 또는 기안자가 준 서술·첨부 | **없음** | 호출마다 정해진 구조화 출력 |
   | 답변기 | 승인자의 보류 질문 + 작업 행에 고정된 문서 revision | 읽기 전용 3개([ADR-0020](0020-hold-answer-slots-and-server-templates.md)) | 슬롯 답변 |

3. **모델 호출 지점은 다섯이다.** 판독기가 넷, 답변기가 하나다.
   ① 증빙 분류, ② 증빙 유형별 추출(`docs/design/receipt-pipeline.md:65-66`), 여행사 메일 판독(`CONTEXT.md:345`), 기안 초안 구조화(U6), 보류 답변(`docs/PRD.md:45`).
   판독기의 넷은 **별도 호출·별도 스키마**다. 분류와 추출을 한 스키마로 합치지 않는다(C1).
4. **기안 초안은 판독기의 한 호출이다**(U6). 판독기가 기안자가 준 서술·첨부를 폼 후보로 구조화한다.
   정책 판단, 초과 사유의 인정, 빠진 사실의 창작은 하지 않는다(codex §5.3).
   초안은 산출물(artifact)이고 판정 입력을 자동으로 만들지 않는다. 기안자가 고쳐서 상신한다. 상신은 사람의 명령이다(비교 문서 `:184`).
   초안 작성의 책임자는 작성을 요청한 기안자다([ADR-0019](0019-non-approval-owner-is-assigned-operations-person.md)).
   기안자가 채택해 폼에 들어간 값의 출처는 `사람 수기 확정`이다(C9).
5. **에이전트에게 부작용 도구가 없다**(A1). 판독기는 도구가 0개, 답변기는 읽기 전용 3개다.
   업무 상태를 바꾸는 쓰기는 명령 처리기만 한다. 에이전트의 출력은 작업 행에 고정된 결과 수락 계약에 따라 코드가 저장한다(codex §3.1, claude §4.1).
6. **부서 에이전트(인사·총무·재무)와 오케스트레이터 에이전트를 두지 않는다**(A2). 흐름은 문서 상태와 `job`이 끈다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:29-30`).
7. **숫자와 판정은 전부 코드다**(A6). 한도·결재선·재무합의자·기한·대사·수취 의무·환산·차이가 여기 든다.
   LLM이 맡는 것은 읽기(판독·초안 구조화)와 보류 답변의 이음말뿐이다.

## 근거

**왜 둘인가.** 판독기와 답변기를 가르는 이유는 **실패 격리**다. 영수증·여행사 메일에 심긴 지시문이, 계산 기록을 읽을 수 있고 승인자에게 문장을 내보내는 맥락에 들어가면 안 된다
(비교 문서 `:80`, claude §2.2 B2, codex §1.3 1행). 판독기의 실패는 틀린 추출값에서 멈춘다. 그 값은 검산·대사·수기 확정을 거친 `Confirmed<T>`로만 판정에 간다
(`docs/adr/0008-extraction-uncertainty-is-first-class.md:32`).

**왜 분류·추출을 따로 세지 않는가.** 두 호출은 권한(도구 0개)·입력 신뢰 수준(같은 이미지)·책임자가 같다(claude §2.3, codex §1.1).
그래도 grok이 댄 실패 격리 이유는 맞다 — 한 응답이 유형과 금액을 같이 쓰면, 모델이 검산을 통과하는 유형 쪽으로 금액을 맞춘다(grok §3.3 1행).
그래서 에이전트 경계가 아니라 **스키마 경계**로 지킨다(C1). 여행사 메일도 같다. 신뢰할 수 없는 문서 1건을 도구 없이 읽어 구조화 값을 내고, 실패도 같은 종류다(A4, grok §3.1).

**왜 기안 초안이 판독기의 일인가.** 기안자가 준 서술·첨부를 도구 없이 읽어 구조화 후보를 내는 일이다. 권한과 출력 모양이 판독기와 같다(codex §2.1 "A 문서 판독" 행).
답변기의 조회 도구도, 승인자 쪽 맥락도 필요 없다. 그래서 에이전트 수는 그대로 둘이고 호출 지점만 하나 는다(비교 문서 `:184`).

**부작용 도구가 없으면 ADR-0011 반증 1이 열리지 않는다.** 반증 1은 세 조건이 함께 성립해야 열린다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:89`).

| 조건 | 이 결정에서 | 이유 |
| --- | --- | --- |
| (a) 실행 전 사람 확인이 필요한 부작용 도구 | 없음 | 에이전트에게 부작용 도구가 없다 |
| (b) 한 작업 안의 사람 확인 지점 둘 이상 | 없음 | 사람의 판단은 모두 루프 밖의 명령이다. 여러 요청에 걸치는 유일한 작업(보류 답변)에도 그 안에 사람 확인 지점이 없다 |
| (c) 그 사이의 보상 동작 | 없음 | 되돌릴 외부 부작용이 없다. 모의 커넥터는 모두 읽기 전용이다([ADR-0021](0021-three-read-only-mock-connectors-no-erp.md)) |

표는 claude §4.1을 옮겼다. 기안 초안도 이 표를 바꾸지 않는다 — 상신은 사람의 명령이고, 에이전트는 초안을 돌려줄 뿐이다(비교 문서 `:184`).

**왜 부서·오케스트레이터 에이전트가 없는가.** 인사·총무의 일은 사람의 상태 전이이고 결재가 아니다(`PRC-8-3`, `docs/company/travel-procedure.md:152`).
재무의 판정(대사·수취 의무·환산)은 코드다(`docs/design/receipt-pipeline.md:74`). 그 자리에 모델을 두면 모델이 판정과 라우팅을 갖는다.
그 경계는 세 이유 어느 것으로도 설명되지 않는다(claude §2.3, codex §1.4).

| 기각한 대안 | 기각 이유 |
| --- | --- |
| 계약 3개 — `classify`·`extract`·`draft_hold_answer`(grok §3.1, §3.4) | 분류·추출을 별도 호출·별도 스키마로 두는 것은 그대로 받았다(C1). 그것을 에이전트 경계로 세지 않는다. 권한·입력 신뢰 수준·책임자가 같기 때문이다(claude §2.3 2행) |
| 단일 에이전트 + 읽기 도구(claude §2.4 A1, codex §1.4 "더 적게") | 신뢰할 수 없는 문서가 조회 도구를 쥔 맥락에 들어간다(claude §2.2 B2) |
| 단일 에이전트 + 도메인 부작용 도구 합집합(claude §2.4 A2) | S5·S12가 모델의 행동에 기대게 되고 ADR-0011 반증 1이 열린다(claude §2.4 표) |
| 부서 에이전트 + 오케스트레이터(claude §2.4 B·C, codex §1.4 "더 많이", grok §3.4 C) | 경계를 세 이유로 설명할 수 없고, 판정과 라우팅이 모델로 간다(claude §2.3) |
| 계약 1개 + 보류 답변은 템플릿만(grok §3.4 B) | ADR-0011 결정 2(보류 답변은 모델의 수동 루프, `:27`)를 개정해야 한다(grok §3.4). U2는 모델의 이음말 + 서버 템플릿을 골랐다([ADR-0020](0020-hold-answer-slots-and-server-templates.md)) |
| 기안 초안 없음 — 호출 지점 4곳 유지(grok·claude, 비교 문서 D2) | 사용자가 U6으로 "초안은 에이전트, 상신은 사람"을 골랐다 |
| 위임 범위 안의 에이전트 상신(codex §9 "기안의 자동화 범위" ②) | U6은 상신을 사람에게 둔다. codex도 이 안에는 위임·철회·잘못된 상신의 복구 계약이 더 필요하다고 적었다(codex §9) |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 판독기와 답변기를 합쳐도 #11의 주입 픽스처가 답변을 오염시키지 않고, 두 프로필을 따로 유지하는 비용이 실측으로 크다(claude §2.5-1).
     codex도 같은 자리를 적었다 — 두 작업의 프롬프트·권한·자료 범위가 실제로 같아지면 1개로 합친다(codex §1.4 "추천이 틀리는 조건").
  2. 사람의 확인을 받아 실행하는 에이전트 동작이 요구되고, 그것을 "사람 명령 + 에이전트 산출물"로 표현할 수 없다(claude §4.1).
     그때 ADR-0011 반증 1의 세 조건을 다시 잰다. 부작용 도구 하나를 더했다고 반증 1 전체가 자동으로 성립하지는 않는다(codex §3.1).
  3. 위 다섯 곳 밖의 모델 호출이 요구된다(예: 사용자 자유 질문). claude의 조건 "다섯 번째 호출 지점이 요구된다"(claude §2.5-2)는 U6으로 성립했고,
     이 ADR은 그 결과로 목록을 다섯으로 다시 열었다(비교 문서 `:184`). 같은 조건을 다섯 곳 밖의 호출에 옮긴다 `[유도]`.
  4. 모델이 라우팅해야만 H1~H11을 만족하는 시나리오가 나온다(claude §2.5-3).
  5. 분류와 추출을 나눈 뒤에도 같은 이미지의 탈옥이 두 호출 모두에서 스키마 밖 값을 저장소에 쓴다. 그때는 호출을 합치지 않고 저장 경로를 막는다(grok §3.4 끝).
- 에이전트가 결재 행위(승인·동의·반려·보류)의 행위자가 되지 않는다는 것(`CONTEXT.md:331`, `docs/PRD.md:141`)은 그대로다.
  기안 쪽은 `docs/adr/0011-messages-api-direct-waits-are-document-state.md:100`의 정정이 열어 둔 자리였다. 이 ADR은 거기에 초안까지만 에이전트를 두고, 상신은 사람에게 둔다.
- 기존 결정과의 관계.
  - [ADR-0011](0011-messages-api-direct-waits-are-document-state.md): 모델 호출 지점을 넷에서 다섯으로 보완했다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:17`). 에이전트 수 둘, 내구 실행 계층 없음은 그대로다. `:95`의 물음에 "아니오"로 답했다.
  - [ADR-0012](0012-transition-audit-provenance-in-one-transaction.md): 에이전트가 행위자인 이벤트는 `actor_kind`가 에이전트이고, 행위자는 계약 이름과 `model_call_id`로 적는다(A7). 책임자는 늘 사람이다([ADR-0019](0019-non-approval-owner-is-assigned-operations-person.md)).
  - [ADR-0015](0015-typescript-web-stage-sse-no-unverified-answer-text.md): 모델의 문장이 승인자에게 닿는 곳은 보류 답변 하나이고, 검증을 통과한 완성 답변만 보인다(`docs/adr/0015-typescript-web-stage-sse-no-unverified-answer-text.md:26`).
  - [ADR-0016](0016-record-and-replay-model-calls.md): 다섯 호출 모두 `model_call`로 기록하고 재생한다. 재생 중에도 검산·대사·결재선·감사는 지금 코드가 돈다(`docs/adr/0016-record-and-replay-model-calls.md:34`).
- 구성도와 호출 지점 표는 `docs/ARCHITECTURE.md` §2·§4다.
