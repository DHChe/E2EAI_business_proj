# ADR-0037 — 하네스 AC는 Docker 컨테이너 안의 작업 트리 사본에서 돌고, PostgreSQL은 compose로 붙으며, 패키지는 기획 때 확정한다

- **상태**: Accepted
- **날짜**: 2026-09-25
- **맥락 티켓**: #32 (결정), #39 (구현), #24 (실행기 도입, 결정 2), #30 (하네스 3자 평가 I-5·I-6·I-8), #11 (재생 기록)

## 맥락

[ADR-0013](0013-postgres-object-storage-isolated-by-world-id.md)은 하네스 AC에 PostgreSQL 인스턴스가 필요하다는 대가를 적고, 방법은 뒤로 넘겼다.
"하네스 AC와 #11 평가가 PostgreSQL 인스턴스를 어떻게 얻는지(compose 서비스, 테스트용 임시 DB 등)는 구현 phase가 정한다."(`docs/adr/0013-postgres-object-storage-isolated-by-world-id.md:86`)
#24는 이를 첫 제품 phase로 넘겼다(#24 결정 2).

#30의 3자 평가가 두 문제를 더 찾았다.

- **AC는 샌드박스 밖에서 돈다**(I-5). 구현 세션은 제한된다 — "`codex exec`는 고정 argv, workspace-write 샌드박스, 네트워크 끔으로 실행한다."(`docs/agents/harness.md:198`)
  그런데 세션이 쓴 코드는 AC와 리뷰 기준선에서 사용자 권한과 인터넷을 가진 채 돈다(`scripts/execute.py:702-721`, develop `d5ec34a`).
- **AC가 남긴 파일을 보지 않는다**(I-8). ⑤ 검사는 AC 전에 한 번만 돈다. AC `printf ac > outside.log`는 completed로 끝나고 파일이 남는다.

#32에서 구현 세션의 샌드박스를 실험으로 확인했다(2026-09-25, codex-cli 0.155.1).

| 확인한 것 | 결과 |
| --- | --- |
| 인터넷, localhost TCP, 유닉스 소켓 | 모두 막힘. localhost TCP와 소켓은 실제 `codex exec`로도 확인했다 |
| 유닉스 소켓만 여는 권한 프로필 | 소켓을 열려면 `network.enabled=true`가 필요했고, 그러면 인터넷 전체가 열렸다. 도메인 제한은 적용되지 않았다 |
| 세션 안 `npm ci` | 필요한 패키지가 `~/.npm` 캐시에 있을 때만 된다. 새 패키지 설치는 막힌다 |
| PGlite(WASM으로 만든 PostgreSQL 18.3) | 샌드박스 안에서 메모리·파일 모드 모두 된다 |
| 실행기 테스트 152개·가드 테스트 66개를 `codex sandbox`로 | 모두 통과 |

지금 구조에서 구현 세션은 PG 서버에 붙을 수 없고, 새 패키지를 설치할 수 없다.

## 결정

1. **AC는 Docker 컨테이너 안에서 돈다.** step 시도·수정 unit·리뷰 기준선의 AC가 모두 대상이다. 줄마다 새 컨테이너를 쓴다.
   "줄 사이에 변수·작업 디렉토리 상태가 이어지지 않는다"(`docs/agents/harness.md:130`)를 컨테이너 경계가 지킨다.
2. **컨테이너는 작업 트리 사본에서 돈다.** 그 시점의 추적 파일과 무시되지 않은 새 파일을 넣는다. AC가 만든 파일은 컨테이너와 함께 사라지고, 실제 저장소·`.git`·홈 디렉토리에 닿지 않는다.
   AC 뒤 ⑤ 검사와 도구 캐시 허용 목록은 두지 않는다.
3. **컨테이너는 인터넷이 없는 내부 네트워크에 붙는다.** 닿는 곳은 같은 네트워크의 PostgreSQL 서비스(Docker compose)뿐이다. 세계 격리는 그대로 `world_id`다(ADR-0013 결정 4).
4. **구현 세션의 조건은 바꾸지 않는다.** 세션은 PG에 붙지 못한다. DB가 필요한 시험은 세션이 쓰고 AC 컨테이너가 돌린다. AC 실패 사유는 다음 시도의 프롬프트로 간다.
5. **npm 패키지는 기획 때 확정한다.** `/harness` 기획 세션이 `package.json`·`package-lock.json`을 phase 파일과 함께 커밋한다.
   실행기는 기동 때 lockfile로 두 벌을 설치한다. 세션용은 호스트에서, 컨테이너용은 네트워크가 있는 설치 전용 컨테이너에서 설치하고, 둘 다 `npm ci --ignore-scripts`다.
   세션이 새 패키지가 필요하면 패키지 이름을 사유에 적고 `blocked`로 멈춘다.
6. **재생 기록은 저장소의 `fixtures/replay/`에 요청 해시별 JSON 파일로 둔다.** 시험이 시작할 때 PG에 적재한다.
   파일은 사용자가 승인한 실측만 만들고([ADR-0035](0035-live-model-runs-only-on-user-approval.md) 결정 3·5), step 변경 허용 경로에 넣지 않는다.
   정답 파일을 잠그는 [ADR-0033](0033-gold-answers-written-first-and-locked.md) 결정 5와 같은 방식이다.
7. **Docker 데몬이 없으면 실행기는 세션 전에 멈춘다.** 사유는 "Docker Desktop 실행 필요"이고 exit 1이다. index는 바꾸지 않는다.

## 근거

**코디네이터는 다른 안을 추천했다. 사용자는 추천과 다르게 Docker를 골랐다**(#32 결정 절).
추천은 AC를 세션과 같은 Codex 샌드박스(`codex sandbox`)에서 돌리고, 시험 DB는 프로세스 안에서 도는 PGlite로 두는 안이었다. 세션도 DB 시험을 직접 돌려 볼 수 있다는 것이 추천 이유였다.
이 ADR은 사용자의 선택 이유를 따로 받지 않았다. 아래는 이 선택이 주는 것과 받아들인 대가다.

**Docker가 주는 것.**

- **진짜 PostgreSQL 서버다.** 운영과 로컬 재현이 쓰는 compose([ADR-0017](0017-public-demo-single-vm-replay-default-capped-live.md) 결정 1–2)와 같은 엔진·접속 방식이다.
  제품 코드에 시험용 두 번째 DB 드라이버가 필요 없고, 연결 여럿의 동시성 시험도 할 수 있다. PGlite는 연결이 하나다.
- **격리가 가장 강하다.** 컨테이너 안의 코드는 홈 디렉토리·키체인·`.git`·인터넷에 닿지 않는다.
- **사본 실행으로 I-8이 사라진다.** AC가 남긴 파일이 실제 저장소에 남지 않는다. AC 뒤 ⑤ 검사도, "어떤 캐시를 허용할지" 목록도 필요 없다.

**패키지를 기획 때 확정하는 이유.** 세션에 네트워크를 열면 이 Codex 버전에서는 인터넷 전체가 열린다(위 확인 표). 기획 세션은 사람과 대화하며 돌므로, 패키지 추가가 사람이 보는 자리에서 일어난다.
`--ignore-scripts`는 패키지의 설치 스크립트가 격리 밖에서 돌지 않게 한다.

**재생 기록을 파일로 두는 이유.** AC 컨테이너에는 인터넷이 없어 기록을 밖에서 받아 올 수 없다. 파일이면 기록 한 건의 변화가 diff로 보이고, 스키마가 바뀌어도 다시 적재하면 된다.
잠그는 이유는 정답 파일과 같다. 구현 세션이 기대값을 자기 코드에 맞춰 바꾸지 못하게 한다.

**사용자가 받아들인 대가.** 숨기지 않는다.

- **세션은 DB 시험을 돌려 보지 못한다.** 세션은 짐작으로 DB 코드를 내고 AC 실패 사유로만 배운다. unit당 3회 시도가 DB 오류에 먼저 쓰일 수 있다.
- **`node_modules`가 두 벌이다.** esbuild·rollup 같은 패키지는 OS별 실행 파일이 달라, macOS 호스트에서 설치한 것은 Linux 컨테이너에서 돌지 않는다 `[유도]`.
  세션(macOS)과 AC(Linux)의 OS가 달라, 세션에서 통과한 시험이 AC에서만 실패할 수 있다.
- **Docker Desktop이 늘 켜져 있어야 한다.** 사람이 맡는 환경 준비가 하나 는다. 이미지·볼륨·compose를 관리해야 하고, AC 줄마다 컨테이너와 사본을 만드는 시간이 든다.
- **실행기가 DB를 알게 된다.** #24 결정 2는 "실행기는 DB를 모른다"고 적었다. 이제 실행기가 compose 서비스를 올린다. DB 안의 데이터는 여전히 읽지 않는다.

| 기각한 대안 | 기각 이유 |
| --- | --- |
| AC를 `codex sandbox`로, 시험 DB는 PGlite(**코디네이터 추천**) | 사용자가 고르지 않았다. 세션도 DB 시험을 돌릴 수 있고 기존 시험이 샌드박스에서 통과한다는 이점은 위 확인 표에 남긴다 |
| 실행기가 호스트에 PG 서버를 띄우고 AC만 접속 | AC를 샌드박스 밖에서 돌려야 한다. 세션은 여전히 접속하지 못한다 |
| AC는 인터넷만 차단 | 홈 디렉토리 등 저장소 밖 쓰기가 열려 있다 |
| 지금대로 두고 위험을 기록 | I-5가 그대로 남는다 |
| 세션에 네트워크 허용 | 이 Codex 버전은 레지스트리만 열 수 없어 인터넷 전체가 열린다(위 확인 표) |
| 환경 phase를 손으로 따로 돈다 | 결과는 기획 때 확정과 비슷하고, 새 패키지가 필요할 때마다 phase가 하나 는다 |
| 저장소를 컨테이너에 직접 연결하고 AC 뒤 ⑤ + 캐시 허용 목록 | 목록에 없는 캐시가 생길 때마다 error로 멈춘다. 사본이면 목록이 필요 없다 |
| 재생 기록을 PG 덤프로 | 기록 한 건의 변화가 diff로 보이지 않고, 스키마가 바뀔 때마다 덤프를 다시 만들어야 한다 |
| 재생 기록 위치를 첫 실측 때 정한다 | 그 전에 쓴 시험이 기록을 읽는 자리를 가정하면 다시 고쳐야 한다 |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. DB를 다루는 unit이 AC의 DB 오류로 시도를 소진하는 일이 되풀이된다. 세션이 DB 시험을 못 돌리는 대가가 현실이 된 것이다. 그때는 세션이 DB에 닿는 길(PGlite, 또는 세션의 컨테이너화)을 다시 본다.
  2. 세션(macOS)에서 통과한 시험이 AC 컨테이너(Linux)에서 OS 차이만으로 실패하는 일이 되풀이된다.
  3. 대부분의 AC 줄에서 컨테이너·사본 준비 시간이 그 줄의 실행 시간보다 길다.
  4. `--ignore-scripts`로 설치한 패키지가 설치 스크립트 없이 동작하지 않는다. 그때는 설치 스크립트를 어디서 돌릴지 정한다.
- **후속.** 구현은 #39다. #40의 리뷰어가 받는 기준선 결과도 이 컨테이너에서 나온다.
  이미지(기반 이미지 digest 고정, node·python3·git·bash), compose 파일 위치와 PG 버전·수명, AC의 git 읽기 명령을 위한 `.git` 처리, lockfile이 같을 때 설치를 건너뛰는 방법은 #39가 정한다.
- 기존 결정과의 관계.
  - [ADR-0013](0013-postgres-object-storage-isolated-by-world-id.md): 결과의 후속 항목(`:86`)에 답한다. #11의 매 커밋 재생 시험은 하네스 AC이므로 이 환경에서 돈다.
    승인 실측의 실행 환경은 실측 명령을 만드는 구현 phase가 정한다(`docs/adr/0035-live-model-runs-only-on-user-approval.md:73`).
  - [ADR-0016](0016-record-and-replay-model-calls.md): 기록은 여전히 PostgreSQL의 `model_call` 행이다. 하네스에서는 저장소 파일에서 적재한다(결정 6).
  - [ADR-0033](0033-gold-answers-written-first-and-locked.md): 재생 기록을 정답 파일과 같은 방식으로 잠근다.
  - `docs/agents/harness.md`의 세션 조건(`:198`)은 그대로다. 판정 표의 ⑤·⑦ 설명(`:212-222`)은 #39가 새 구조에 맞춘다.
