# ADR-0033 — 정답 파일은 구현 첫 step이 규정만 보고 쓰고 잠근다

- **상태**: Accepted
- **날짜**: 2026-09-25
- **맥락 티켓**: #11 (결정), #16 (규정 블록·전결표 예시 E1~E11), #15 (합의는 검증이 아니다), #24 (하네스 실행기)

## 맥락

S2·S3·S10은 코드의 계산을 규정 블록으로 따로 계산한 값과 비교한다(`docs/PRD.md:152-153`, `:160`). S2에는 전결표 예시 E1~E11이 있다(`docs/company/approval-matrix.md:341-400`). `TRV`·`PRC`에는 시험 벡터가 없다.
PRD는 그 정답 집합을 #11이 만든다고 적었다(`docs/PRD.md:153`, `:160`).

정답을 **누가, 언제** 쓰느냐가 결과를 가른다. 한 출장으로 보자. 부장이 `나` 등급 지역에서 3박하고 실비로 230,000·180,000·180,000원을 냈다.

- `TRV-6-2`는 지급액을 상한 × 밤의 수와 비교하며 "밤마다 따로 비교하지 않는다"(`docs/company/travel-policy.md:116`). 블록은 `compare: 합계`다(`:125`). `나` 등급 부장의 1박 상한은 200,000원이다(`:126`, `:129`).
  200,000 × 3 = 600,000원이 실비 합계 590,000원보다 크므로 590,000원을 지급한다.
- 밤마다 비교하도록 잘못 읽으면 200,000 + 180,000 + 180,000 = 560,000원이 나온다.
- 같은 문맥이 코드와 정답을 함께 쓰면 560,000원이 "정답"이 되고 대조는 통과한다(D6).

하네스의 구조가 이 위험을 키운다.

- **정답과 코드를 같은 모델 계열이 쓴다**(F1). 구현은 Codex 하나이고 리뷰는 Claude와 Grok이다(`docs/agents/harness.md:173`). 충돌할 때만 중재하면, 같은 오독은 충돌이 나지 않아 조용히 통과한다(G3).
- **합의된 정답 변경을 파일에 옮길 주체가 없다**(F2). 구현 AI는 정답을 고치지 못한다(D7 ①). 리뷰어 계약문은 파일 변경을 금지하고(`docs/agents/harness.md:274`), Grok은 `--deny Write --deny Edit`로 돈다(`:289`).
- **정답을 계산하려면 규정에 없는 입력 둘이 필요하다**(F4). `PRC-3-2`는 `calendar_source: external`이다 — "연도별 공휴일 달력은 이 규정이 갖지 않는다"(`docs/company/travel-procedure.md:61`). `TRV-14-1`은 환율 기준일을 지출일로 둔다(`docs/company/travel-policy.md:319`). 시나리오 날짜가 미래라 실제 환율이 없다.

이 ADR에서 **비교 문서**는 `docs/research/eval-plan-comparison.md`다. A1–A16은 그 문서 `:48-63`, G3은 `:84-88`, F1–F15는 `:134-148`, U1–U5는 `:158-162`, C1–C18은 `:173-190`에 있다. D1–D15는 레인 지시서 `docs/research/eval-plan-lane-brief.md:24-46`의 결정이다.
레인 인용(codex·grok·claude §N)은 비교 문서 §0(`:11-19`)이 가리키는 #11 제안서의 절이다. 자세한 절차는 `docs/EVAL.md` §9다.

## 결정

1. **정답은 구현 phase의 첫 step이 쓴다**(D6). 첫 step은 제품 코드 없이 규정 3종과 시나리오 입력만 보고 정답 파일을 쓴다. #11은 정답 파일의 형식과 규칙만 정하고 값은 쓰지 않는다.
2. **정답 파일은 `eval/gold/`에 둔다**(C5). 제품 코어 밖이다([ADR-0032](0032-pass-judged-by-deterministic-checks-and-human-sample.md) 결정 4).
   항목의 칸은 여덟이다 — `scenario_id`·`target`·`expected`·`clauses`(판 포함)·`derivation`·`trap`·`allowed_clause_ids`·`written_by`. 칸의 뜻과 예는 `docs/EVAL.md` §9다.
3. **첫 step은 세계 픽스처 둘을 정답과 함께 쓰고 잠근다**(C6). 연도별 공휴일 달력(`PRC-3-2`)과 일별 환율표(`TRV-14-1`)다. 둘은 정답이 아니라 입력이다. 값은 합성이다 `[설계 가정]`.
4. **첫 step의 AC에는 보정 문항 E1~E11이 든다**(C5). 규칙으로 계산한 결재선이 전결표 예시값과 같아야 한다. 첫 step이 규정을 맞게 읽었는지 보는 문항이다. 나머지 AC(스키마, 조항 ID가 규정에 있는가, `derivation`이 비지 않았는가)는 `docs/EVAL.md` §9다.
5. **첫 step 뒤에는 정답 파일·픽스처·변경 장부를 잠근다**(D6). 이후 step의 변경 허용 경로에 `eval/gold/`를 넣지 않는다. 허용 경로 밖 변경은 실행기가 위반으로 판정한다(`docs/agents/harness.md:156`).
6. **정답이 코드와 다르면 네 조건을 지킨다**(D7).
   1. 구현 AI는 정답 파일을 고치지 못한다. AC가 정답과 달라 실패하면 step 보고에 "정답 이의"(항목·이유·조항)를 남긴다.
   2. 리뷰어는 구현과 다른 모델이다(phase 끝의 Claude·Grok). 각자 규정 블록으로 다시 계산하고 근거 조항을 리뷰 보고에 적는다.
   3. 리뷰어의 계산이 정답·코드 어느 쪽과도 다르거나 리뷰어 둘이 갈리면 `blocked`로 멈춘다. 둘 다 정답과 같으면 코드를 고친다. 둘 다 코드와 같으면 정답을 바꾼다(결정 8).
   4. 정답을 바꾸면 변경 장부에 남긴다(결정 9).
7. **충돌이 없어도 리뷰어 둘이 다시 계산한다**(U3). 대상은 `trap: interpretation` 표시가 붙은 항목 전부와 무작위 k = 10개다 `[설계 가정]`.
   전결표 예시 E1~E11의 경계 항목에도 해석 함정 표시를 붙인다. 판정은 결정 6의 3과 같다.
8. **정답 파일에 값을 옮기는 것은 실행기다**(U5). 실행기(`scripts/execute.py`, AI가 아님)는 리뷰어 둘이 기계가 읽는 형식으로 낸 **같은 값**만 정답 파일과 변경 장부에 옮긴다.
   이 기능은 아직 하네스에 없고 별도 이슈로 더한다. 그 전에는 `blocked`로 멈추고 사람이 옮긴다.
9. **변경 장부는 `eval/gold/CHANGELOG.md`다**(C5). 칸은 날짜·항목·이전 값·새 값·이유·근거 조항과 판·리뷰어 A 계산·리뷰어 B 계산·제기한 step·사람 확인 여부다.

## 근거

**왜 첫 step인가.** 정답을 코드보다 먼저 쓰면 정답이 코드를 보고 맞춰질 수 없다. 코드가 없으니 규정 원문을 읽는 길밖에 없다.

**왜 잠그는가.** 구현 AI가 정답을 고칠 수 있으면, AC 실패는 가장 쉬운 길인 정답 수정으로 풀린다. 픽스처도 같다. 공휴일 달력이나 환율표가 바뀌면 정답이 바뀐다. 픽스처가 열려 있으면 정답을 돌려서 고치는 길이 남는다 `[유도]`.

**왜 충돌이 없어도 다시 계산하는가.** 첫 step과 뒤 step을 같은 모델 계열이 쓴다(F1). 560,000원 예는 코드와 정답이 같아 D7의 중재가 켜지지 않는다. 구현과 다른 모델 둘이 규정 블록으로 다시 계산해야 590,000원과 부딪힌다.
해석 함정 표시는 오독하기 쉬운 자리를 모은다. 무작위 k개는 표시를 빠뜨린 자리를 줍는다. E1~E11은 규칙을 쓴 쪽(#16)이 만든 예시라, 규칙의 오독이 예시에도 들어갔을 수 있다(claude §17-8). 그래서 보정 문항으로 쓰되 경계 항목은 재계산 대상에 넣는다.

**왜 실행기가 옮기는가.** 구현 AI는 못 고치고 리뷰어는 쓰지 못한다(F2). 사람만 남는데, 정답 충돌마다 사람을 기다리면 phase가 매번 멈춘다. 실행기는 AI가 아니고, 독립인 리뷰어 둘이 낸 같은 값만 옮긴다. 그래서 옮기는 자리에 새 판단이 끼지 않는다.

| 기각한 대안 | 기각 이유 |
| --- | --- |
| #11이 지금 정답 값을 쓴다 | 시나리오 입력과 세계 픽스처가 아직 없다. 잠금은 하네스의 변경 허용 경로로 거는데, 그 경로는 구현 phase에 생긴다 `[유도]` |
| 충돌 때만 중재(codex §9, grok §9) | 같은 모델 계열의 같은 오독은 충돌이 나지 않는다(F1, G3) |
| 정답 전부를 리뷰어가 다시 계산 | 리뷰 비용이 정답 수만큼 커진다(claude §16-2) |
| 리뷰어가 변경 장부에 한 줄을 남기며 정답을 고친다(grok §9) | 리뷰어는 파일을 쓰지 못한다(`docs/agents/harness.md:274`, `:289`, F2) |
| 구현 AI가 리뷰어 합의값을 옮긴다 | 구현 AI의 허용 경로에 정답 파일이 들어가 잠금이 풀린다(D7 ①) |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 정답의 오류가 뒤늦게 사람에게 발견되는데, 그 항목이 리뷰어 둘의 재계산을 이미 통과했다. 그러면 구현과 다른 모델 둘도 같은 오독을 하는 것이고, 모델을 바꾸는 것만으로는 독립이 서지 않는다(결정 6·7).
  2. 무충돌 재계산에서 해석 함정이 아닌 무작위 항목의 오독이 자주 나온다. 그러면 해석 함정 표시가 오독 자리를 가리지 못하는 것이고, 재계산 범위를 넓힌다(결정 7).
  3. 정답 이의가 값이 아니라 `target`의 이름이나 모양 때문에 쌓인다. 코드 없이 쓴 정답의 칸이 뒤 step의 데이터 모델과 맞지 않는다는 뜻이다. 그러면 첫 step이 쓰는 값과 이름의 대응을 나눠야 한다(결정 1).
  4. 같은 조항에서 리뷰어 둘이 갈려 `blocked`가 되풀이된다. 규정 문언이 두 해석을 허용한다는 뜻이고, 이 결정이 아니라 규정의 결함이다. 규정 보완은 #20이다(결정 6).
- 넘기는 것: 하네스 기능 셋은 한 이슈로 묶는다(비교 문서 §5 "결정이 끌고 오는 것"). 실행기가 리뷰어 합의값을 옮기는 기능(결정 8), 리뷰어 보고의 "정답 재계산" 칸(결정 7), 구현 step 보고의 "정답 이의" 칸(결정 6)이다. 이슈는 아직 없다.
- 기존 결정과의 관계.
  - `docs/PRD.md` S3·S10: "정답 집합은 #11이 만든다"를 이 ADR에 맞게 고쳤다. 합격 값은 그대로다.
  - [ADR-0013](0013-postgres-object-storage-isolated-by-world-id.md): 결정 6은 공휴일 달력을 저장하고 기한을 매번 계산한다(`docs/adr/0013-postgres-object-storage-isolated-by-world-id.md:35`). 첫 step이 쓰는 달력 픽스처가 평가 세계의 그 입력이다.
  - [ADR-0032](0032-pass-judged-by-deterministic-checks-and-human-sample.md): 리뷰어의 중재는 정답 값을 가리는 일이지 제품 결과의 LLM 채점이 아니다.
  - [ADR-0036](0036-hold-answer-quotes-whole-clause.md): `allowed_clause_ids`는 이 ADR의 정답 파일 칸이고, 첫 step이 질문마다 쓴다.
