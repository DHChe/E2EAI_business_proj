# ADR-0026 — 시간은 상태를 바꾸지 않는다. 보류에는 기안자 답변 기한을 두고, 승인자는 보류 중에도 결정한다

- **상태**: Accepted
- **날짜**: 2026-09-22
- **맥락 티켓**: #17 (결정), #19 (승인 대기 타임아웃 에스컬레이션), #8 (보류 뒤 답이 없을 때), #20 (답변 기한의 값)

## 맥락

`보류`는 승인자가 기안자 또는 에이전트에게 무언가를 묻는 상태이고, 답변이 오면 같은 승인자의 대기로 돌아간다(`docs/adr/0003-approver-actions-three.md:25-26`, `CONTEXT.md:88`). 답변 없이 시간이 흐를 때의 처리는 비어 있었다(`47c89dc`의 `CONTEXT.md:88`).
#19는 "승인 대기 타임아웃 에스컬레이션"을 요구했다(`docs/adr/0003-approver-actions-three.md:55`). 규정은 기한이 지난 뒤의 상태 전이를 정하지 않는다고 적는다(`PRC-14-3`, `docs/company/travel-procedure.md:285`).
ARCHITECTURE는 기한을 저장하지 않고 경과를 표시만 하며, 기한 경과가 자동 전이를 일으키게 되면 그 책임자 행을 다시 두라고 적었다(`docs/ARCHITECTURE.md:310-317`).

빈틈은 정산에서 크다. 정산 결재 중에는 살아 있는 문서 기한이 결재 처리 기한뿐인데, 보류가 그것을 닫는다(비교 문서 §4 11번 `:173`). 법정 판정이 `판정 불가`이면서 `대사 완료`가 아닌 지출은 재무합의자가 보류하고 질문한다(`PRC-13-1`·`PRC-13-4`, `docs/company/travel-procedure.md:213-215`, `:239`). 정산의 그 분기에 이 빈틈이 있다. 얼마나 자주 생기는지는 단정하지 않는다.

세 레인은 시간이 상태를 바꾸지 않는다는 데 합의했다(A8). 경과를 영속 사건으로 둘지, 새 시계를 둘지는 갈렸고(D4), 사용자가 U3으로 골랐다.

## 결정

1. **시간이 흘러도 문서 상태는 바뀌지 않는다**(A8). 자동 승인·자동 반려·자동 취소와 상위자 이관을 두지 않는다. 기한 경과로 상태를 바꾸는 명령 자체를 두지 않는다.
2. **보류도 `PRC-14-1`의 처리 행위 하나다**(A9). 다시 그 승인자의 차례가 된 날이 새 도달일이다(`PRC-14-2`, `docs/company/travel-procedure.md:283`).
3. **기안자 답변 기한을 신설한다**(U3). 보류 대상이 기안자일 때만 둔다(claude §4 추천 2). 그 값은 #20이 정한다(U3). 값이 정해지기 전에는 이 기한을 계산하지 않는다 `[유도]`.
4. **답변 기한은 저장하지 않는 계산값이다**(U3, `PRC-3-1`, `docs/company/travel-procedure.md:48`). 기한이 지나면 그다음 영업일을 그 승인자의 새 도달일로 본다(U3). 이것은 전이가 아니다.
   경과는 기안자와 승인자의 큐에 표시한다(claude §4 추천 2). 깨우는 `job`이 필요 없다(`docs/adr/0011-messages-api-direct-waits-are-document-state.md:18`).
5. **승인자는 보류 중에도 답을 기다리지 않고 바로 결정한다**(U3). `보류`에서 같은 승인자의 승인·동의·반려를 받는다(U3, C2).
   - 가드는 대기에서 결정할 때와 같다. 재량 관문과 상신 뒤 짝 보류는 승인·동의만 막는다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:46`, A6).
   - 열린 질문은 "답변 없이 종결"로 닫힌다. 늦게 온 답변은 기록만 되고 전이를 일으키지 않는다(claude §4 추천 3).
6. **보류 대상이 에이전트이면 답변 기한을 두지 않는다.** 에이전트 답변이 실패하면 그것은 실행 상태(`job`)이지 업무 상태가 아니다(claude §4 추천 4, `docs/adr/0011-messages-api-direct-waits-are-document-state.md:43`). 승인자는 다시 묻거나 바로 결정한다.
7. **답변은 열린 질문을 닫는다. 입력을 바꾸지 않은 답변은 같은 대기로 돌아간다. 입력을 바꾼 답변은 [ADR-0024](0024-rejection-resubmission-and-card-bound-approvals.md) 결정 5의 카드 차이 규칙을 따르고, 결재선과 이미 승인한 카드가 그대로면 같은 대기로 돌아간다**(C4). 다시 그 승인자의 차례가 된 날이 새 도달일이다(`PRC-14-2`, `docs/company/travel-procedure.md:283`).
   그래서 `docs/adr/0003-approver-actions-three.md:26`의 "답변이 오면 같은 결재자의 `결재대기`로 돌아간다"를 고친다(정정 표시).
8. **타임아웃의 책임자 행은 두지 않는다.** `docs/ARCHITECTURE.md:317`의 조건 — 기한이 저장되거나 기한 경과가 자동 전이를 일으키는 것 — 이 이 결정에서 생기지 않는다. 답변 기한도 계산값이고(결정 4), 자동 전이가 없다(결정 1). 그래서 `docs/ARCHITECTURE.md:310-317`의 표시 원칙은 그대로다(U3 결과 `:217`).

## 근거

**왜 시간이 상태를 바꾸지 않는가.** 자동 반려는 결재 행위다. 결재 4행위의 행위자는 현재 단계 담당자인 사람뿐이다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:35-36`).
다른 사람에게 넘기면 결재선이 바뀐다. 결재선은 진행 중에 바뀌지 않고(`APV-11-1`, `docs/company/approval-matrix.md:256`), 결재자 부재 때 대신 결재하는 `대결`은 MVP 범위 밖이다(`CONTEXT.md:100`).
이 규정은 기한 경과에 대한 불이익을 정하지 않는다(`PRC-15-2`, `docs/company/travel-procedure.md:291`). 경과를 전이의 방아쇠로 쓰면 이 취지와 부딪힌다(claude §4 `[유도]`).

**왜 답변 기한인가.** 표시만 하면 정산 보류 중에 살아 있는 시계가 하나도 없는 빈틈이 남는다(claude §11 F-(c)의 약점). 답변 기한은 새 전이 없이, 이미 있는 승인자의 결정을 그 사람의 큐 앞에 다시 세울 뿐이다(claude §4 논거).
grok은 "기한에는 재량이 없다"(`docs/company/travel-procedure.md:365`)를 답변 기한을 만들지 않는 근거로 들었다(grok §2). 그 줄은 기한 연장 재량을 막는 문장이고, 새 고정 기한을 막지 않는다(비교 문서 §4 8번 `:170`, `[코디네이터 판단]`).

**왜 보류 중에 결정하는가.** 답변 기한이 지나 새 도달일이 와도, 승인자가 보류를 풀 길이 답변 도착뿐이면 문서는 계속 멈춘다. 반려는 관문 중에도 늘 받는다는 기존 규칙(`docs/ARCHITECTURE.md:328`)과 같은 모양의 전이다(C2).

| 기각한 대안 | 기각 이유 |
| --- | --- |
| 기한 경과를 한 번 영속 기록(`DeadlineElapsed` + `EscalationRecorded`)하고, 인사 절차 운영 담당의 지연 목록에 올린다(codex §4) | U3. 저장된 경과 사건과 그 책임자, 스케줄러 명령이 필요하고 `docs/ARCHITECTURE.md:310-317`를 고쳐야 한다(codex §13이 스스로 적음, 비교 문서 `:102`) |
| 답변 기한을 만들지 않고 기한 경과를 표시만 한다. 자동 전이 명령이 오면 `DEADLINE_IS_DISPLAY_ONLY`로 거절한다(grok §2) | U3. 정산 보류에 살아 있는 시계가 없다. 거절할 자동 전이 명령을 두지 않으므로(결정 1) 이름이 필요 없고, 답변 기한의 경과는 표시만이 아니라 새 도달일을 만든다 |
| 기한이 지나면 자동 취소하거나(#19, `docs/research/receipt-parsing.md:251`) 자동 반려·자동 승인한다 | A8. 자동 반려는 사람만 하는 결재 행위를 system이 하는 것이다(`docs/adr/0012-transition-audit-provenance-in-one-transaction.md:35-36`). 자동 취소는 정산에 불가능하다([ADR-0025](0025-withdrawal-only-for-preapproval.md)) |
| 상위자에게 에스컬레이션하거나 대결로 넘긴다 | A8. 결재선이 바뀐다(`APV-11-1`). 대결은 MVP 범위 밖이다(`CONTEXT.md:100`). 비결재 조작의 담당도 부재 때 팀장·admin으로 대신 채우지 않는다(`docs/adr/0019-non-approval-owner-is-assigned-operations-person.md:37`) |
| 보류 동안에도 `PRC-14-1`이 계속 흐르고 그 경과가 보류를 끝낸다(grok §2가 기각) | A9. 보류는 `PRC-14-1`의 세 행위 가운데 하나이고, 다음 시계는 `PRC-14-2`의 새 도달일에 시작한다 |

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. 승인자가 장기 부재인 문서가 반복되고, 그 문서가 막힌 비용(예: 출발일을 넘기는 사전승인)이 대결 도입 비용보다 크다(claude §4 틀리는 조건). 그때는 대결 ADR이 필요하고, `docs/ARCHITECTURE.md:317`대로 책임자 행과 깨우는 `job`이 생긴다.
  2. 답변 기한 경과 뒤 승인자가 거의 늘 반려한다. 그 반려는 사실상 "답 없음 → 반려" 자동 규칙의 사람 도장이다(claude §4 틀리는 조건).
  3. 반복 보류로 결재 처리 기한의 경과 표시를 피하는 일이 관측된다(codex §4 반증 조건).
  4. 답 없는 보류가 문서 기한을 넘긴 뒤 아무도 행동하지 않아 사전승인 완료나 지급을 놓치는 일이 시나리오에서 반복된다(grok §2 반증). 그러면 표시와 새 도달일만으로는 부족하다.
- **사람 확인 지점.** 0이다(A14). 기한 경과에는 확인 버튼도 새 결재 역할도 더하지 않는다. 보류 중의 결정은 이미 있는 승인자의 결정을 앞당길 뿐이다(claude §8). 답변 기한의 약점 — 출장 중인 기안자에게 짧을 수 있다(claude §11 F) — 은 값을 정하는 #20의 몫이다.
- 넘기는 것: 답변 기한의 값과 그 규정 문언은 #20(비교 문서 `:249`, `:217`. claude §11 F는 3영업일, grok의 `PRC-14-4` 초안은 반대 방향 — C10). 답변 기한 경과의 표시 이름은 #22(`:250`), 답변 기한 화면은 #25(`:251`), 기한 경과의 시각 표현은 #12(`:253`).
- 기존 결정과의 관계.
  - [ADR-0003](0003-approver-actions-three.md) `:26`을 결정 7로 고친다. `:48`의 첫 미정("보류에 답변이 오지 않은 채 시간이 흐르면")이 닫힌다.
  - [ADR-0010](0010-human-routing-bounded-by-structure-measured-by-ratio.md) `:65-66`이 넘긴 "멈춘 건이 기한을 넘길 때의 상태 전이"는 결정 1이 답한다 — 전이가 없다.
  - [ADR-0011](0011-messages-api-direct-waits-are-document-state.md) `:18`("N일 뒤에 깨워라"가 필요 없다)과 맞는다.
  - [ADR-0019](0019-non-approval-owner-is-assigned-operations-person.md): 에이전트 보류 답변의 책임자는 질문한 승인자다(`docs/adr/0019-non-approval-owner-is-assigned-operations-person.md:33`).
  - `docs/ARCHITECTURE.md` §6의 "기한 계산을 표에 두는가 — 두지 않는다"(`:305-316`)는 그대로다. 결정 8이 `:316`의 조건을 판정한다.
