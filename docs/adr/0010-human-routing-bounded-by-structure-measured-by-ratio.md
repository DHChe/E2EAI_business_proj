# ADR-0010 — 사람에게 보내는 양은 구조로 막고 비율로 잰다

- **상태**: Accepted
- **날짜**: 2026-09-21
- **맥락 티켓**: #18 (결정), #11 (합격 기준 후보), #19 (93% 근거)

## 맥락

[ADR-0008](0008-extraction-uncertainty-is-first-class.md)이 추출의 불확실성을 1급 출력으로 만들면서
"사람에게 가는 건수가 늘어날 여지"를 결과로 남겼다. 그 건수가 곧 보장의 분모다 —
승인 프롬프트의 약 93%를 사람이 승인한다는 측정이 있고 `[1차, #19 ⑤]`, 건수가 많아지면 `사람이 확인함`은 고무도장의 기록이 된다.

설계 문서 §10은 이 건수를 **구조로** 억제했다 — 규칙 6개와 수치 5개(H1~H11).
시스템 연동이 먼저 닫고, 판정 입력 필드만 묻고, `검산 불가` 단독은 보내지 않는다.
그 결과 법인카드 경로에서 사람에게 갈 수 있는 필드는 2~5개로 줄어든다.

#18의 교차 대조에서 Codex 레인은 같은 문제를 **비율로** 풀었다 —
수기 필요율·추가 주의 요구율·접촉 횟수·책임자 하루 작업량에 상한을 두고, 넘치면 처리를 멈춘다.

두 방식은 서로 다른 질문에 답한다. 구조 상한은 **자리의 천장이지 건수가 아니다** —
그 자리에 신호가 얼마나 자주 서는지는 설계가 말해 주지 않는다. 비율 상한은 건수를 재지만,
왜 그 건수가 나오는지와 넘쳤을 때 무엇을 고칠지는 말해 주지 않는다.

## 결정

1. **구조 층을 유지한다.** H1~H11과 경로별 필드 상한(법인카드 2~5개)은 그대로다.
2. **운영 지표 층을 더한다.** 비율 상한 넷을 둔다. 네 값은 모두 `[초기 검증 가정]`이다.

   | # | 지표 | 상한 |
   | --- | --- | --- |
   | R1 | 수기 필요율 | ≤ 10% |
   | R2 | 추가 주의 요구율 | ≤ 15% |
   | R3 | 사람 접촉 횟수 | 100건당 ≤ 20회 |
   | R4 | 책임자 하루 추가 작업 | 1인 하루 ≤ 20회 |

3. **넘치면 미완료·대기 수를 공개하고 처리를 멈춘다.** 필요한 확정을 건너뛰어 정상으로 처리하지 않고,
   대기 건을 승인 카드나 자동 정산으로 우회시키지 않는다.
4. **두 층의 관계를 한 절로 못박는다.** 구조는 "왜 적게 가는가"를 설계로 보장하고, 비율은 "정말 적게 갔는가"를 운영에서 잰다.
   이 관계를 **#11(Eval 계획)에 넘길 합격 기준 후보**로 둔다 — 두 층을 함께 만족해야 합격이다.

설계 본문은 [`docs/design/receipt-pipeline.md`](../design/receipt-pipeline.md) §10.1·§10.2.

## 근거

**왜 구조만으로는 부족한가.** 구조 상한은 신호가 섰을 때만 열리는 자리의 수다. 신호가 얼마나 자주 서는지는
모델·로캘·전처리 품질에 달려 있고 설계 시점에는 알 수 없다. ADR-0008이 남긴 false abstention(읽을 수 있었는데 기권)은
구조를 하나도 어기지 않고 건수를 키운다.

**왜 비율만으로는 부족한가.** 비율은 결과다. 넘쳤을 때 어느 라우팅 규칙이 건수를 만들었는지는
구조 층의 규칙 단위로 갈라야 보인다(설계 문서 §10 「예산을 넘기면 무엇을 하는가」). 그리고 비율만 있으면
보내야 할 것을 대기로 돌려 숫자를 맞출 수 있다 — 그래서 R1은 실제로 보낸 수가 아니라 보내야 한다고 판정된 수로 센다.

**왜 멈추는가.** 넘친 확정을 버리면 (i) 추출 불확실이 조용한 오류가 되어 척추 C("틀렸다는 걸 아는 것")가 무너진다.
§10은 사람을 더 붙여서 해결하지 않는다고 정했다. 버리지도 늘리지도 않으면 남는 것은 멈추고 드러내는 것이다.

**왜 `[초기 검증 가정]`인가.** 네 값은 연구에서 나온 수치가 아니다. 93%는 Claude Code 승인 프롬프트에 대한 관찰이지
영수증 파이프라인의 승인률이 아니다. 근거 있는 값처럼 적으면 #11이 반증할 자리가 사라진다.

## 결과

- 설계 문서 §0의 표시 체계에 `[초기 검증 가정]`이 더해진다. `[설계 가정]`과 달리 측정 결과가 값을 고친다.
- #11은 합격 기준 후보를 두 층으로 받는다 — H1~H11이 설계대로 지켜지는가, R1~R4가 상한 안에 드는가.
- 운영에서 "멈춤"이 보이게 된다. 처리량보다 드러냄을 고른 결정이다. 멈춘 건이 기한을 넘길 때의 상태 전이는
  이 결정이 정하지 않는다(설계 문서 §13 — #17).
- H9(월별 수기 확정 대상 비율 10%)와 R1은 문턱이 같다. H9는 설계가 들어가야 할 예산으로 남고, R1이 그것을 운영에서 잰다.
