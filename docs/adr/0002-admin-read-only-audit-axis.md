# ADR-0002 — admin은 값을 고칠 수 없고 재심만 열 수 있다

- **상태**: Accepted
- **날짜**: 2026-09-20
- **맥락 티켓**: #6 (결정), #18 (발단), #17 (후속 상태)

## 맥락

#18이 증빙 추출 파이프라인을 재설계하며 하나를 확정했다 —
불확실한 추출 값은 자동 추론으로 메우지 않고 **대사 시점에 사람이 직접 확정해 입력**하며,
그 개입이 감사 로그에 남는다. 그러면서 축이 하나 생겼다:

> 업무 당사자 3자(인사·총무·재무) 위에 **admin 마스터 계정**이라는 감사 역할이 얹힌다.
> 당사자가 넷이 되는 게 아니라 **축이 하나 더 생기는 것**이다.

#18은 권한 범위를 열어 둔 채 #6으로 넘겼다 —
"열람만인가, 수기 확정을 되돌릴 수 있는가, 승인 완료 건을 열 수 있는가."

## 결정

**admin = 대표이사 직속 내부감사 1인.** 권한은 **둘로 쪼개져 있다.**

| 할 수 있다 | 할 수 없다 |
| --- | --- |
| 완료 건 포함 전건 열람 | 값 수정 · 원복 |
| 감사 로그 열람 | 결재선 참여 (승인 · 반려 · 보류) |
| **이의 플래그로 재심 개시** | `재무합의` 설정값 변경 |

~~이의 플래그는 대상 건을 `재무합의대기`로 되돌린다.~~ **정정(#17, 2026-09-22)**: 정산에 걸린 이의 플래그는 대상 건을 `재무합의대기`의 첫 단계로 되돌리고, 결재권자 범위의 쟁점이면 원 결재선까지 다시 본다. 사전승인에는 `재무합의대기`가 없어(`APV-9-1`, `docs/company/approval-matrix.md:205`) #10이 그 플래그를 `UNDEFINED_BY_17`로 거절해 두었는데(이슈 #17 코멘트 "#10에서 넘어온 것" 1), 진행 중인 사전승인은 현재 결재권자의 대기에 재심 표지를 붙이고 상태를 바꾸지 않으며, 완료된 사전승인은 다시 열지 않고 플래그를 그 출장의 정산 카드로 넘긴다([ADR-0027](0027-reopen-returns-to-first-finance-consent.md) 결정 2·11·12).
감사자는 **판정하지 않고 되물을 뿐이지만, 되묻는 행위 자체는 상태를 움직인다.** **보완(#17, 2026-09-22)**: 정산에서 그렇다 — 플래그는 정산을 `재무합의대기` 첫 단계로 옮긴다. 사전승인에서는 상태를 바꾸지 않는다(`:29`, [ADR-0027](0027-reopen-returns-to-first-finance-consent.md) 결정 11–12).

## 근거

### 왜 값을 못 고치는가

admin이 값을 고칠 수 있으면 **4번째 업무 당사자**가 되어 #5가 세운 3자 구조가 무너진다.
더 나쁜 것은 `행위자 / 책임자` 분리(#5 결정 7)가 흐려지는 것이다 —
감사자가 고친 값의 책임자가 누구인지 답할 방법이 없다.

### 왜 대표이사 직속인가

경영지원본부장을 admin으로 두면 **고액 전결권자가 자기 결재를 자기가 감사한다.**
재무팀 내 감사 담당은 `재무합의`와 같은 팀에서 나와 독립성이 흐려진다.
전산팀은 "영수증을 사람이 고친 게 맞나"를 판정할 업무 지식이 없다.
대표이사 직속은 **경영지원본부 밖에 있어 구조적 겸직이 생기지 않는다.**

단 **조직 배치가 건별 이해충돌 부재를 보장하지는 않는다.**
1인 감사이므로 자기가 기안·수기 확정·결재에 관여한 건은 감사 대상에서 제외한다.
그 건을 누가 대신 볼지는 아직 정하지 않았다.

### 왜 "열람 전용"이라고 부르지 않는가

처음에는 "열람 전용 + 이의 플래그"로 적었으나, **그 두 문구는 같이 성립하지 않는다.**
플래그가 재무합의 회귀의 충분조건이면 admin은 이미 절차 재개 권한을 가진 것이다. **보완(#17, 2026-09-22)**: 이 문장은 정산 플래그의 옛 논거다. 사전승인은 `:29`를 따른다.
병렬 검토에서 이 자기모순이 적발됐고, 권한을 둘로 쪼개 쓰는 쪽으로 고쳤다.
**값을 바꾸지 않는 것과 상태를 되돌리지 않는 것은 같은 제한이 아니다.**

## 결과

- 감사가 사후 추적에 그치지 않고 **절차를 다시 열 수 있다.**
- #18이 남긴 "사람이 확정한 값 자체가 틀렸을 때" 문제에 ~~사전 방어는 여전히 없다.~~ **정정(#23, 2026-09-22)**: 사전 방어가 생겼다 — [ADR-0008](0008-extraction-uncertainty-is-first-class.md)이 백지 입력 · 확정값 재검산 · 사유 기록을 채택했다(`docs/adr/0008-extraction-uncertainty-is-first-class.md:65`).
  이의 플래그는 **발견 후 대응**이다. ~~사전 방어의 채택 여부는 #18에 남아 있다.~~ **정정(#23, 2026-09-22)**: #18이 ADR-0008로 채택했다.
- ~~#17로 넘어가는 것: 재심 후 복귀 경로, 완료 건의 기존 승인·지급 효력,~~
  ~~수정값이 `대사`를 다시 거치는 조건.~~ **정정(#17, 2026-09-22)**: 바뀐 것 없이 닫힌 재심은 복귀점으로 돌아간다 — 완료 건은 원 `완료`와 원 완료 시각으로 돌아가고, 지급 뒤 상태(`지급 처리됨`·`반환 대기`)에서 열린 재심은 그 상태로 돌아간다 `[설계 가정]`. 기존 승인은 효력을 유지한다. 재심 중에는 아직 하지 않은 지급 처리를 막고, 이미 기록된 지급은 지우지 않는다. 수정값은 새 필드 revision으로 검산·대사를 다시 거친다. 플래그 자체가 대사를 다시 돌리는지는 열려 있다([ADR-0027](0027-reopen-returns-to-first-finance-consent.md) 결정 4·5·7·8). **보완(#26, 2026-09-23)**: 다시 돌리지 않는다 — 대사는 입력이 바뀔 때만 돈다. 완료 뒤 대사가 바꾼 카드는 재심의 "바뀐 카드"에 든다([ADR-0031](0031-reconciliation-pending-states-and-input-driven-rerun.md) 결정 5).
- `승인 / 반려 / 보류` 3종에 이의 플래그를 네 번째로 더해 세지 않는다.
  승인자의 액션과 감사자의 액션은 다른 축이다([ADR-0003](0003-approver-actions-three.md)).
