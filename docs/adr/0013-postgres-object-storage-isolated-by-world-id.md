# ADR-0013 — 저장은 PostgreSQL + 비공개 객체 저장소이고, 격리는 `world_id`다

- **상태**: Accepted
- **날짜**: 2026-09-22
- **맥락 티켓**: #9 (결정), #16 (규정 원본·판), #18 (증빙), #11 (독립 재계산·평가 격리)

## 맥락

세 레인의 저장 추천이 갈렸다.

| 레인 | 추천 |
| --- | --- |
| codex | PostgreSQL(업무·감사·작업) + 비공개 Cloudflare R2(증빙 바이트). 방문자별 demo 공간(codex §5, §6) |
| grok | SQLite 파일 하나(WAL, 연결 하나) + 콘텐츠 주소 파일. 공유 시드 + 리셋 스크립트(grok §5.1, §6.3) |
| claude | SQLite **세계(world) 하나당 파일 하나.** 방문자·평가 시나리오·하네스 AC가 각자 시드 사본을 갖는다(claude §5.1) |

**코디네이터는 claude안(SQLite 세계당 파일)을 추천했다. 사용자는 추천과 다르게 codex안을 골랐다**(비교 문서 U1).
이 ADR은 그 선택과, 사용자가 받아들인 대가를 함께 적는다.

어느 안이든 R-a~R-g를 충족할 수 있다는 점은 레인들도 인정했다 — codex는 "SQLite가 R-c를 못 한다고 탈락시키지 않는다"고 적었고(codex §5),
grok은 PostgreSQL을 기각하면서도 그 이유가 "기능 부족이 아니다"라고 적었다(grok §5.1). 갈림은 기능이 아니라 운영·격리·보이는 모습의 저울질이다.

## 결정

1. **업무·감사·작업·outbox는 PostgreSQL에 둔다.** 문서·결재선·현재 상태·필드 이력·감사 이벤트([ADR-0012](0012-transition-audit-provenance-in-one-transaction.md))·
   `job`([ADR-0011](0011-messages-api-direct-waits-are-document-state.md))·모델 호출 기록([ADR-0016](0016-record-and-replay-model-calls.md))이 여기 있다.
2. **증빙 바이트는 비공개 객체 저장소 Cloudflare R2에 둔다.** 원본 파일과 모델에 보낸 이미지가 대상이다. DB는 key·hash·변환 정보를 참조한다.
   S3 호환 기본 입출력만 쓰고, 잠금 보관·법적 불변 저장 기능은 전제하지 않는다(codex §5). 로컬은 R2 대신 로컬 디렉터리 adapter를 쓴다([ADR-0017](0017-public-demo-single-vm-replay-default-capped-live.md)).
3. **객체와 DB 사이에 분산 트랜잭션은 없다.** 임시 업로드 → hash·크기 확인 → DB에서 첨부 커밋 순서다.
   누락 객체는 추출 대상으로 잡지 않고, 고아 임시 객체는 업무 감사 대상과 구분해 정리한다(codex §5.1).
4. **방문자와 평가 시나리오의 격리는 `world_id`다.** 세계 하나가 한 벌의 회사 데이터와 그 위의 문서·감사다(claude §5.1의 "세계" 개념).
   방문자 한 명, 평가 시나리오 하나가 각각 세계 하나다. 업무 행은 `world_id`를 갖고, 조회와 명령은 한 세계 안에서만 돈다.
5. **정책 원본은 규정 3종 Markdown이다**([ADR-0005](0005-policy-source-of-truth.md)). DB에는 `(code, edition, sha256)`과 계산 기록만 둔다.
   같은 `(code, edition)`인데 해시가 다르면 **부팅이 실패한다** — 판을 올리지 않고 조항을 고친 것이다(claude §5.3). 파생 JSON은 커밋하지 않는다. 이 MVP는 판 1만 적재한다.
6. **기한은 저장하지 않는다.** 기준일(기안일·도달일 등)·주입한 시계·공휴일 달력·판을 저장하고 매번 계산한다(`PRC-3-1`, `docs/company/travel-procedure.md:48`).
7. **증빙 원본과 모델에 보낸 이미지를 둘 다 보존한다.** 좌표가 보낸 이미지의 픽셀 좌표이기 때문이다. 크롭은 저장하지 않고 그 이미지와 박스로 다시 만든다(ADR-0009).
8. **독립 재계산(S2·S3·S10)을 위해 입력을 전부 저장한다.** 평가기는 그 입력을 읽어 별도 경로로 계산한다. **제품 함수를 두 번 부르는 것은 독립이 아니다**(codex §5.1, grok §11, claude §5.3).
9. 대사의 내부 상태 `후보 복수`·`짝 보류`는 영속 상태로 받는다(claude §5.3). 타입 정리는 #18 후속이다.

## 근거

**사용자가 PostgreSQL을 고른 이유**(결정 기록 U1).

- **운영 규모로 보이는 저장이다.** claude 스스로 SQLite를 고르며 심사자에게 "장난감"으로 보일 위험을 질문으로 올렸고,
  그 약점을 "운영 규모의 동시 쓰기는 입증하지 못한다"로 적었다(claude §9-5).
- **워커를 별도 프로세스로 떼기 쉽다.** SQLite WAL은 쓰기가 한 번에 하나이고 같은 호스트를 요구한다(codex §5·grok §5.1이 인용한 <https://www.sqlite.org/wal.html> §1·§2.2, 레인 확인 2026-09-22).
  codex는 "웹 명령·작업 처리·스트림 조회를 분리 운영하고 이후 worker를 옮길 때 동일 저장 모델을 유지하는 편"을 추천 이유로 적었다(codex §5).
  [ADR-0011](0011-messages-api-direct-waits-are-document-state.md)이 워커를 처음부터 별도 서비스로 둔 것과 맞물린다.

**사용자가 받아들인 대가.** 숨기지 않는다.

- **쿼리마다 격리 조건이 붙는다.** claude가 PostgreSQL 안의 약점으로 짚은 그대로다 — "스키마·`world_id`로 격리하므로 쿼리마다 조건이 붙는다"(claude §5.2).
  SQLite 세계당 파일에서는 "파일 복사 = 세계 복제"라 평가가 저절로 봉인됐다(같은 표). 그 봉인을 이제 코드가 지킨다.
- **운영 부담과 월 비용이 는다.** DB 서버 하나를 더 둔다(claude §5.2 운영 행). 볼륨·백업·복원을 사용자가 맡는다([ADR-0017](0017-public-demo-single-vm-replay-default-capped-live.md)).
- **하네스 AC에 PostgreSQL 인스턴스가 필요하다.** claude안에서는 하네스 AC 하나가 시드 사본 하나였고, AC를 셸 커맨드로 둘 수 있었다(claude §5.1, `docs/agents/harness.md:96`).
  이제는 AC와 #11 평가가 DB 인스턴스를 어떻게 얻는지 정해야 한다(아래 결과).

**객체 저장을 따로 두는 이유.** 증빙 바이트는 크고 불변이며, DB는 그 식별자와 해시만 알면 된다.
DB 백업만으로 증빙을 복구했다고 보지 않고 참조 객체와 정책 판을 함께 복구 검사한다(codex §5.1).

**정책 판을 해시로 고정하는 이유.** ADR-0005는 값이 조항 안에 산다고 했다(`docs/adr/0005-policy-source-of-truth.md:30-32`).
판정 기록은 `(문서코드, 판, 조항 식별자)`를 남긴다(`:86`). 같은 판 번호로 조항이 몰래 바뀌면 그 기록이 가리키는 원문이 바뀐다. 해시가 그것을 막는다.

**기한을 저장하지 않는 이유.** S10의 합격 조건에 "저장 날짜에만 의존한 기한 0"이 있다(`docs/PRD.md:160`). 기한을 저장하지 않으면 그런 기한이 생길 자리가 없다(claude §5.3).

| 기각한 대안 | 기각 이유 |
| --- | --- |
| SQLite 세계당 파일(claude, **코디네이터 추천**) | 사용자가 위의 두 이유로 고르지 않았다. 격리·하네스 AC의 이점은 인정하고 대가로 적었다 |
| SQLite 파일 하나 + 리셋 스크립트(grok) | 동시 심사자가 한 시드를 공유하면 두 사람의 동의가 서로 덮인다 — grok 스스로 적은 약점이다(grok §10-5, §6.3) |
| 런타임 transcript·벤더 로그만 | R-e 탈락([ADR-0012](0012-transition-audit-provenance-in-one-transaction.md)) |
| JSON 파일 | 상태 변경과 감사를 한 트랜잭션에 묶을 수 없다(claude §5.2) |
| 크롭 저장 | 보낸 이미지와 박스만 있으면 다시 만들 수 있다. 좌표가 보낸 이미지의 픽셀 좌표다(`docs/adr/0009-evidence-is-crop-plus-original-toggle.md:27`). 두 벌을 두면 어긋날 자리가 생긴다 `[유도]` |
| 정책 JSON 커밋, 매 요청 파싱 | ADR-0005 ⑤ 위반, 판이 몰래 바뀔 수 있다(claude §7 ADR-G) |

SQLite를 쓰지 않으므로 사실 검증 2(SQLite WAL-reset 버그)는 기록만 남긴다 — 3.7.0~3.51.2에 있을 수 있고 3.51.3에서 고쳐졌으며, 3.44.6·3.50.7 백포트 예외가 있다
(<https://sqlite.org/wal.html#walreset>, 사실 검증 2, 확인 2026-09-22).

## 결과

- **반증 조건.** 아래 중 하나가 관측되면 이 결정은 틀렸다.
  1. DB 복구 뒤 크롭에서 원본까지 추적할 수 없거나, 과거 판으로 독립 재계산할 입력이 사라진다(codex §5).
  2. 범위가 단일 사용자 로컬 실행으로 확정되고 DB 운영이 주된 실패 원인이 된다. 그때는 SQLite가 더 맞다(codex §1 표). 복구·운영 비용이 그 요구에 비해 과해도 같다(codex §5).
  3. 한 세계의 명령이나 조회가 다른 `world_id`의 행을 읽거나 바꾼 사례가 하나라도 나온다. 격리를 코드가 지키기로 한 이 선택의 대가가 현실이 된 것이다 `[유도]`.
  4. #11이 판이 여럿 동시에 살아야 하는 시나리오를 넣는다. 그러면 옛 판의 자리를 먼저 정한다(claude §7 ADR-G).
- **후속.**
  - 하네스 AC와 #11 평가가 PostgreSQL 인스턴스를 어떻게 얻는지(compose 서비스, 테스트용 임시 DB 등)는 구현 phase가 정한다. 세계 격리는 `world_id`다.
  - 대사 내부 상태의 타입 정리는 #18 후속이다(`docs/design/receipt-pipeline.md:68`에는 있고 `ReconciliationOutcome` `:835-839`에는 없다, claude §11 모순 8).
- 기존 결정과의 관계.
  - [ADR-0005](0005-policy-source-of-truth.md) ④는 판이 문서 단위라고 하고, `PRC-2-2`는 한 출장에 사전승인 기안일의 판을 정산까지 적용한다(`docs/company/travel-procedure.md:33`).

    > _ADR-0005 ④(`docs/adr/0005-policy-source-of-truth.md:81-86`)·`PRC-2-2`와 어긋날 여지가 있다. 새 판이 나오면 옛 판으로 판정되는 출장이 남으므로 판이 여럿 동시에 살아야 하는데,
    > 저장소에는 문서마다 파일이 하나다. 이 ADR은 판 1만 적재해 지금은 부딪치지 않게 한다. 옛 판을 둘 자리는 ADR-0005 후속으로 다시 논의할 가치가 있다(claude §11 모순 6)._

  - [ADR-0009](0009-evidence-is-crop-plus-original-toggle.md): 원본과 pre-resize된 보낸 이미지를 둘 다 두는 것이 이 ADR의 저장 단위다(`docs/adr/0009-evidence-is-crop-plus-original-toggle.md:27`).
  - `CONTEXT.md:358`: 감사 로그는 추가만 된다. 세계를 통째로 지우는 것은 한 세계 안의 감사 삭제가 아니다(claude §6.1). 세계의 보존·삭제 주기는 이 ADR이 정하지 않는다 — codex가 사용자 결정으로 남긴 자리다(codex §6.2).
