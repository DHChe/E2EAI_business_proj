description: 변경 사항을 저장소 문서 기준으로 검수한다
---

이 저장소의 변경 사항을 리뷰하라. **작성과 리뷰는 별개 패스다.** 방금 네가 쓴 코드라도
새로 읽고 검증한다.

## 1. 기준 문서를 먼저 읽는다

- `/AGENTS.md` 및 `docs/agents/*.md`
- `/CONTEXT.md` (또는 `/CONTEXT-MAP.md`) — 없으면 용어 항목을 건너뛴다
- `/docs/adr/` — 변경 영역을 다루는 ADR
- `/docs/PRD.md` — MVP 제외 사항
- `/docs/ui-guide.md` — UI 변경이 있을 때만

## 2. 변경 범위를 확인한다

범위 인자 `$ARGUMENTS`(예: `<base>..<end>`)가 주어지면 그 범위를 `git diff` 대상으로 쓰고 묻지 않는다.
인자가 없을 때만 브랜치·커밋·merge-base를 추측하지 말고 물어본다.

## 3. 체크리스트

| 항목              | 확인할 것                                                              |
| ----------------- | ---------------------------------------------------------------------- |
| ADR 준수          | `docs/adr/`의 결정을 벗어난 기술 선택이 있는가                          |
| 용어 일치         | `CONTEXT.md` 용어집의 어휘를 썼는가. 용어집이 피하는 동의어로 샜는가    |
| 범위 준수         | PRD의 MVP 제외 사항을 구현했는가. 요청 범위를 넘었는가                 |
| 테스트 존재       | 새 동작에 대한 테스트가 있는가                                          |
| 가짜 완료         | TODO 주석, `test.skip`/`.only`, 스텁 테스트, 미구현 분기가 남았는가     |
| 고아 코드         | 이번 변경으로 안 쓰이게 된 import/변수/함수가 남았는가                  |
| 무관한 변경       | 요청과 무관한 리팩터링/포맷 변경이 섞였는가                             |
| 빌드·테스트       | 빌드와 테스트 커맨드가 실제로 통과하는가 (직접 실행해서 확인)           |

빌드/테스트 커맨드가 아직 정의되지 않은 저장소면 그 항목은 `N/A`로 적고 사유를 남긴다.
추측해서 ✅를 주지 않는다.

## 4. 출력

| 항목 | 결과 | 비고 |
| ---- | ---- | ---- |
| {항목} | ✅ / ❌ / N/A | {근거 — 파일:줄 인용} |

- 모든 ❌에 대해 구체적 수정 방안을 제시한다.
- ✅는 **실제로 확인한 것에만** 준다. 안 돌려본 커맨드는 ✅가 아니다.
- ADR과 모순되지만 재논의할 가치가 있다고 판단되면, 위반으로 적지 말고 그 취지를 밝힌다.

출력의 **마지막 줄**은 정확히 `REVIEW_RESULT: passed` 또는 `REVIEW_RESULT: failed`다.
❌가 하나라도 있으면 `failed`, 없으면 `passed`다. 판정 줄 뒤에는 다른 내용을 붙이지 않는다.
